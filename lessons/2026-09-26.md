## 設定外部化與機密管理 · 第 2 步

### 概念：Environment Variables Override Properties（環境變數覆蓋設定）

昨天學會用 `application.properties` + `@Value("${key}")` 把設定值抽出程式碼。但這個檔案本身會被 git 記錄，所以不適合放密碼這類機密資料。

今天的解法：把機密資料改放進**環境變數**，不寫進任何檔案。Spring Boot 的**寬鬆綁定（Relaxed Binding）**規則會自動把環境變數名稱對應到 properties 的 key（大寫轉小寫、底線轉點）。

#### 程式碼演進

```properties
# ❌ 昨天的寫法（密碼明文躺在檔案裡，會被 git 記錄）
# application.properties
db.password=supersecret123
```

```bash
# ✅ 今天修好：application.properties 裡完全不寫 db.password
# 改成在終端機／部署環境設定：
export DB_PASSWORD=supersecret123
```

```java
// Java 程式碼完全不用改！
@Value("${db.password}")
private String dbPassword;
```

#### 術語表

| 術語 | 定義 |
|---|---|
| Environment Variable（環境變數） | 存在作業系統層級、程式啟動時可讀到的變數，不會存進專案檔案裡 |
| Relaxed Binding（寬鬆綁定） | Spring Boot 自動把 `DB_PASSWORD` 對應到 `db.password` 的內建規則 |
| Secret（機密資料） | 密碼、API 金鑰這類不能公開、不該進 git 的設定值 |

#### 一句話帶走

密碼不寫進任何檔案，改用環境變數傳進去，這樣密碼永遠不會被 commit。
