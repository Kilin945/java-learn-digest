## 統一例外處理：@RestControllerAdvice · 第 1 步

### 概念：為什麼需要統一例外處理

一個 API 服務裡，例外種類很多（查無資料、外部服務掛掉、參數格式錯誤...）。如果每個 Controller 方法都自己寫 try-catch 處理，會有兩個問題：

1. **重複**——每個方法都要複製一樣的錯誤處理邏輯。
2. **分散**——想統一改錯誤回應格式時，要一個個檔案去改。

比喻：診所每個診間看完診不會自己收費，而是統一送到「批價櫃檯」處理——邏輯只寫一次，所有診間共用。`@RestControllerAdvice` 就是這個「批價櫃檯」的角色。

### 問題寫法（今天看到的反例）

```java
class ResourceNotFoundException extends RuntimeException {
    ResourceNotFoundException(String msg) { super(msg); }
}

@RestController
class UserController {

    @GetMapping("/users/{id}")
    ResponseEntity<?> getUser(@PathVariable Long id) {
        try {
            User user = userService.findById(id);
            return ResponseEntity.ok(user);
        } catch (ResourceNotFoundException e) {
            return ResponseEntity.status(404)
                    .body(Map.of("error", e.getMessage()));
        }
    }

    @DeleteMapping("/users/{id}")
    ResponseEntity<?> deleteUser(@PathVariable Long id) {
        try {
            userService.delete(id);
            return ResponseEntity.noContent().build();
        } catch (ResourceNotFoundException e) {
            return ResponseEntity.status(404)
                    .body(Map.of("error", e.getMessage()));
        }
    }
}
```

每個方法重複同一段 catch 邏輯——這是明天要用 `@RestControllerAdvice` 改掉的「問題寫法」。

### 術語表

| 術語 | 定義 |
|---|---|
| try-catch | 先執行可能出錯的程式（try），丟出例外就進 catch 區塊處理 |
| 自訂例外（Custom Exception） | 自己定義的例外類別，代表特定錯誤狀況 |
| RuntimeException | 執行期才會發生的例外基底類別，自訂例外常繼承它 |
| ResponseEntity | Spring 用來包裝 HTTP 回應（狀態碼 + body）的物件 |
