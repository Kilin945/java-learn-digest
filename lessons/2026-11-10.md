## B1 第 2 篇 · 拿會變的欄位算 hashCode：放進 Set 後改欄位就再也找不到

**題目**：equals/hashCode 契約？為什麼要一起覆寫？（第 2 篇）

### 題目在問什麼
- 可變欄位：物件建好後還會被 setXxx 改的欄位。
- 要答三件事：改欄位後的症狀、原因、如何避免。

```java
// 輸入：User u = new User("Amy"); set.add(u); u.name = "Bob";
// 輸出：set.contains(u) == false; set.remove(u) == false; set.size() == 1
```

### 解題思路
1. 物件放進 Set 當下，位置依當時的 hashCode 決定。
2. 欄位改了、hashCode 變了，去找會走到別的桶子。
3. 結果：contains/remove 失敗、孤兒物件、去重失效。
4. 解法：用不會變的欄位算 hashCode。

### 答案
放進 HashSet 的那一刻位置就定了；之後改欄位 hashCode 變，但物件不搬家，所以找不到、刪不掉。

```java
// 典型寫法（簡化）
class User {
    String name;
    User(String name) { this.name = name; }
    @Override public boolean equals(Object o) { return o instanceof User u && name.equals(u.name); }
    @Override public int hashCode() { return name.hashCode(); }
}
Set<User> set = new HashSet<>();
User u = new User("Amy");
set.add(u);
u.name = "Bob";
set.contains(u);  // false
set.remove(u);    // false
set.size();       // 1
```

### 第 1 輪 · 釐清：桶子是什麼時候決定的？
```java
// 簡化示意
class Node { final int hash; final Object key; Node next; }
// add 時算一次 hash 並記在 node.hash，桶號 = hash & (桶數-1)
// contains 時重新算「手上這個 key」的 hash，到該桶比 node.hash 與 equals
// HashMap 不會監聽欄位，key 欄位改了 node.hash 不會更新
```

### 第 2 輪 · 推演後果：改完後用新物件找
```java
set.contains(new User("Amy")); // 桶子對，但 equals 與節點裡的 "Bob" 不符 → false
set.contains(new User("Bob")); // equals 符合但走錯桶 → false
set.add(new User("Bob"));      // 成功，size 變 2，去重失效
// 遍歷掃整張表，仍看得到孤兒
```

### 第 3 輪 · 連結經驗：entity 當 key
```java
// 典型寫法（簡化）：@Data 預設把所有欄位算進 equals/hashCode
@Data class Order { Long id; String status; }
cache.put(order, "cached");
order.setStatus("PAID");
cache.get(order); // null，沒有例外也沒有 log
```

### 追問：拿會變動的欄位算 hashCode 會怎樣？
```java
class User {
    final Long id;
    String name; // 不參與 equals/hashCode
    @Override public boolean equals(Object o) { return o instanceof User u && Objects.equals(id, u.id); }
    @Override public int hashCode() { return Objects.hashCode(id); }
}
// 資料庫產生的 id 在新建時是 null，拿到 id 前別放進集合
// 真的要改參與 hashCode 的欄位：先 remove，改完再 add
```

### 為什麼要懂
快取 Map、去重 Set 的 key 常是 entity，欄位在業務流程中一定會被改；不懂會遇到無例外、無 log 的「放進去卻查不到」。

### 結論
HashMap/HashSet 只在放進去時算一次 hashCode；參與 hashCode 的欄位在物件待在集合期間必須不變，實務上挑 id。

### 術語表
| 術語 | 說明 |
|---|---|
| 桶子（bucket） | HashMap 內部依 hashCode 算出的一格位置 |
| 節點（Node） | 桶子裡的一筆資料，記 hash、key、value |
| 可變欄位 | 建好後還能被 setXxx 修改的欄位 |
| 孤兒物件 | 還在集合裡但 contains/get/remove 碰不到的物件 |
| @Data（Lombok） | 自動產生 getter/setter/equals/hashCode，後兩者預設用全部欄位 |
