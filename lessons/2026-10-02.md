## Logging 與結構化日誌 · 第 4 步

### MDC: Tagging Every Log Line with a Request ID

**問題**：伺服器同時處理很多請求，log 會交錯混在一起，看不出哪一行屬於哪個請求。

**解法**：MDC（Mapped Diagnostic Context，診斷上下文）。在請求一進來時把 requestId 放進 MDC，之後同一條執行緒印出的 log 都能自動帶上它。

比喻：餐廳每張訂單貼上桌號，廚房出餐紀錄才分得清是哪一桌。

三步驟：
1. 請求進來時 `MDC.put("requestId", ...)`
2. 在 log 格式用 `%X{requestId}` 印出
3. 請求結束在 `finally` 內 `MDC.clear()`（執行緒會被重複使用，不清會污染下一個請求）

```java
@Component
public class RequestIdFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest req,
            HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {

        MDC.put("requestId", UUID.randomUUID().toString().substring(0, 8));
        try {
            chain.doFilter(req, res);
        } finally {
            MDC.clear();
        }
    }
}
```

```properties
logging.pattern.level=%5p [%X{requestId}]
```

輸出效果：

```
 INFO [a1b2c3d4] Order created, id=42
ERROR [a1b2c3d4] Payment failed
```

**一句話**：用 MDC 在請求開頭貼上 requestId、結尾 clear，就能用一個編號撈出整個請求的來龍去脈。

### 術語表
- **MDC**（診斷上下文）：綁在當前執行緒上的 key-value 小表，log 輸出時可印出其中的值。
- **requestId**（請求編號）：每個 HTTP 請求一個唯一編號。
- **Thread**（執行緒）：程式中同時做事的工作者，會被回收再利用。
- **Filter**（過濾器）：請求抵達 Controller 前、回應送出前的一道關卡。
- **%X{key}**（MDC 佔位符）：log 格式中會被換成 MDC 對應值的標記。

官方文件：https://logback.qos.ch/manual/mdc.html
