## @Value 與 application.properties 讀設定 · 第 3 步

### 概念：@Value 只在 Spring Bean 裡才有效

- 前兩步學到 `@Value("${key}")` 可以把 application.properties 的值注入欄位，也學會用 `@Value("${key:預設值}")` 準備備用值。
- 這一步的重點：**@Value 是靠 Spring 的 IoC 容器（控制反轉容器）在物件建立時幫忙塞值的**。只有由 Spring 建立、放進容器管理的物件（稱為 **Bean**），才享得到這個服務。
- 如果自己在程式碼裡用 `new` 建立物件，這個物件完全不在 Spring 的管轄範圍內，@Value 欄位不會被注入，結果就是 `null`，而且不會噴任何錯誤，非常容易踩雷。
- 正確做法：改用 `@Autowired` 讓 Spring 幫你注入一個已經建立好、且已經被注入設定值的 Bean，而不是自己手動 new。

### 程式碼

```java
@Component
public class GreetingService {

    @Value("${app.greeting:Hello}")
    private String greeting;

    public String greet() {
        return greeting;
    }
}

// ❌ 自己 new，@Value 完全沒用
GreetingService s1 = new GreetingService();
System.out.println(s1.greet()); // null

// ✅ 交給 Spring 建立、自動注入
@Autowired
private GreetingService greetingService;

System.out.println(greetingService.greet()); // Hello 或 properties 裡設的值
```

### 術語表

| 術語 | 定義 |
|---|---|
| Bean | Spring 建立並管理的物件，不是自己手動 new 出來的，才享有 @Value 等自動注入功能 |
| IoC Container（控制反轉容器） | Spring 內部負責統一建立、管理所有 Bean 並幫忙注入設定值的「大管家」 |
| @Autowired（自動裝配） | 告訴 Spring「幫我自動放入一個現成的 Bean」，取代自己手動 new |
