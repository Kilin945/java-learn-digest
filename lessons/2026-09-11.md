## 單元測試 vs @SpringBootTest 整合測試 · 第 3 步

### 概念
單元測試（unit test）只測一個方法或 class 本身的邏輯，不依賴資料庫、網路等外部資源，跑得快。
整合測試（integration test）用 `@SpringBootTest` 真的啟動整個 Spring 應用程式，讓所有元件（bean）兜在一起運作，能抓到「元件裝不起來」的問題，但速度較慢。

今天示範一個最簡單的整合測試：`contextLoads()`。內容可以完全空白，只要 Spring 容器能成功組裝所有 bean，測試就算通過；反之若有元件兜不起來（缺設定、循環依賴等），測試會直接失敗。

### 程式碼
```java
import org.junit.jupiter.api.Test;
import org.springframework.boot.test.context.SpringBootTest;

@SpringBootTest
class DemoApplicationTests {

    @Test
    void contextLoads() {
        // 方法內容可以空白
        // Spring 把所有 bean 組裝成功，測試就算過
    }
}
```

### 總結對比
- 單元測試：快、獨立、測邏輯本身，不需要資料庫／網路。
- 整合測試：慢，但能抓到「元件裝不起來」這種單元測試測不到的問題。
- 實務建議：大量寫單元測試打底，整合測試留給關鍵流程把關。

### 術語表
| 術語 | 定義 |
|---|---|
| @SpringBootTest | 貼在測試 class 上的標記，讓 Spring 真的啟動整個應用程式來測 |
| contextLoads | 約定俗成、內容可空白的測試方法，只確認應用程式能否成功啟動 |
| bean | 交給 Spring 管理的物件（零件），Spring 負責組裝 |
