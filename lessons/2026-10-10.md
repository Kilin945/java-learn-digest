## Spring Security 入門：認證與授權概念 · 第 6 步

### Who am I? Getting the Current User with @AuthenticationPrincipal

比喻：認證成功就像在櫃台拿到訪客證，之後每層樓的保全看證件就知道你是誰。Spring Security 把「目前登入者」放進 **SecurityContext**（跟著這次請求走），Controller 只要跟 Spring 要就拿得到，不必再查資料庫。

```java
@RestController
public class MeController {

    // 方法 1：直接要 UserDetails（最常用）
    @GetMapping("/api/me")
    public String me(@AuthenticationPrincipal UserDetails user) {
        return "Hello, " + user.getUsername();
    }

    // 方法 2：要 Authentication，可以多看到角色
    @GetMapping("/api/me/roles")
    public String roles(Authentication auth) {
        return auth.getName() + " -> " + auth.getAuthorities();
        // 例如：alice -> [ROLE_ADMIN]
    }
}
```

重點：
- 該路徑必須是需登入的，沒登入會先被擋成 401。
- roles("ADMIN") 會自動加上 `ROLE_` 前綴，所以 getAuthorities() 看到 `ROLE_ADMIN`，而 hasRole("ADMIN") 不用自己寫前綴。

### 術語表
- **SecurityContext（安全上下文）**：存放目前請求登入者的地方。
- **Principal（主體）**：目前登入的那個人，這裡就是 UserDetails。
- **@AuthenticationPrincipal**：Controller 參數註解，請 Spring 注入目前登入者。
- **Authentication（認證結果物件）**：含使用者名稱與角色（getAuthorities）。

一句話：登入者放在 SecurityContext，Controller 用 @AuthenticationPrincipal 或 Authentication 就能直接拿到。
