## Starter 依賴：spring-boot-starter-web 幫你帶了什麼 · 第 3 步

### 概念

昨天學到 `spring-boot-starter-web` 內建了一台小型 Tomcat（網頁伺服器）。但接到請求後，還需要有人知道「這個網址該交給哪段程式碼處理」——這正是 **Spring MVC** 在做的事。

Spring MVC 是這個 starter 附贈的網頁框架，核心角色是 **DispatcherServlet**（可想成「總機」）：所有進來的請求都先經過它，再依照網址轉給對應的方法處理。你只需要：

- 在類別上貼 `@RestController`，告訴 Spring「這裡有處理請求的方法」
- 在方法上貼 `@GetMapping("/路徑")`，告訴總機「這個網址歸我管」

不需要自己寫任何解析 HTTP 請求或網址的邏輯。

### 程式碼範例

```java
@RestController          // 告訴 Spring：這個類別裡的方法要處理網址請求
public class HelloController {

    @GetMapping("/hello")   // 告訴總機：有人訪問 /hello 就轉給這個方法
    public String sayHello() {
        return "Hello, Spring Boot!";
    }
}
```

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Spring MVC | 網頁框架 | starter-web 內建的一套規則，負責把網址請求交給對應程式碼處理 |
| DispatcherServlet | 分派器/總機 | 所有請求先經過它，再轉給正確的方法 |
| @RestController | 標籤/註解 | 貼在類別上，宣告該類別處理網址請求 |
| @GetMapping | 標籤/註解 | 貼在方法上，指定該方法對應哪個網址 |
