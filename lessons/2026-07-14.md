## Profiles：dev / prod 用不同設定 · 第 3 步

### 概念：@Profile 讓「元件」也依環境切換

前兩步教的是「設定值」依 profile 切換（例如 `application-dev.properties` 裡的資料庫連線字串）。這一步要教的是「整段行為／元件」也能依 profile 切換。

Spring 裡負責做事的物件叫 **Bean**（元件），是 Spring 容器幫你建立、管理生命週期的物件。只要在 Bean 上加 `@Profile("名稱")`，就是告訴 Spring：「這個元件只有在該 profile 啟用時才要建立」。同一個 interface（介面，只定義要做什麼、不寫怎麼做）可以有 dev 版和 prod 版兩種實作，Spring 開機時只會建立符合目前啟用 profile 的那一份，呼叫端完全不用改程式碼。

### 程式碼

```java
public interface EmailSender {
    void send(String to, String content);
}

@Component
@Profile("dev")
class FakeEmailSender implements EmailSender {
    public void send(String to, String content) {
        System.out.println("[DEV] 假裝寄信給 " + to + ": " + content);
    }
}

@Component
@Profile("prod")
class RealEmailSender implements EmailSender {
    public void send(String to, String content) {
        // 真的呼叫寄信服務
    }
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| Bean（元件） | 由 Spring 容器負責建立、管理生命週期的物件，不用自己 new |
| @Profile（環境條件註解） | 加在 Bean 上，宣告只在指定 profile 啟用時才建立這個 Bean |
| Interface（介面） | 只定義「要做什麼」，不寫「怎麼做」，讓不同實作可以互換 |

### 一句話帶走

@Profile 讓同一個介面在不同環境長出不同的實作，呼叫端的程式碼一行都不用改。
