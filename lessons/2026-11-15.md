## B6 第 2 篇 · StringBuffer 的同步差在哪；String 為什麼要設計成不可變

**題目**：String vs StringBuilder vs StringBuffer？

### 題目在問什麼
- String 不可變；StringBuilder 可變、無鎖；StringBuffer 可變、方法有 synchronized。
- 要答完：① StringBuffer 與 StringBuilder 的差別；② String 為什麼不可變（追問）。

```java
// 輸入：兩條執行緒，同時對同一個可變字串各 append 1000 次 'x'
// 輸出：理想長度 2000
//   StringBuffer  -> 一定 2000
//   StringBuilder -> 可能少於 2000，甚至丟例外
```

### 解題思路
1. 先分出能不能改內容（第 1 篇）。
2. 兩個可變的差別只剩多執行緒下怎麼辦：弄懂 synchronized 與代價（本篇）。
3. 列出不可變的好處（本篇）。

### 答案
StringBuffer 方法都加 synchronized，多執行緒安全但每次要拿鎖、放鎖，比較慢；StringBuilder 沒鎖，單執行緒最快。

```java
// 簡化示意
public synchronized StringBuffer append(String str) {
    // ...複製字元、更新長度...
    return this;
}
// StringBuilder.append 相同，只是沒有 synchronized
```

### 第 1 輪（釐清）：synchronized 到底是什麼？為什麼加了就變慢？
```java
// 簡化示意
StringBuffer sb = new StringBuffer();
// A 呼叫 sb.append("x")：① 先拿 sb 的鎖才進方法
// B 同時呼叫 sb.append("y")：② 拿不到鎖，在門口等
// A 做完：③ 放鎖，B 才進去
// 慢在：每次都要拿鎖放鎖；有人搶時還要等
```

### 第 2 輪（反事實）：兩條執行緒共用沒有鎖的 StringBuilder，會壞在哪？
```java
StringBuilder sb = new StringBuilder();
Runnable job = () -> {
    for (int i = 0; i < 1000; i++) sb.append('x');
};
new Thread(job).start();
new Thread(job).start();
// append 內部：① 寫進第 count 格 ② count++
// A、B 同時讀到 count=5 -> 都寫第 5 格 -> 一個字元被蓋掉，長度 < 2000
// 遇到陣列擴充還可能丟 ArrayIndexOutOfBoundsException
// StringBuffer 每次 append 整段上鎖 -> 一定 2000
// 但鎖只管單次呼叫：sb.append(a); sb.append(b); 兩行之間別的執行緒仍可插入
```

### 第 3 輪（連結經驗）：電文組字串迴圈、FILL 補齊那段，該選哪個？
```java
// 典型寫法（簡化）；Field 為示意用類別
StringBuilder msg = new StringBuilder();
for (Field f : fields) {
    String v = f.value();
    msg.append(v);
    for (int i = v.length(); i < f.length(); i++) {
        msg.append(' ');   // FILL 補空白
    }
}
String result = msg.toString();
// msg 是區域變數，只有本執行緒看得到 -> 不需要鎖 -> StringBuilder
```

### 追問：String 為什麼要設計成不可變？
```java
// 一、安全：check(path) 之後、open(path) 之前內容若可被改，檢查與實際使用就對不上
// 二、HashMap key：String 把 hashCode 算一次就快取；key 若可變，put 後內容一改，就找不到那筆
// 三、天生執行緒安全：內容不變，多執行緒讀同一個 String 不用鎖
// 字串池：
String a = "hi";
String b = "hi";   // 指向池中同一物件；若可變，改 a 連 b 一起變
```

### 為什麼要懂
看到 StringBuffer 要能判斷是否真有多執行緒共用；HashMap 明明 put 卻 get 不到時，要想到 key 可變。

### 結論
StringBuffer 與 StringBuilder 只差一把鎖，區域變數組字串用 StringBuilder。String 不可變換來安全、可當 key、天生執行緒安全，字串池也才成立。

### 術語表
| 術語 | 白話定義 |
|---|---|
| synchronized | 讓同一時間只有一條執行緒能執行某段程式 |
| 鎖（lock） | 掛在物件上的「使用中」標記 |
| 執行緒安全 | 多條執行緒同時用結果也不錯亂 |
| hashCode | 由內容算出的整數，HashMap 靠它決定放哪格 |
| 字串池 | JVM 存常數字串的區域，相同內容共用同一物件 |
