## B8 第 3 篇 · Java 8 有 default method 之後，abstract class 還剩什麼：欄位、建構子、單一繼承

### 題目：abstract class 與 interface 差在哪？什麼時候用哪個？

**題目在問什麼**

- default method：Java 8 起 interface 的方法可以有方法本體。
- 本篇問：interface 也能寫程式了，abstract class 還有什麼取代不了？
- 要答到三件事：存狀態（欄位）、建構子、單一繼承的語意。

```java
// 輸入：interface 可以寫 default method
// 輸出：abstract class 獨有的三件事
//   ① 欄位  ② 建構子  ③ 單一繼承（是一種什麼）
```

**解題思路**

1. interface 是約定「能做什麼」（第 1 篇）。
2. abstract class 是半成品骨架（第 2 篇）。
3. **default method 只補行為不補資料 → 欄位（本篇）。**
4. **資料要在建立時備好 → 建構子（本篇）。**
5. **extends 與 implements 數量限制不同 → 單一繼承語意（本篇）。**

**答案**

interface 即使有 default method，仍沒有實例欄位、沒有建構子，且可以實作多個；abstract class 這三件事相反，所以要共用資料與流程骨架就用 abstract class。

```java
// 簡化示意
interface Parser {
    int VERSION = 1;              // 其實是 public static final 常數，全體共用一份、不能改
    // int pos;                   // 編譯錯誤：常數必須給初始值，也不是每個物件各一份
    // Parser() { }               // 編譯錯誤：interface 沒有建構子
    default int next() {
        // return pos++;          // 寫不出來：interface 沒有 pos
        return VERSION;           // 只能碰常數、自己的抽象方法
    }
}

abstract class BaseParser {
    protected final String raw;   // 實例欄位：每個物件一份
    protected int pos;            // 狀態：解析到哪裡（典型寫法，簡化）
    protected BaseParser(String raw) {  // 建構子：建立時先做共用初始化
        this.raw = raw;
        this.pos = 0;
    }
}
```

### 第 1 輪 · 釐清：「interface 不能存狀態」的狀態、實例欄位到底是什麼？interface 裡寫 int MAX = 100 不算嗎？

狀態＝每個物件自己一份、而且會變的資料。interface 裡的欄位全是全班共用的常數。

```java
// 典型寫法（簡化）
abstract class Msg {
    protected int pos;   // 實例欄位：new 幾個物件就有幾份
}
class A extends Msg { }
class B extends Msg { }

A a = new A();
B b = new B();
a.pos = 5;           // b.pos 還是 0，互不影響 → 這就是狀態

interface Limit {
    int MAX = 100;       // 等同 public static final，全部共用、不能改
}
// Limit.MAX = 101;      // 編譯錯誤
```

### 第 2 輪 · 追原因：abstract class 自己不能 new，為什麼還要有建構子？

建立子類別物件時，父類別那一段欄位要先蓋好；子類別用 super(...) 呼叫父類別建構子來完成。

```java
// 典型寫法（簡化）
abstract class BaseParser {
    protected final String raw;
    protected int pos;

    protected BaseParser(String raw) {   // 不能被 new，但子類別可以呼叫
        this.raw = raw;
        this.pos = 0;
    }
    abstract void map();
}

class OrderParser extends BaseParser {
    OrderParser(String raw) {
        super(raw);   // 第一件事先叫父類別；沒寫編譯器補 super()
    }
    void map() { }    // 此時 raw、pos 已有值
}
// new 的順序：先父類別建構子，再子類別建構子本體
// interface 沒有這個機制，default method 被呼叫時沒有建立時備好的資料
```

### 第 3 輪 · 比較：extends 只能一個、implements 可以很多個，差在哪？什麼時候選哪個？

extends 是「是一種什麼」，身分只有一個；implements 是「能做什麼」，能力可以疊。

```java
// 簡化示意
interface A { default int speed() { return 1; } }
interface B { default int speed() { return 2; } }

class C implements A, B {
    public int speed() {
        return A.super.speed();    // 撞名時編譯器強迫自己選
    }
}

// class D extends X, Y { }        // 編譯錯誤：只能 extends 一個
//   X、Y 各帶欄位與建構子，疊在同一個物件裡初始化順序會說不清

abstract class Base { }
class E extends Base implements A { }   // 一個「是一種」＋ 若干「能做」

// 要共用欄位、建構子、骨架 → abstract class
// 只約定行為、各實作無關   → interface
```

### 追問：Java 8 之後 interface 有 default method 了，那 abstract class 還有什麼不能被取代的？

三件事：存狀態、建構子、單一繼承的語意。

```java
// 典型寫法（簡化），不是專案原始碼
// 對照外掛：共用解析骨架＝abstract class，各電文欄位對應＝實作
abstract class MessageParser {
    protected final String raw;       // ① 狀態
    protected int pos;                // ① 狀態

    protected MessageParser(String raw) {   // ② 建構子
        this.raw = raw;
        this.pos = 0;
    }

    public final void parse() {       // 共用流程，final 鎖順序
        map();
    }
    protected abstract void map();    // 各電文自己的欄位對應
}

// ③ 單一繼承：這支「是一種」電文解析器
class OrderMessageParser extends MessageParser {
    OrderMessageParser(String raw) { super(raw); }
    protected void map() { }
}

// 換成 interface + default method 會缺：
//   ① 沒地方存 raw、pos  ② 沒建構子  ③ 沒有「是一種」的身分
// 只想約定「能 parse」、各實作互不相干 → interface 就夠
```

### 為什麼要懂

code review 有人說用 interface 加 default method 就好時，要能判斷共用流程需不需要存進度、原文這類每個物件各一份的資料。需要的話 default method 寫不出來，只能繞去用 static 或外部 Map，多執行緒下會互相覆蓋。

### 結論

default method 只補了行為，沒補資料。abstract class 剩下欄位、建構子、單一繼承語意三件事；共用資料加流程骨架用 abstract class，只約定行為用 interface。

### 術語表

| 術語 | 白話定義 |
|---|---|
| default method | interface 裡有方法本體的方法，Java 8 起可寫，實作類別可以不覆寫 |
| 實例欄位 | 屬於單一物件的變數，new 幾個就有幾份 |
| 狀態 | 物件身上存的、會隨執行改變的資料 |
| 常數（public static final） | 全體共用一份、不能改的值；interface 欄位一律是這種 |
| 建構子 | new 時自動執行的初始化區塊 |
| super(...) | 子類別建構子呼叫父類別建構子，必須是第一行 |
| 單一繼承 | 一個類別只能 extends 一個父類別，但可 implements 多個 interface |
