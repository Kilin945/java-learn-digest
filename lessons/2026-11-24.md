## A6 第 1 篇 · 一個請求進來：DispatcherServlet → HandlerMapping → 你的 Controller 方法

**題目：Spring MVC 一個請求從進到出的流程？**（第 1 篇：只講「進來」，參數轉換與回傳在第 2 篇，攔截器與例外處理在第 3 篇）

### 題目在問什麼
- 請求 = 一次 HTTP 呼叫，長相是「方法 + 網址」，例如 POST /qa-ask。
- 「從進到出」= 經過哪些角色、順序、各自負責什麼。
- 今天只講：請求怎麼找到你的 Controller 方法。

```
// 輸入：POST /qa-ask
// 輸出：你的某個 Controller 方法被呼叫一次
```

### 解題思路
1. Tomcat 只懂 Servlet，所以先問 Spring 靠哪個 Servlet 接手（第 1 篇）
2. 網址是文字、Controller 是方法，所以問誰負責對照（第 1 篇）
3. 轉參數、呼叫（第 2 篇）
4. 回傳轉 JSON／頁面（第 2 篇）
5. 攔截器、例外統一處理（第 3 篇）

### 答案
請求先進 DispatcherServlet（唯一入口），它問 HandlerMapping 這個「方法+網址」對應哪個 Controller 方法，拿到答案才往下交給別人去呼叫。

```java
// 簡化示意：不是原始碼
protected void doDispatch(HttpServletRequest request, HttpServletResponse response) {
    HandlerExecutionChain chain = getHandler(request);                  // ① 查 HandlerMapping
    HandlerAdapter adapter = getHandlerAdapter(chain.getHandler());     // ② 找會呼叫它的 adapter（第 2 篇）
    adapter.handle(request, response, chain.getHandler());              // ③ 呼叫（第 2 篇）
}
```

### 第 1 輪 · 釐清：DispatcherServlet 到底是什麼？
Spring 內建的類別，本質是 Servlet，Spring Boot 啟動時自動註冊進 Tomcat，路徑對應 "/"。它是 Servlet 世界與 Spring 世界的交接口。

```
DispatcherServlet extends FrameworkServlet extends HttpServlet
瀏覽器 → Tomcat → DispatcherServlet.service() → Spring MVC
```

### 第 2 輪 · 追原因：為什麼要唯一入口，不是一網址一 Servlet？
一網址一 Servlet 要各自註冊並重複寫編碼、讀 body、轉型別、例外處理等共通邏輯。Front Controller 設計讓共通邏輯在入口做一次，新增網址只要多一個普通方法。

```java
// 典型寫法（簡化）：老做法
@WebServlet("/qa-ask")
public class QaAskServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) { /* 每個都要重複 */ }
}
```

### 第 3 輪 · 連結經驗：qa-ask 那條鏈，對照表在 Controller 長什麼樣？
啟動時 Spring 掃描 @RequestMapping 系列註解，自己建出對照表。

```java
// 典型寫法（簡化）：名稱為示意
@RestController
public class SomeController {
    @PostMapping("/qa-ask")   // 表中一列：POST /qa-ask → ask()
    public Object ask() { return null; }
}
// 查不到 → 404；網址對、HTTP 方法不對 → 405
// 預設實作：RequestMappingHandlerMapping
```

### 為什麼要懂
 API 回 404／405 時，要知道問題在「對照表沒有這一列」：網址寫錯、HTTP 方法不對、或 Controller 沒被掃描到。

### 結論
請求先到 Tomcat，交給唯一入口 DispatcherServlet，它查 HandlerMapping 的「網址 → 方法」表，找到 Controller 方法才往下走。

深入官方文件：https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-servlet.html

### 術語表
| 術語 | 說明 |
|---|---|
| Servlet | Java 規定的接 HTTP 請求的標準類別，Tomcat 只認識它 |
| DispatcherServlet | Spring MVC 內建的 Servlet，唯一入口，負責分派 |
| HandlerMapping | 「網址+HTTP 方法 → 處理者」的對照表與查表邏輯 |
| Handler | 處理者，通常是標了 @PostMapping 等註解的 Controller 方法 |
| Front Controller | 所有請求先走同一入口再分派的設計 |
| HandlerAdapter | 實際呼叫處理者、轉好參數的角色（第 2 篇） |
