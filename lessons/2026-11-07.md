## A7 第 1 篇 · Controller 外面那一圈

**題目：Spring MVC 和 Spring Boot 差在哪？**

### 題目在問什麼
- Spring MVC：Spring 處理 HTTP 請求的 web 框架。
- Spring Boot：包在 Spring 外面、減少設定的腳手架，不是另一個 web 框架。
- 要答到：①兩者關係 ②外面那一圈（設定、打包、執行）的差別 ③自己專案各用哪種。

```java
@RestController
public class HelloController {
    @GetMapping("/hello")
    public String hello() { return "hi"; }
}
// 差別在外面：設定（XML vs 註解＋自動配置）、執行（外部 Tomcat+WAR vs 內嵌 Tomcat+jar）、相依（手挑 vs starter）
```

### 解題思路
1. 先確認兩者是不是同一層：MVC 是框架本體，Boot 是腳手架（本篇）。
2. Controller 兩邊一樣，差別在設定、相依、佈署（本篇）。
3. Boot 為何不用 XML 也能動：第 2 篇。
4. 對回自己的專案（本篇）。

### 答案
MVC 是 web 框架本體，Boot 是包起來的腳手架：@SpringBootApplication 取代 web.xml／XML，starter 管相依，內嵌 Tomcat 讓 jar 直接跑。

```java
// 傳統：web.xml 宣告 DispatcherServlet + applicationContext.xml 宣告 Bean + WAR 丟進外部 Tomcat
// Boot：
@SpringBootApplication
public class App {
    public static void main(String[] args) { SpringApplication.run(App.class, args); }
}
// pom: spring-boot-starter-web；執行：java -jar app.jar
```

### 第 1 輪（釐清）內嵌 Tomcat 到底是什麼？
Tomcat 本質是一堆 jar。外部：Tomcat 是主角、WAR 是客人；內嵌：你的 main() 是主角，Tomcat 是零件。SpringApplication.run() 會建容器、new Tomcat、註冊 DispatcherServlet、監聽 8080。

### 第 2 輪（反事實）沒有 starter 會壞在哪？
要自己對 spring-webmvc、jackson、tomcat 版本，挑錯常在執行期才出 NoSuchMethodError／ClassNotFoundException。starter 是一份相依清單，配合 parent 的 BOM 決定版本，不寫版本號。

### 第 3 輪（連結經驗）現職 vs anki-forge
| 要做的事 | 現職（MVC＋XML＋外部 Tomcat） | anki-forge（Boot） |
|---|---|---|
| 宣告 Bean | XML `<bean>` 或 XML 開掃描 | @SpringBootApplication 掃描 |
| 啟動入口 | Tomcat 讀 web.xml | main() 的 SpringApplication.run |
| 打包 | WAR | jar |
| 執行環境 | 要先有 Tomcat | java -jar |
| 改 port／連線 | Tomcat 或 XML | application.properties／yml |

### 為什麼要懂
維護 XML＋WAR 時要分辨問題出在 Tomcat、web.xml 還是 Spring XML；轉 Boot 時要知道 port、Bean 是誰設定的。

### 結論
Controller 裡的 MVC 概念不變，Boot 改掉的是外面那一圈。

### 術語表
- Spring MVC：處理 HTTP 的 web 框架。
- web.xml：傳統 web 應用的啟動說明書。
- DispatcherServlet：MVC 總收發室。
- WAR：給 Servlet 容器載入的打包檔。
- 內嵌 Tomcat：把 Tomcat 當函式庫由 main() 啟動。
- starter：配好版本的相依清單。
- BOM：版本對照表。
- @SpringBootApplication：設定類別＋自動配置＋元件掃描的合併註解。
