## 衍生查詢 vs @Query · 第 4 步

### How to Choose: Derived Query or @Query?

這是本主題的收尾步驟：不學新語法，學「該用哪一種」的判斷原則。

- **Derived Query Method（衍生查詢方法）**：靠方法名稱的命名規則，讓 Spring Data JPA 自動生成 SQL，適合條件簡單（1~2 個）的情境，方法名稱本身就是文件。
- **@Query + JPQL + @Param**：直接手寫查詢語法，適合條件變多（3 個以上）、需要 JOIN、聚合函式，或方法名稱長到難以一眼看懂的情境。

判斷原則：**方法名稱一眼看不懂在查什麼，就是換 @Query 的時候。**

```java
// ❌ 條件一多，方法名稱開始難讀
List<User> findByUsernameAndStatusAndCreatedAtAfterOrderByCreatedAtDesc(
    String username, String status, LocalDateTime after);

// ✅ 改用 @Query，意圖一眼看懂
@Query("SELECT u FROM User u " +
       "WHERE u.username = :username AND u.status = :status " +
       "AND u.createdAt > :after ORDER BY u.createdAt DESC")
List<User> searchUsers(@Param("username") String username,
                        @Param("status") String status,
                        @Param("after") LocalDateTime after);
```

### 術語表

| 術語 | 定義 |
|---|---|
| Readability（可讀性） | 別人（或未來的你）看到這段程式碼，能不能很快看懂它在做什麼 |
| Decision Rule（判斷原則） | 幫你快速決定「這次該用哪個工具」的經驗法則，不是絕對規定 |

### 本主題完整回顧（Step 1~4）

1. Derived Query Method 靠方法名稱自動翻譯成 SQL。
2. 可用 And / Or 組合多個欄位條件，欄位順序需與參數順序一致。
3. 條件太多變得難讀時，可改用 @Query 寫 JPQL，搭配 @Param 對應佔位符。
4. 選擇原則：條件簡單用衍生查詢；條件複雜或需要客製 SQL 邏輯時改用 @Query。
