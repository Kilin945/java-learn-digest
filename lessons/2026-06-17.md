## 建構子注入 vs 欄位注入 vs setter 注入 · 第 1 步

### 概念：Field Injection（欄位注入）

**依賴注入（Dependency Injection, DI）**：物件不自己 `new` 依賴，由 Spring 容器從外部「送」進來。廚師（Service）不自己買菜，由後台（容器）送食材（Repository）進廚房。

**欄位注入**是最簡單的寫法：直接在欄位上標 `@Autowired`，Spring 啟動後用反射（Reflection）塞值。

### 程式碼範例

```java
@Service
public class OrderService {

    @Autowired                   // Spring 自動塞入
    private UserRepository userRepository;

    public void placeOrder(Long userId) {
        userRepository.findById(userId);
    }
}
```

### 欄位注入的三個缺點

| 缺點 | 說明 |
|---|---|
| ① 不能加 `final` | 注入發生在物件建立後，欄位無法宣告為不可變 |
| ② 測試困難 | 不啟動 Spring 容器就無法注入，單元測試難寫 |
| ③ 隱藏依賴 | 從建構子看不出類別需要什麼，可讀性差 |

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Dependency Injection | 依賴注入 (DI) | 不讓物件自己 new 依賴，由外部送進來 |
| @Autowired | 自動裝配 | 告訴 Spring 在此位置塞入對應 Bean |
| Field Injection | 欄位注入 | 在欄位上標 @Autowired，Spring 用反射注入 |
| Reflection | 反射 | Java 執行期間繞過 private 存取欄位的機制 |
