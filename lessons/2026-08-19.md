## 統一例外處理：@RestControllerAdvice · 第 4 步

### 概念：Catch-all Handler with Exception.class

前面已經幫 `ResourceNotFoundException` 建立了專屬的 `@ExceptionHandler`，但真實世界裡例外種類千百種，不可能每一種都寫一個 handler。解法是額外加一個處理 `Exception.class`（Java 所有例外的共同父類別）的方法，當作「萬用備援」：只要沒有更精確符合的 handler，Spring 就會把例外交給它，統一回傳結構化 JSON 與 500 Internal Server Error 狀態碼。

### 程式碼

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(ResourceNotFoundException ex) {
        ErrorResponse error = new ErrorResponse(404, ex.getMessage());
        return new ResponseEntity<>(error, HttpStatus.NOT_FOUND);
    }

    // 新增：接住其他所有沒被特別處理的例外
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleUnknown(Exception ex) {
        ErrorResponse error = new ErrorResponse(500, "系統發生未預期的錯誤");
        return new ResponseEntity<>(error, HttpStatus.INTERNAL_SERVER_ERROR);
    }
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| Exception.class（萬用例外類別） | Java 所有例外的共同父類別，抓它等於抓住「其他沒被特別處理的例外」 |
| Fallback handler（備援處理方法） | 當沒有更精確符合的 handler 時，最後拿來兜底的方法 |
| 500 Internal Server Error（伺服器內部錯誤） | 問題出在伺服器端程式本身，不是使用者操作錯誤 |
