## IoC 與依賴注入：為什麼不要自己 new · 第 6 步

### 概念：Bean Scope — Singleton vs Prototype

Spring 管理 Bean 時有「作用域（Scope）」的概念，決定同一個 Bean 定義要建立幾個實例：

- **Singleton（預設）**：整個 ApplicationContext 只有一個實例，所有注入點共用同一顆物件。適合無狀態 Service。
- **Prototype**：每次注入或 `getBean()` 都建立全新實例。適合需要獨立狀態的物件。

**比喻**：Singleton = 公司公用咖啡機（全公司只有一台）；Prototype = 自動販賣機（每按一下出來一杯全新的）。

### 程式碼

```java
// Singleton（預設）
@Service
public class OrderService {
    public double calcTotal(List<Item> items) { ... }
}

// Prototype：每次注入都拿到全新物件
@Service
@Scope("prototype")
public class ReportBuilder {
    private final List<String> lines = new ArrayList<>();
    public void addLine(String line) { lines.add(line); }
    public String build()            { return String.join("
", lines); }
}
```

### 術語表

| 術語 | 中文 | 定義 |
|------|------|------|
| Scope | 作用域 | 決定 Spring 為同一 Bean 定義建立幾個實例 |
| Singleton | 單例 | 整個 ApplicationContext 只有一個實例（Spring 預設） |
| Prototype | 原型 | 每次注入/getBean() 都建立全新實例 |
| Stateless | 無狀態 | 物件不保存因呼叫者不同而差異的資料，可安全共用 |

### 核心原則

> 大多數 Service 無狀態，用預設 Singleton 共用就好；需要獨立狀態的物件，加 `@Scope("prototype")` 讓每次注入都拿到全新的一顆。
