## Logging 與結構化日誌 · 第 5 步

### Structured Logging: from plain text to JSON

**重點**：純文字 log 給人讀，但機器很難依欄位搜尋；結構化日誌把每筆 log 寫成一行 JSON，每個資訊有自己的欄位（時間、等級、訊息、requestId…），日誌平台可直接篩選。

比喻：自由發揮的便條紙 vs. 有固定欄位的表格。

Spring Boot 3.4+ 只要加一行設定，程式碼不用動：

```properties
# application.properties
# 可選格式：ecs / logstash / gelf
logging.structured.format.console=logstash
```

```java
log.info("Order created, orderId={}", orderId);
```

輸出大致為（實際為單行）：

```json
{
  "@timestamp": "2026-10-02T09:15:30.123+08:00",
  "level": "INFO",
  "logger_name": "com.example.OrderService",
  "message": "Order created, orderId=42",
  "requestId": "a1b2c3"
}
```

- 昨天放進 MDC 的 requestId 會自動成為 JSON 欄位，不用再寫 `%X{requestId}`。
- 格式選擇：`ecs`（Elastic）、`logstash`（最通用）、`gelf`（Graylog）；不確定就選 `logstash`。
- 建議只在正式環境開啟 JSON，本機開發維持純文字（可用 Spring profile 分開）。

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Structured Logging | 結構化日誌 | 把每筆 log 寫成有固定欄位的資料（通常是 JSON） |
| JSON | 一種資料格式 | 用 `{"欄位":"值"}` 表示資料的文字格式 |
| Field | 欄位 | 資料裡有名字的一格，如 level、message、requestId |
| Log platform | 日誌平台 | 集中收集、搜尋、分析 log 的系統，如 Elasticsearch、Loki、Datadog |
| Profile | 設定檔環境 | Spring 依環境（開發／正式）切換設定的機制 |

官方文件：https://docs.spring.io/spring-boot/reference/features/logging.html#features.logging.structured
