## 交易：@Transactional 的邊界與陷阱 · 第 2 步

### 概念：Self-Invocation Trap（自我呼叫陷阱）

Spring 的 @Transactional 是靠 **AOP（切面導向程式設計）** 實作的：Spring 會幫被標註的物件包一層 **Proxy（代理人）**。外部呼叫方法時，其實是先呼叫到代理人，代理人負責開交易、蓋章、決定 commit 或 rollback，最後才轉交給真正的物件執行。

如果在**同一個 class 內**，方法 A 直接用 `this.methodB()` 呼叫同一個 class 的方法 B，這個呼叫完全**繞過了代理人**，所以就算 methodB 標了 @Transactional，也不會有任何交易保護——不會自動 rollback。

這種「物件內部自己呼叫自己方法」的情況，叫做 **self-invocation（自我呼叫）**。

### 範例：問題寫法

```java
@Service
public class OrderService {

    public void placeOrder(Order order) {
        // 自己呼叫自己，沒經過代理人
        this.saveOrder(order);
    }

    @Transactional
    public void saveOrder(Order order) {
        // 這裡丟例外也不會自動 rollback
        orderRepository.save(order);
    }
}
```

> 正確修法（把交易方法搬到另一個 class，讓外部透過代理物件呼叫）將在下一步說明。

### 術語表

| 術語 | 定義 |
|---|---|
| Proxy（代理） | Spring 幫物件包的一層代理人，外部呼叫先經過它，才能插入交易等額外邏輯 |
| AOP（切面導向程式設計） | 把共用邏輯（交易、記錄等）插進方法前後執行的技術，是 @Transactional 的底層機制 |
| Self-invocation（自我呼叫） | 同一個 class 內一個方法直接呼叫另一個方法（如 this.xxx()），不會經過代理人 |
