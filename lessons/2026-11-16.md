## A2 第 1 篇 · 欄位注入 vs 建構子注入：測試時 new 不出來、依賴藏起來

### ⭐ @Autowired 欄位注入為什麼 IDE 給黃線？建構子注入好在哪？

**題目在問什麼**

- 欄位注入：把 @Autowired 寫在欄位上，讓 Spring 幫你放進去。
- 建構子注入：把需要的物件寫成建構子參數，由 Spring 呼叫建構子時傳進來。
- 依賴：這個類別要靠別的物件才能動，那個別的物件就是它的依賴。
- 要答到兩件事：黃線在警告什麼；建構子注入好在哪。本篇只講「測試 new 不出來」和「依賴藏起來」。

```java
// 典型寫法（簡化）：欄位注入
@Service
public class OrderService {
    @Autowired                          // ← IDE 在這一行畫黃線
    private PaymentClient paymentClient;
}

// 典型寫法（簡化）：建構子注入
@Service
public class OrderService {
    private final PaymentClient paymentClient;
    public OrderService(PaymentClient paymentClient) {
        this.paymentClient = paymentClient;
    }
}
```

**解題思路**

1. 先弄清楚黃線在警告什麼：不是會出錯，而是寫法有問題。
2. **看 private 欄位外面（測試）塞不塞得進去。（本篇）**
3. **看欄位注入有沒有地方列出依賴，讀的人能不能一眼知道它要什麼。（本篇）**
4. **對照建構子注入怎麼解決上面兩點。（本篇）**
5. final 與循環依賴（第 2 篇）。

**答案**

黃線的意思是：能動，但不好測也不好讀。欄位注入把依賴藏在 private 欄位裡，外面塞不進假物件，也看不出類別要幾樣東西；建構子注入把依賴寫在簽章上，直接 new 就能塞 mock。

```java
// 欄位注入：沒有地方塞假物件
OrderService s1 = new OrderService();   // 能 new，但 paymentClient 是 null

// 建構子注入：直接塞
OrderService s2 = new OrderService(mockPaymentClient);
```

### 第 1 輪 · 釐清：@Autowired 寫在 private 欄位上，Spring 到底怎麼塞進去？

```java
// 簡化示意：Spring 做的事大致等於
OrderService bean = new OrderService();          // ① 無參數建構子 new
Field f = OrderService.class
        .getDeclaredField(paymentClient);        // ② 用名字找欄位
f.setAccessible(true);                           // ③ 關掉 private 檢查（反射）
f.set(bean, paymentClientBean);                  // ④ 塞進去
// 沒有 Spring 就沒人做 ②③④，欄位一直是 null
```

### 第 2 輪 · 反事實：沒有 Spring 容器，欄位注入的 OrderService 在單元測試會壞在哪？

```java
// 簡化示意：欄位注入版
@Test
void payWithFieldInjection() {
    OrderService s = new OrderService();
    s.pay(100);   // 💥 NullPointerException
}
// 只剩三條路：啟動整個 Spring（慢）、@InjectMocks（底層也是反射）、反射硬塞（欄位改名就壞）

// 簡化示意：建構子注入版
@Test
void payWithConstructorInjection() {
    PaymentClient mock = Mockito.mock(PaymentClient.class);
    OrderService s = new OrderService(mock); // 忘了傳依賴就編譯不過
    s.pay(100);
}
```

### 第 3 輪 · 連結經驗：我天天看到的那條黃線，在我的 code 裡實際在指什麼？

IntelliJ 通常寫「Field injection is not recommended」，指的是依賴藏起來、類別悄悄變胖。

```java
// 典型寫法（簡化）：欄位注入，依賴悄悄一個一個加
@Service
public class OrderService {
    @Autowired private PaymentClient paymentClient;
    @Autowired private StockService stockService;
    @Autowired private MailSender mailSender;
    @Autowired private CouponService couponService;
    @Autowired private AuditLogger auditLogger;
}

// 典型寫法（簡化）：建構子注入，同樣五個依賴
public OrderService(PaymentClient p, StockService s, MailSender m,
                    CouponService c, AuditLogger a) { ... }
// 參數列一長，就會察覺類別管太多事
```

### 為什麼要懂

替舊的 Service 補單元測試時，欄位注入的類別 new 出來就是 NullPointerException，只能啟動整個 Spring 來測，一個測試跑好幾秒。懂了原因就知道該改成建構子注入。

### 結論

黃線不是說你寫錯，而是欄位注入讓依賴藏起來、讓測試離不開 Spring。建構子注入把依賴寫在簽章上，缺什麼一眼看到，測試直接 new。

### 📖 術語表

| 術語 | 白話定義 |
|---|---|
| 依賴 | 這個類別要靠別的物件才能完成工作，那個別的物件就是它的依賴 |
| 注入 | 不是類別自己 new 依賴，而是由外面（Spring）交給它 |
| 容器 | Spring 啟動後負責建立、保管所有 Bean 並互相接起來的東西 |
| 反射 | 程式在執行時用名字找到欄位或方法並操作，連 private 也能繞過 |
| mock | 測試用的假物件，回傳事先設定好的結果 |
