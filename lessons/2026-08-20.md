## 統一例外處理：@RestControllerAdvice · 第 5 步

### 概念：Putting It All Together（拼圖組裝與收尾）

這是本主題最後一步，把前四天教過的內容整合成一個完整可用的 `GlobalExceptionHandler`：

1. 痛點：每個 Controller 各自 try-catch，程式碼重複又分散
2. 解法：`@RestControllerAdvice` 建立全域例外處理中心，`@ExceptionHandler` 指定要處理的例外類型
3. 升級：用 `ResponseEntity<ErrorResponse>` 回傳結構化 JSON，並正確設定 HTTP 狀態碼
4. 補強：加入 `@ExceptionHandler(Exception.class)` 作為萬用備援，統一回傳 500，避免洩漏原始錯誤堆疊

Spring 選擇處理方法的原則是「最精確符合」（most specific match）：即使同一個 class 裡同時有針對 `ResourceNotFoundException` 與 `Exception` 的處理方法，拋出 `ResourceNotFoundException` 時 Spring 仍會優先用專門為它寫的方法，萬用方法只接住其餘沒被點名的例外。

### 完整程式碼

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 專門處理：找不到資源
    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(
            ResourceNotFoundException ex) {
        ErrorResponse body = new ErrorResponse(404, ex.getMessage());
        return new ResponseEntity<>(body, HttpStatus.NOT_FOUND);
    }

    // 萬用備援：其他沒被特別處理的例外都會掉進這裡
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleAll(Exception ex) {
        ErrorResponse body =
            new ErrorResponse(500, "系統發生未預期的錯誤");
        return new ResponseEntity<>(
            body, HttpStatus.INTERNAL_SERVER_ERROR);
    }
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| @RestControllerAdvice | 全域例外攔截中心，整個應用程式共用一份 |
| @ExceptionHandler | 標註方法負責處理哪一種例外 |
| Fallback（備援） | 沒有專門處理方法符合時的最後防線 |
| Most specific match | Spring 挑選處理方法時優先用最貼近例外類型的那一個 |

### 一句話帶走

把分散的 try-catch 集中成一個 GlobalExceptionHandler，Spring 會自動幫你挑最精確的處理方法，程式碼更乾淨、也更不容易漏掉錯誤處理。
