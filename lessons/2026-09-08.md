## 交易：@Transactional 的邊界與陷阱 · 第 5 步

### 概念：Keep Transaction Boundaries Small & Local（交易邊界要小、要在地）

把交易想像成「請銀行行員一起做完這幾筆轉帳，做不成就全部取消」。行員處理時會鎖住相關資料列，不讓別人動。如果在交易進行中還請行員順便做跟資料庫無關的慢事（打外部 API、寄 email、寫檔案），行員就會一直站著等，鎖住的資料也不會放開。後面排隊的請求要等，資料庫的連線池（數量有限的共用連線車隊）也會被占滿，最後拖累整個系統。

原則：`@Transactional` 方法裡只放「跟資料庫有關、要一起成功或一起失敗」的操作；慢的外部呼叫搬到交易外面。

```java
// ❌ 問題寫法：外部 API 呼叫被包進交易裡，連線被占著等它
@Transactional
public void placeOrder(Order order) {
    orderRepository.save(order);
    paymentGateway.charge(order);   // 打外部金流 API，可能要等好幾秒
    inventoryRepository.decreaseStock(order);
}

// ✅ 改善寫法：外部呼叫搬到交易外面，交易只包資料庫操作
public void placeOrder(Order order) {
    paymentGateway.charge(order);        // 先在交易外做慢動作
    saveOrderAndStock(order);            // 再進交易，只碰資料庫
}

@Transactional
public void saveOrderAndStock(Order order) {
    orderRepository.save(order);
    inventoryRepository.decreaseStock(order);
}
```

**一句話帶走**：交易只鎖資料庫的事，慢的外部呼叫搬出去，連線才不會被占住。

### 術語表

| 術語 | 定義 |
|---|---|
| Connection Pool（連線池） | 資料庫連線組成的共用車隊，數量有限，占滿時其他請求要排隊。 |
| Transaction Boundary（交易邊界） | `@Transactional` 方法的範圍，決定哪些操作要一起成功或一起失敗。 |
| External Call（外部呼叫） | 呼叫資料庫以外的服務，如 API、寄信，速度較慢也不受 rollback 保護。 |

### 主題小結（@Transactional 邊界與陷阱，5 步回顧）

1. `@Transactional` 讓方法成為交易邊界：正常結束 commit，丟例外 rollback。
2. Spring 用 proxy 實作，同 class 內 self-invocation（`this.xxx()`）會繞過 proxy，導致失效。
3. 預設只在 unchecked exception 才 rollback；checked exception 需要 `rollbackFor` 才會觸發。
4. 例外被 try-catch 吞掉（沒有 rethrow）時，Spring 偵測不到，交易照樣 commit。
5. 交易邊界要小、要在地：別把外部呼叫這類慢動作包進交易，避免占用連線池拖累系統。
