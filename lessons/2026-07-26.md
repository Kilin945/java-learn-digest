## application.yml 結構與設定優先序 · 第 4 步

### 概念：環境變數也能覆寫 yml

昨天學到命令列參數（command-line argument）可以覆寫 application.yml。今天多認識一個一樣能覆寫 yml 的來源：**環境變數（environment variable）**，可以想成是貼在整台機器上的便利貼，任何在這台機器上跑的程式都讀得到。

Spring Boot 有個叫「**寬鬆綁定（relaxed binding）**」的規則：自動把環境變數名稱轉成 yml 的點記法（dot notation）——全部轉大寫、點改成底線。

所以 `server.port` 對應的環境變數就是 `SERVER_PORT`。

目前已知的設定優先序：

```
命令列參數 (command-line argument) > 環境變數 (environment variable) > application.yml
```

### 程式碼範例

```bash
# application.yml 裡寫的是 8080
server:
  port: 8080

# 設定環境變數
export SERVER_PORT=9090

# 沒加命令列參數 → 用環境變數的 9090
java -jar app.jar

# 同時加了命令列參數 → 命令列參數贏，變成 7070
java -jar app.jar --server.port=7070
```

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| environment variable | 環境變數 | 存在作業系統這台機器上的設定值，任何在這台機器啟動的程式都能讀到 |
| relaxed binding | 寬鬆綁定 | Spring Boot 自動把 SERVER_PORT 對應成 server.port，不用手動轉換 |
| override | 覆寫 | 後面生效的設定值把前面的值蓋掉，最後只有一個值生效 |

### 今日一句話帶走

環境變數也能蓋掉 yml，Spring Boot 靠寬鬆綁定自動對應名稱；但命令列參數優先序還是比環境變數高。
