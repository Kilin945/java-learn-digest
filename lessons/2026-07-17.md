## @SpringBootApplication 與自動組態的原理 · 第 2 步

### 概念：Conditional Auto-Configuration（@ConditionalOnClass）

Spring Boot 的自動組態不是憑空發生的，它是靠「條件判斷」決定要不要套用某段設定。

- Spring Boot 內部有上百個 `XxxAutoConfiguration` 組態類別。
- 每個都可能貼著 `@ConditionalOnClass`，意思是「只有當 classpath（類別路徑，即專案裡實際可用的程式碼）上存在某個類別時，這段自動設定才會生效」。
- 例如加了 `spring-boot-starter-web`（一種「懶人包依賴」，一次打包好常用相關 jar 檔）之後，classpath 上會出現 Tomcat 相關類別，Spring Boot 偵測到就自動幫你設定好內建網頁伺服器。

比喻：智慧管家打開冰箱看到有什麼食材，才決定要不要動手做對應的菜——不是亂猜，是「看得到才做」。

### 範例程式碼（簡化示意）

```java
@Configuration
@ConditionalOnClass(Tomcat.class)   // classpath 上要有 Tomcat 這個類別才生效
public class TomcatAutoConfiguration {

    @Bean
    public WebServerFactory tomcatFactory() {
        return new TomcatServletWebServerFactory();
    }
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| classpath（類別路徑） | 專案裡實際有哪些程式碼（jar 檔）可以被用到 |
| @ConditionalOnClass（條件式組態） | 貼在自動組態類別上，指定「classpath 上要有某類別才套用這段設定」 |
| starter（懶人包依賴） | 像 spring-boot-starter-web 這種，一次打包好常用相關依賴的套件 |

### 昨日回顧

@SpringBootApplication 是 @SpringBootConfiguration、@EnableAutoConfiguration、@ComponentScan 三個註解的懶人包，貼一個等於三個都套用。
