## A3 第 2 篇 · scope：singleton／prototype／request；singleton 裡注入 prototype 只會注入一次

**題目：Bean 生命週期與 scope？singleton 預設代表什麼？**

### 題目在問什麼
- scope（作用域）＝容器替某個 Bean「造幾個物件、什麼時候造、活多久」的規則。
- 要答完三件事：三種 scope 各是什麼、singleton 為什麼是預設、singleton 裡注入 prototype 會出什麼狀況。
- 要先弄清楚：「注入」這個動作發生在哪一刻？

```java
// singleton ：整個容器只造 1 個，大家共用（預設）
// prototype ：每次有人跟容器要，就造 1 個新的
// request   ：每個 HTTP 請求造 1 個，請求結束就丟（只有 Web 環境才有）
// 輸入：ServiceA（singleton）依賴 Counter（prototype），呼叫 ServiceA 三次
// 輸出：三次用的都是同一個 Counter
```

### 解題思路
1. 先把 scope 定義成「造幾個、何時造」。
2. 逐個對照：一份／每次新的／每請求一份。
3. 看注入發生在哪一刻：建 singleton 的那一次，只有一次。
4. 想每次都新的，改成用到時才向容器現拿（ObjectProvider）。
5. 生命週期（建構 → 注入 → @PostConstruct → @PreDestroy）在第 1 篇講過。

### 答案
singleton 是預設 scope，容器裡只有一份、所有人共用；prototype 每次要都給新的；request 每個 HTTP 請求一份。

```java
@Component                      // 預設 singleton
class ErrorCodeService { }

@Component
@Scope("prototype")             // 每次跟容器要就 new 新的
class Counter { }

@Component
@RequestScope                   // 每個 HTTP 請求 1 個；沒有請求的環境用不了
class RequestContext { }
```

### 第 1 輪（釐清）：singleton 說「只有一份」，這個「一份」到底是怎麼算的？
```java
ErrorCodeService a = ctx.getBean(ErrorCodeService.class);
ErrorCodeService b = ctx.getBean(ErrorCodeService.class);
System.out.println(a == b);   // true

Counter x = ctx.getBean(Counter.class);
Counter y = ctx.getBean(Counter.class);
System.out.println(x == y);   // false
// 「一份」是每個容器、每個 Bean 定義一份，不是 JVM 全域單例。
```

### 第 2 輪（比較）：prototype 和 request 差在哪？什麼時候選哪個？
```java
// prototype：每次跟容器要就造新的，跟 HTTP 請求無關；任何環境可用；
//            容器不負責銷毀，@PreDestroy 不會被呼叫
// request  ：每個 HTTP 請求 1 個，同請求內共用；請求結束丟掉；只有 Web 環境有
// 每次用都要全新 → prototype
// 同請求內共用、請求間隔離 → request
// 全站共用、無個別狀態 → singleton
```

### 第 3 輪（連結經驗）：ErrorCodeService 啟動自檢為什麼只跑一次？
```java
// 典型寫法（簡化示意）
@Component
class ErrorCodeService {
    @PostConstruct
    void selfCheck() { }   // 物件只有 1 個 → 只跑 1 次

    // 危險：singleton 欄位是所有請求共用的
    // private String currentUser;
}
```

### 追問：prototype 和 request scope 差在哪？singleton 裡注入 prototype 會發生什麼事？
```java
// ✗ 陷阱：建構子只在建 ServiceA 時跑 1 次，Counter 從此固定
@Component
class ServiceA {
    private final Counter counter;
    ServiceA(Counter counter) { this.counter = counter; }
    void work() { counter.increase(); }
}

// ✓ 用 ObjectProvider 每次現拿
@Component
class ServiceB {
    private final ObjectProvider<Counter> provider;
    ServiceB(ObjectProvider<Counter> provider) { this.provider = provider; }
    void work() {
        Counter c = provider.getObject();   // 每次都向容器要新的
        c.increase();
    }
}
// 另一種做法：lookup method（@Lookup）
```

### 為什麼要懂
在 Service 欄位放請求專屬資料，測試正常、上線多人同時用就會出現「A 看到 B 的資料」，很難重現；以為注入 prototype 就每次是新物件，結果資料一直累積，也是同類問題。

### 結論
預設 singleton ＝ 容器裡只有一份、所有請求共用，所以不能放請求專屬狀態；注入只發生一次，所以 singleton 裡的 prototype 不會自己更新，要每次都新的就用 ObjectProvider 現拿。

官方文件：https://docs.spring.io/spring-framework/reference/core/beans/factory-scopes.html

### 術語表
| 術語 | 說明 |
|---|---|
| scope | 容器替 Bean 造幾個物件、何時造、活多久的規則 |
| singleton | 預設 scope；每個容器、每個 Bean 定義一份，大家共用 |
| prototype | 每次向容器要都給新物件；容器不負責銷毀 |
| request scope | 每個 HTTP 請求一份，請求結束就丟；只有 Web 環境有 |
| ObjectProvider | 取貨窗口，getObject() 時才向容器現拿 Bean |
| lookup method | 用 @Lookup 標記，由容器每次呼叫時回傳新取得的 Bean |
