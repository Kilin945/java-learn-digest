## B8 第 2 篇 · abstract class＝半成品骨架：共用流程寫在父類別，差異留給子類別（電文解析骨架）

**題目**：abstract class 與 interface 差在哪？什麼時候用哪個？（本篇只講 abstract class）

### 題目在問什麼
- 觀念題，要比 interface 與 abstract class。
- 要答到三件事：abstract class 是什麼、跟 interface 的分界、什麼情況選它。
- 判斷依據：實作之間有沒有一大段一樣的流程。

### 解題思路
1. 先講 interface：只約定「能做什麼」（第 1 篇）
2. **abstract class 把共用流程寫死、差異留成空格（本篇）**
3. **判斷依據：實作之間重複的流程多不多（本篇）**
4. default method 之後 abstract class 還剩什麼（第 3 篇）

### 答案
abstract class 是「一類東西的半成品」：共用流程直接寫好，只把子類別不一樣的地方留成 abstract 方法。實作之間有一大段一樣的流程時用它。

```java
// 簡化示意：電文解析骨架
public abstract class AbstractMessageParser {
    public final Map<String, String> parse(String raw) {
        String[] cols = raw.split(",");                // ① 共用：切欄位
        if (cols.length != columnCount()) {            // ② 共用：驗長度，數字由子類別提供
            throw new IllegalArgumentException("欄位數不符: " + raw);
        }
        return mapFields(cols);                        // ③ 差異：留給子類別
    }
    protected abstract int columnCount();
    protected abstract Map<String, String> mapFields(String[] cols);
}

public class BalanceParser extends AbstractMessageParser {
    @Override protected int columnCount() { return 3; }
    @Override protected Map<String, String> mapFields(String[] cols) {
        return Map.of("type", cols[0], "account", cols[1], "amount", cols[2]);
    }
}
// new BalanceParser().parse("BAL,A123,1000") → {type=BAL, account=A123, amount=1000}
```

### 第 1 輪 · 釐清：方法前面加 abstract 到底是什麼意思？
```java
protected abstract int columnCount();   // 只有簽名，沒有 { }
new AbstractMessageParser();            // 編譯錯誤：半成品不能 new
// 子類別漏填任何一個空格 → 編譯錯誤，不會等到上線才發現
```

### 第 2 輪 · 反事實：沒有骨架、每支電文各寫完整流程會壞在哪？
```java
// 切欄位、驗長度在每個 Parser 都抄一份，只有欄位對應不同
// 對方改分隔符號 → 要改 N 個類別；改漏一個，那支電文默默解析錯，編譯器不會提醒
// 有骨架：只改父類別一處
```

### 第 3 輪 · 連結經驗：在我的 Groovy 外掛電文處理裡長什麼樣子？
```groovy
// 典型寫法（簡化）：不是專案原始碼，類別名稱是示意
abstract class BaseMessageParser {        // 共用解析骨架
    final Map parse(String raw) { return mapFields(raw.split(',')) }
    abstract Map mapFields(String[] cols)  // 留給各電文的空格
}
class SomeMessageParser extends BaseMessageParser {  // 各電文的欄位對應
    Map mapFields(String[] cols) { /* 這支電文的欄位對應 */ }
}
```
新增電文＝新增子類別、只寫欄位對應；共用流程要改＝只改父類別。

### 為什麼要懂
新增電文時知道只要填空格、不用整份複製；共用格式改了，只改父類別一處。

### 結論
abstract class 是半成品：共用流程寫在父類別，差異留成 abstract 方法給子類別填。實作間重複流程多就選它，只約定行為、各實作無關才選 interface。

### 術語表
| 術語 | 白話定義 |
|---|---|
| abstract class | 抽象類別。半成品類別，可含寫好的方法和空格，不能直接 new |
| abstract 方法 | 只有簽名、沒有內容的方法，等於骨架上的空格，子類別一定要填 |
| 父類別／子類別 | 被繼承的是父類別，用 extends 繼承它的是子類別 |
| @Override | 標示「我在填（或改寫）父類別的那個方法」，簽名寫錯編譯器會報錯 |
| final 方法 | 子類別不能改寫的方法，用來鎖死流程順序 |
| 電文 | 系統之間傳遞的固定格式文字，欄位位置與意義事先約定 |
