## B2 第 1 篇 · 序列化與反序列化：物件變成位元組再變回來的 code

### ⭐ Java 序列化是什麼？哪裡會炸？

**題目在問什麼**

- 序列化：把記憶體裡的物件轉成一串位元組（byte[]）。
- 反序列化：把位元組還原成物件。
- 要回答兩件事：它是什麼、哪裡會出錯。本篇講前者，地雷放第 2 篇。

```java
// 輸入：記憶體裡的物件
User u = new User("kilin", 30);
// 輸出（序列化）：byte[]，開頭固定 [-84, -19, 0, 5, ...]（0xACED 記號）
byte[] bytes = ...;
// 反序列化：同一串位元組 -> 內容相同、但重新建出來的另一個 User
User copy = ...;
```

**解題思路**

1. 物件只活在記憶體，所以先搞懂要變成位元組。（本篇）
2. 不是任何物件都能轉，要有 Serializable 標記。（本篇）
3. 寫出去、讀回來各用哪個類別。（本篇）
4. 改版後讀不回來：serialVersionUID。（第 2 篇）
5. 不該存的東西：transient。（第 2 篇）

**答案**

序列化用 `ObjectOutputStream.writeObject`，反序列化用 `ObjectInputStream.readObject`；類別必須 `implements Serializable`，否則丟例外。

```java
// 典型寫法（簡化）
public class User implements Serializable {
    private String name;
    private int age;
}

ByteArrayOutputStream box = new ByteArrayOutputStream();
try (ObjectOutputStream out = new ObjectOutputStream(box)) {
    out.writeObject(new User("kilin", 30));
}
byte[] bytes = box.toByteArray();

try (ObjectInputStream in = new ObjectInputStream(new ByteArrayInputStream(bytes))) {
    User copy = (User) in.readObject(); // 不是 new，User 建構子不會執行
}
```

### 第 1 輪 · 釐清：implements Serializable 到底是什麼？

```java
// 簡化示意
public interface Serializable { }   // 空的標記介面

void writeObject(Object obj) {      // 簡化示意，不是原始碼
    if (!(obj instanceof Serializable)) {
        throw new NotSerializableException(obj.getClass().getName());
    }
    // 用反射讀欄位值，寫成位元組
}
```

### 第 2 輪 · 反事實：欄位的類別沒 Serializable 會壞在哪？

```java
// 典型寫法（簡化）
class Conn { }                        // 沒有 Serializable
class User implements Serializable {
    String name = "kilin";
    Conn conn = new Conn();
}
// 編譯通過；執行 writeObject 時：
// java.io.NotSerializableException: Conn
// runtime 才爆，沒走到該路徑的測試發現不了
```

### 第 3 輪 · 連結經驗：凱基與 SmartRobot-Core 的案例

```java
// 案例一（簡化示意，不是凱基原始碼）
while (hasNext()) {
    try {
        save(serialize(item));
    } catch (Exception e) {
        log.error("序列化失敗 " + item, e); // 每筆失敗都寫 stack trace，磁碟被慢慢填滿
    }
}
// 案例二：session -> writeObject -> byte[] -> Redis -> readObject -> session
// 存的是當時的類別長相，讀的是現在的類別；欄位為何會掉，第 2 篇講。
```

**為什麼要懂**：session、快取、訊息佇列把物件丟進 Redis 或檔案時，背後多半是這套轉換；遇到 NotSerializableException 或資料讀出來怪怪的，要先分辨是寫的一端還是讀的一端出問題。

**結論**：序列化是把物件寫成位元組、反序列化是讀回來；Serializable 是放行標記，欄位裡每個物件也都得有，沒有就在執行時才爆。

### 術語表

| 術語 | 白話定義 |
|---|---|
| 位元組 byte[] | 存檔、傳輸最基本的單位，一串數字 |
| 標記介面 | 沒有方法、只貼標籤的介面，Serializable 即是 |
| runtime 例外 | 編譯時看不出來、跑到那行才丟出的錯誤 |
| 反射 | 執行時查看物件有哪些欄位、值是多少的能力 |
