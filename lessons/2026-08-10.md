## DTO 與 entity 為什麼要分開 · 第 3 步

### Entity → DTO Conversion

昨天學到 DTO 是只放乾淨欄位的類別，但欄位值要有人把它從 Entity「搬」過去。做法：在 DTO 裡寫一個建構子（constructor），讓它吃一個 Entity 物件，逐個欄位複製。沒被複製的欄位（如 password）自然不會出現在 DTO 裡，也就不會被序列化送出去。

比喻：Entity 是倉庫裡資料齊全的貨物（含進貨價、供應商），DTO 是店員照著抄到貨架上的標籤（只有品名、售價）。

```java
public class UserDto {
    private Long id;
    private String name;
    private String email;

    // 建構子：吃一個 User entity，只搬需要的欄位
    public UserDto(User user) {
        this.id = user.getId();
        this.name = user.getName();
        this.email = user.getEmail();
        // user.getPassword() 沒被抄，password 就不會流出去
    }

    public Long getId() { return id; }
    public String getName() { return name; }
    public String getEmail() { return email; }
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| Constructor（建構子） | 物件被 new 出來時第一個執行的方法，通常用來初始化欄位 |
| Conversion / Mapping（轉換 / 映射） | 把一個物件的資料依規則複製到另一種形狀的物件上 |
| Getter（取值方法） | 只負責把某個欄位的值取出來給別人看的方法 |
