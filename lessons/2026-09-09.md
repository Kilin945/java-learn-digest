## 單元測試 vs @SpringBootTest 整合測試 · 第 1 步

### 概念：Unit Test 是什麼

就像組腳踏車時，你會先在桌上單獨測「煞車」這個零件，而不是直接騎上路——unit test（單元測試）就是只測一個 method 或 class，**不碰資料庫、不打真實 API、不啟動 Spring 容器**。特色是：快、獨立、範圍小。

用 JUnit（Java 最常用的測試框架）就能寫：

```java
class Calculator {
    int add(int a, int b) {
        return a + b;
    }
}

class CalculatorTest {

    @Test
    void add_shouldReturnSum() {
        Calculator calc = new Calculator();

        int result = calc.add(2, 3);

        assertEquals(5, result);
    }
}
```

這段測試完全不需要 Spring，跑起來只要幾毫秒。

整合測試（integration test）留到下一步再講。

### 術語表

| 術語 | 定義 |
|---|---|
| Unit Test（單元測試） | 只測一個方法或 class，不依賴外部資源，跑得快 |
| Integration Test（整合測試） | 把多個零件組裝起來一起測（下一步細講） |
| JUnit | Java 最常用的測試框架，提供 @Test 等標記 |
| Assertion（斷言） | 像 assertEquals(5, result) 這種檢查結果是否符合預期的語句 |
