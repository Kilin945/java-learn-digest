## B9 第 1 篇 · 兩條執行緒兩把鎖：一段跑了就卡死的 code

**題目：deadlock 是什麼？怎麼避免、怎麼查？**（本篇只講「是什麼」，避免在第 2 篇，查在第 3 篇）

### 題目在問什麼

- deadlock（死結）：程式沒報錯、沒當掉，但某幾條執行緒永遠停在原地。
- 要答三件事：①死結是什麼 ②怎麼避免 ③怎麼查。
- 死結不是「慢」，是「永遠不會結束」。

```
輸入：兩條執行緒 T1、T2，兩把鎖 A、B
  T1：先拿 A，再拿 B
  T2：先拿 B，再拿 A
預期輸出（你以為的）：兩條都跑完，印出 done
實際輸出（死結）：什麼都不印，程式也不結束，CPU 幾乎 0%
```

### 解題思路

1. 先有一段會卡死的最小 code，親眼看到它卡住。**（第 1 篇）**
2. 知道死結由哪些條件湊出來，才知道拆哪一個。（第 2 篇講）
3. 實際解法：固定上鎖順序、tryLock 加逾時。（第 2 篇講）
4. 怎麼查：看出誰卡在誰身上。（第 3 篇講）

### 答案

死結就是兩條執行緒各自握著一把鎖，同時又在等對方手上的那一把，誰都不肯先放，所以永遠等下去。

```java
public class DeadlockDemo {
    static final Object lockA = new Object();
    static final Object lockB = new Object();

    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            synchronized (lockA) {          // ① T1 拿到 A
                pause(100);                 // 讓 T2 有時間拿 B
                synchronized (lockB) {      // ③ 要 B，但 B 在 T2 手上，等
                    System.out.println("T1 done");
                }
            }
        }, "T1");

        Thread t2 = new Thread(() -> {
            synchronized (lockB) {          // ② T2 拿到 B
                pause(100);
                synchronized (lockA) {      // ④ 要 A，但 A 在 T1 手上，等
                    System.out.println("T2 done");
                }
            }
        }, "T2");

        t1.start();
        t2.start();
    }

    static void pause(long ms) {
        try { Thread.sleep(ms); } catch (InterruptedException e) { }
    }
}
```

### 第 1 輪 · 釐清：synchronized 的「握著鎖」「等鎖」到底是什麼狀態？

```
每個 Java 物件身上都有一個「目前是誰握著我」的欄位（簡化示意）

synchronized (lockA) { ... }：
  - 持有者是空   → 把自己填進去，進入大括號（握著鎖）
  - 持有者是別人 → 停住排隊（等鎖，狀態 BLOCKED）
  - 走出大括號   → 持有者清空（放鎖）

只有走出大括號才會放鎖。T1 卡在要 lockB 時，仍握著 A。
最終：lockA 持有者 T1、T2 排隊；lockB 持有者 T2、T1 排隊 → 繞成一圈
```

### 第 2 輪 · 挑戰假設：一定會卡死嗎？把 pause(100) 拿掉會怎樣？

```
情況一：T1 跑得快，在 T2 開始前把兩把鎖拿完又放掉 → 正常結束
情況二：兩條交錯，各拿到一把 → 死結

pause(100) 是把情況二變成每次都發生，方便重現。
拿掉後多數時候走情況一，所以真實專案的死結常是「平常沒事，尖峰流量才卡死」。
```

### 第 3 輪 · 連結經驗：叢集節點不同步、快取廣播清除的場景裡，死結長什麼樣？

```java
// 典型寫法（簡化），不是原始碼
void clearCache() {
    synchronized (cacheLock) {
        cache.clear();
        synchronized (nodeListLock) { broadcastClear(); }
    }
}

void onNodeChanged() {
    synchronized (nodeListLock) {
        refreshNodes();
        synchronized (cacheLock) { cache.clear(); }
    }
}
// 兩個方法拿鎖順序相反，與 T1/T2 同形。同時被觸發就會死結。
// thread dump 裡會看到 BLOCKED 的執行緒互相等鎖（第 3 篇講怎麼讀）。
```

### 為什麼要懂

線上服務一部分請求沒回應、CPU 與記憶體正常、也沒有錯誤 log 時，若不知道「執行緒互相等鎖」，會一直往網路、資料庫找原因。知道死結長什麼樣，才會想到去看執行緒狀態。

### 結論

死結 = 兩條以上執行緒各握一把鎖、又都在等對方那把，繞成一圈永遠停住；它靠時間點湊巧才發生，所以測試常測不出來。

### 術語表

| 術語 | 白話定義 |
|---|---|
| deadlock 死結 | 兩條以上執行緒互相等對方手上的鎖，永遠等下去 |
| 執行緒 thread | 程式裡同時在跑的一條工作線 |
| 鎖 lock | 一次只准一條執行緒進入的門；synchronized 用物件當鎖 |
| BLOCKED | 想進 synchronized 但鎖被握著，正在排隊的狀態 |
| thread dump | 把 JVM 裡所有執行緒當下狀態拍成快照 |
