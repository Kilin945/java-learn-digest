## A3 第 1 篇 · Bean 生命週期：建構 → 注入 → @PostConstruct → @PreDestroy

**題目**：Bean 生命週期與 scope？singleton 預設代表什麼？（本篇只講生命週期，scope 見第 2 篇）

### 題目在問什麼
- Bean：交給 Spring 容器管理的物件；容器是 Spring 內部建立、保存、銷毀 Bean 的管理者。
- 生命週期：Bean 從建出來到被丟掉，依序經過的階段。
- 要答完：階段順序、每階段做什麼、ErrorCodeService 啟動自檢落在哪個階段。

```
建構 → 注入 → @PostConstruct → 可以使用 → @PreDestroy
```

### 解題思路
1. **先排出階段順序：建構、注入、初始化、銷毀。（本篇）**
2. **看懂注入在初始化之前，所以需要依賴的初始化放注入之後。（本篇）**
3. scope 與 singleton 預設代表什麼。（第 2 篇）
4. 串回 ErrorCodeService：自檢落在初始化階段，只跑一次。（本篇講落點，完整原因第 2 篇）

### 答案
Spring 啟動時先建構、再注入、再呼叫 @PostConstruct，之後 Bean 才算可用；容器關閉時呼叫 @PreDestroy 做清理。

```java
// 典型寫法（簡化）
@Service
public class DemoService {
    private final Helper helper;

    // 階段 1：建構。建構子注入時，依賴從參數進來，建構與注入是同一步；
    // 欄位注入則是建構完才另外塞值。
    public DemoService(Helper helper) {
        this.helper = helper;
        System.out.println("1 建構");
    }

    // 階段 3：依賴到齊後，Spring 呼叫一次
    @PostConstruct
    public void init() {
        System.out.println("3 初始化，helper = " + helper);
    }

    // 階段 4：容器關閉前呼叫一次，放掉連線、關執行緒池
    @PreDestroy
    public void close() {
        System.out.println("4 銷毀");
    }
}
// 啟動印：1 建構 → 3 初始化；關閉印：4 銷毀
// Spring Boot 3 用 jakarta.annotation，Boot 2 用 javax.annotation
```

### 第 1 輪 · 釐清：@PostConstruct 到底是什麼？是誰在什麼時候呼叫它？
它只是標記，真正呼叫的是 Spring：Bean 建好、依賴注入完之後，用反射呼叫一次。

```java
// 簡化示意（非 Spring 原始碼）
@PostConstruct          // 貼標記：依賴到齊後，請叫我一次
public void init() {    // 不能有參數，通常回傳 void
    // 可以放心使用已注入的依賴
}
// 不需要、也不應該自己呼叫 init()
```

### 第 2 輪 · 反事實：如果沒有 @PostConstruct，把初始化寫在建構子裡會壞在哪？

```java
// 典型寫法（簡化）：欄位注入 + 建構子初始化 → 壞掉
@Service
public class CodeLoader {
    @Autowired
    private CodeRepo repo;      // 建構完才由 Spring 塞值

    public CodeLoader() {
        repo.findAll();         // NullPointerException：repo 還是 null
    }
}

// 改成 @PostConstruct：時間點在注入之後
@PostConstruct
public void init() {
    repo.findAll();             // OK
}
// 即使建構子注入拿得到依賴，習慣上仍把建物件與做事分開：
// 建構子只存依賴，初始化工作放 @PostConstruct。
```

### 第 3 輪 · 連結經驗：我的 ErrorCodeService 啟動自檢，在生命週期裡長什麼樣子？為什麼只跑一次？

```java
// 典型寫法（簡化），不是 ErrorCodeService 的實際內容
@Service
public class ErrorCodeService {

    // 假設自檢寫在初始化階段：
    // 生命週期是每個 Bean 物件各走一遍；
    // singleton 整個容器只有一個物件 → 只出生一次 → @PostConstruct 只呼叫一次。
    @PostConstruct
    void selfCheck() {
        // 檢查錯誤碼資料是否齊全；有問題丟例外，啟動就失敗
    }

    // 請求呼叫的是一般方法，不會再走生命週期
    public String find(String code) {
        return null; // 略
    }
}
```

### 為什麼要懂
服務啟動失敗、log 出現 BeanCreationException 時，要能判斷錯在建構子、注入、還是 @PostConstruct。連線池、執行緒池要在 @PreDestroy 放掉，否則重新部署會留下殘留資源。

### 結論
Bean 依序經過建構、注入、@PostConstruct、使用、@PreDestroy；初始化放 @PostConstruct，清理放 @PreDestroy。ErrorCodeService 的啟動自檢只跑一次，是因為只有一個物件、生命週期只走一遍。

### 術語表
| 術語 | 白話定義 |
|---|---|
| Bean | 交給 Spring 容器建立並管理的物件 |
| 容器 | Spring 內部負責建立、保存、銷毀 Bean 的管理者 |
| 注入 | 由 Spring 把物件需要的其他物件塞給它，不用自己 new |
| 生命週期 | 物件從建出來到被丟掉依序經過的階段 |
| @PostConstruct | 依賴注入完成後，請 Spring 呼叫一次的方法標記 |
| @PreDestroy | 容器關閉、物件被丟掉前，請 Spring 呼叫一次的方法標記 |
| 反射 | 執行時才去找類別裡的方法並呼叫的機制 |
