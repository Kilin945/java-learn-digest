## B2 第 2 篇 · serialVersionUID、transient；Redis session 改版後讀不回來、權限欄位掉了

**題目：Java 序列化是什麼？哪裡會炸？**

### 題目在問什麼
- 本篇只看 serialVersionUID（類別的版本號）和 transient（這個欄位不要存）。
- 要答到：① 兩者各是什麼 ② 沒處理好會怎樣 ③ 為什麼 Redis session 改版後讀不回來、權限欄位掉了。
- 「讀不回來」有兩種：丟例外，或不報錯但值悄悄變預設值。

### 解題思路
1. 存與讀可能是不同版本的程式，所以先看 JVM 怎麼判斷位元組是不是這個類別寫的：serialVersionUID。
2. 版本號對不上會丟例外；再看不寫與固定版本號各會怎樣。
3. 有些欄位不該存，用 transient 排除。
4. 接回 Redis session 案例，解釋 superAdmin 為什麼掉。

### 答案
serialVersionUID 是類別版本號，存時寫進位元組，讀時和現在的類別比對，不同就丟 InvalidClassException。transient 欄位不寫進位元組，讀回來是預設值（null、0、false）。

```java
// 典型寫法（簡化）
public class LoginUser implements Serializable {
    private static final long serialVersionUID = 1L;
    private String account;           // 會被存
    private boolean superAdmin;       // 會被存
    private transient Thread worker;  // 不存，讀回來是 null
}
```

### 第 1 輪 · 釐清：serialVersionUID 到底是什麼？

```java
out.writeObject(user);
// 位元組裡記：類別名、版本號、欄位名稱與型別、欄位的值
// 讀的時候先比版本號：位元組裡的 vs 現在程式裡的
//   相同 → 繼續讀；不同 → 立刻丟例外，一個欄位都不讀
// java.io.InvalidClassException: LoginUser; local class incompatible:
//     stream classdesc serialVersionUID = 1, local class serialVersionUID = 2
LoginUser u = (LoginUser) in.readObject();
```

### 第 2 輪 · 反事實：沒寫 serialVersionUID，改版會壞在哪？

```java
// 沒寫 → 編譯器依類別結構（類別名、介面、欄位、非 private 方法…）算雜湊
// 舊版算出 A 號，存進 Redis 的就是 A
public class LoginUser implements Serializable {
    private String account;
    private boolean superAdmin;
    public boolean isVip() { return false; }   // 只加一個方法
}
// 新版算出 B 號，A 不等於 B
// 部署後舊 session 全部 InvalidClassException
// 解法：自己寫 serialVersionUID = 1L 並固定
```

### 第 3 輪 · 連結經驗：Redis session 的 superAdmin 權限遺失，code 裡長什麼樣？

以下為典型寫法（簡化），用來解釋症狀，不是原專案原始碼。

```java
// 情況 A：版本號固定為 1L，之後新增 superAdmin 欄位
//   舊位元組沒有這個欄位 → 版本號相同不丟例外
//   → 新欄位拿預設值 false → session 讀得回來但權限沒了

// 情況 B：欄位被標 transient
private transient boolean superAdmin;   // 存的時候就沒寫，讀回來一律 false

// 共通點：沒有例外，只有值變預設，比直接炸更難發現
// 分辨：看欄位有沒有 transient；看欄位是不是改版後才新增
```

### 追問：transient 是做什麼的？serialVersionUID 不一致會怎樣？

```java
// transient：不序列化，讀回來是預設值
// 適用：存不下來的（Connection、Thread）、不該落地的（密碼明文）
private transient Connection conn;
private transient String rawPassword;

private void readObject(ObjectInputStream in)
        throws IOException, ClassNotFoundException {
    in.defaultReadObject();   // 先讀非 transient 欄位
    this.conn = reopen();     // reopen() 為假設的方法，自行重建連線
}

// serialVersionUID 不一致 → InvalidClassException
// 不自己寫 → 編譯器依結構算，結構一變就變 → 改版後舊資料讀不回來
// 補充：版本號相同但欄位型別被換掉（int 改 String）也會丟 InvalidClassException
```

### 為什麼要懂
部署新版後 Redis 舊 session 讀不回來，使用者被登出或權限不對。不懂就只會清 Redis，下次改版再發生，也分不出整包炸掉與悄悄變預設值要往哪查。

### 結論
要存進 Redis 或檔案的類別，自己固定 serialVersionUID，不該存的欄位標 transient。改版時要想：舊資料會不會整包炸，或新欄位會不會悄悄變預設值。

官方文件：https://docs.oracle.com/en/java/javase/17/docs/specs/serialization/version.html

### 術語表
| 術語 | 白話定義 |
|---|---|
| serialVersionUID | 類別的版本號（long），存時寫進位元組，讀時比對 |
| transient | 欄位修飾詞，序列化時跳過該欄位 |
| InvalidClassException | 位元組與現在的類別對不上時丟的例外 |
| 預設值 | 物件 null、數字 0、boolean false |
| Redis session | 把登入狀態物件序列化後存在 Redis，多台伺服器共用 |
