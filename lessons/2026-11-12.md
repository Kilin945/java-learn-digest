## B4 第 2 篇 · OOM 常見成因：靜態 Map 忘了清、沒上限的快取、沒關的串流

**題目：JVM 記憶體區與 OOM 常見成因？**

### 題目在問什麼
- OOM = OutOfMemoryError，JVM 要不到記憶體時丟出。
- 成因要答：heap 為什麼會滿，多半是該回收的被抓著不放。
- 要答到：GC 為什麼收不掉，以及三種常見寫法。
- 查法留給第 3 篇，記憶體區留給第 1 篇。

```java
// 輸入（現象）：系統跑幾天後 heap 只升不降，最後 OutOfMemoryError: Java heap space
// 輸出：1. GC 為什麼沒收？ 2. 最常見的三種寫法？
```

### 解題思路
1. 先看錯誤訊息確認是哪一區爆（第 1 篇）。
2. 搞懂 GC 怎麼判斷能不能收。（本篇）
3. 列出三種抓著不放的寫法。（本篇）
4. 怎麼查（第 3 篇）。

### 答案
三種寫法的共同點：有參照鏈從永遠活著的東西連到物件，GC 不敢收。放進去沒人拿出來，或沒有上限，heap 就只增不減。

```java
// 簡化示意
public class Leaky {
    static Map<Long, Object> SESSIONS = new HashMap<>();      // ① 靜態 Map，只 put 不 remove
    Map<String, Object> cache = new ConcurrentHashMap<>();    // ② 沒上限的快取
    void read(Path p) throws IOException {
        InputStream in = Files.newInputStream(p);             // ③ 沒 close
    }
}
```

### 第 1 輪 · 釐清：GC 到底怎麼判斷一個物件能不能收？
GC 從 GC Root 出發沿參照走，走得到的留下，走不到的才回收。

```java
class Holder {
    static List<byte[]> LEAK = new ArrayList<>();  // static 欄位 = GC Root
    static void handle() {
        byte[] data = new byte[1_000_000];
        LEAK.add(data);   // 方法結束後 stack 上的 data 消失，但 LEAK 還指著它 → 不回收
    }
}
```

### 第 2 輪 · 追原因：為什麼沒上限的快取會撐爆 heap？
普通 Map 只管存不管丟；快取常掛在單例上，從 Root 走得到。

```java
private final Map<String, Object> cache = new HashMap<>();
Object get(String key) { return cache.computeIfAbsent(key, k -> load(k)); }  // 無上限

class Lru<K, V> extends LinkedHashMap<K, V> {
    Lru() { super(16, 0.75f, true); }
    protected boolean removeEldestEntry(Map.Entry<K, V> e) { return size() > 1000; }
}

Cache<String, Object> c = Caffeine.newBuilder()
        .maximumSize(10_000)
        .expireAfterWrite(10, TimeUnit.MINUTES)
        .build();
```

### 第 3 輪 · 挑戰假設：串流沒 close 一定沒事嗎？
不一定。串流底下的檔案或連線要靠 close 才釋放；連線池的連線不還會被借光；被池或框架持有的緩衝區會留在 heap。

```java
void bad(Path p) throws IOException {
    InputStream in = Files.newInputStream(p);
    process(in);   // 丟例外就走不到下一行
    in.close();
}
void good(Path p) throws IOException {
    try (InputStream in = Files.newInputStream(p)) {
        process(in);
    }
}
```

### 為什麼要懂
正式機 heap 一路漲到 OOM、重啟後又漲回去時，要判斷是真的不夠還是被抓著。看 heap dump 佔最多的通常是 static Map、快取或沒還的連線與串流。

### 結論
heap OOM 多半是 static Map 忘了清、快取沒上限、串流或連線沒關。對策：能清的要清、快取設上限或過期、資源用 try-with-resources。

深入官方文件：https://docs.oracle.com/en/java/javase/21/troubleshoot/troubleshoot-memory-leaks.html

### 術語表
| 術語 | 定義 |
|---|---|
| OOM | OutOfMemoryError，JVM 要不到記憶體時丟出的錯誤 |
| GC Root | GC 找活物件的起點，例如 static 欄位、stack 上的區域變數 |
| 參照鏈 | A 指 B、B 指 C 一路連下去，從 Root 走得到就不會被回收 |
| LRU | 快取滿了就丟最久沒用到的 |
| try-with-resources | try 括號宣告資源，離開區塊自動 close() |
| 連線池 | 預先開好的連線供借用，用完要還 |
