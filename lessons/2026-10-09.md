## Spring Security 入門：認證與授權概念 · 第 5 步

### Authorization Rules: Roles & hasRole()

認證（你是誰）完成後，授權決定「你能做什麼」。比喻：門禁卡上的部門標籤決定你能進哪一層樓，這個標籤就是 **Role（角色）**。

做法：
1. 在使用者身上貼角色：`.roles("ADMIN")`
2. 在 `SecurityFilterChain` 規定路徑需要的角色：`.hasRole("ADMIN")`

```java
UserDetails amy = User.withUsername("amy")
    .password(encodedPassword)
    .roles("USER")
    .build();

@Bean
SecurityFilterChain chain(HttpSecurity http) throws Exception {
    http.authorizeHttpRequests(auth -> auth
        .requestMatchers("/public/**").permitAll()
        .requestMatchers("/admin/**").hasRole("ADMIN")
        .anyRequest().authenticated());
    return http.build();
}
```

amy 登入後：`/public/hello` → 200、`/orders` → 200、`/admin/users` → 403（已登入但角色不夠）。

### 注意事項
- 規則由上往下比對，第一條符合就停；範圍小的放前面，`anyRequest()` 放最後。
- Spring 內部把角色存成 `ROLE_ADMIN`，使用 `roles()` / `hasRole()` 時不用自己加 `ROLE_`。

### 術語表
| 術語 | 中文 | 定義 |
|---|---|---|
| Role | 角色 | 貼在使用者身上的身分標籤，決定權限範圍 |
| hasRole() | 要求角色 | 該路徑只有擁有指定角色者可進 |
| requestMatchers() | 路徑比對 | 指定哪些網址套用後面的規則 |
| anyRequest() | 其餘所有請求 | 前面都沒比對到的請求，必須放最後 |
| ROLE_ prefix | 角色前綴 | Spring 內部自動加的 ROLE_ 開頭 |
