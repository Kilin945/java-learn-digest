## Spring Data JPA 與 Repository 介面 · 第 2 步

### 概念：Query Methods（查詢方法）

昨天學到 Repository 介面繼承 `JpaRepository` 後，`save()`、`findById()`、`delete()` 等基本 CRUD 方法會自動被實作出來。今天進一步學到：只要照著固定的命名規則取方法名字，Spring Data JPA 也能自動幫你產生「客製化查詢」的 SQL，完全不用寫任何實作邏輯。

比喻：就像在快餐店跟櫃檯說「一號餐不要辣」，廚房自己知道怎麼做，不需要你寫食譜——只要用固定格式講出需求即可。

### 程式碼範例

```java
public interface UserRepository extends JpaRepository<User, Long> {

    // findBy + 欄位名 Email → SELECT * FROM user WHERE email = ?
    User findByEmail(String email);

    // Containing → 模糊比對，相當於 SQL 的 LIKE '%關鍵字%'
    List<User> findByNameContaining(String keyword);

}
```

這個介面沒有任何方法實作，Spring Data JPA 在程式啟動時會解析方法名稱的規則，自動生成對應的實作。

### 術語表

| 術語 | 定義 |
|---|---|
| Query Method（查詢方法） | 依照特定命名規則寫的方法，Spring Data JPA 會自動解析並產生對應的 SQL，不需要自己實作 |
| findBy...（依欄位查詢） | 方法名稱的固定前綴，後面接欄位名稱，代表「找出這個欄位等於某值的資料」 |
| Containing（模糊比對） | 加在欄位名稱後的關鍵字，代表「包含某字串」，等同 SQL 的 LIKE '%關鍵字%' |
