## 路徑參數、查詢參數、@RequestBody · 第 3 步

### 概念
前兩步學了 `@PathVariable`（抓網址路徑裡的變動值，如 `/users/{id}`）跟 `@RequestParam`（抓網址 `?` 後面的 key=value）。這兩者都只適合傳「一兩個小值」。

當資料變複雜（例如新增使用者要傳姓名、Email 等多個欄位），前端會把資料包成一份 **JSON**（用 `key: value` 描述資料的文字格式）放進 HTTP 請求的 **body（請求主體）**。後端方法參數貼上 `@RequestBody`，Spring 就會自動把這包 JSON 轉換成指定的 Java 物件（通常是一個只有欄位跟 getter/setter 的 **DTO，資料傳輸物件**），欄位名稱對上 JSON 的 key 就自動填值。

至此，接收資料的三種方式都學完了：
- `@PathVariable`：抓路徑上的值
- `@RequestParam`：抓查詢字串的值
- `@RequestBody`：抓請求主體裡一整包 JSON

### 程式碼
```java
// 先定義一個「裝資料用」的類別（DTO）
public class UserCreateRequest {
    private String name;
    private String email;
    // 這裡省略 getter / setter
}

@PostMapping("/users")
public String createUser(@RequestBody UserCreateRequest request) {
    return "建立使用者：" + request.getName();
}

// 前端送出：
// POST /users
// Body: {"name": "小明", "email": "ming@test.com"}
//
// Spring 自動把上面那包 JSON 轉成 UserCreateRequest 物件，
// request.getName() 就會拿到 "小明"
```

### 術語表
| 術語 | 定義 |
|---|---|
| @RequestBody | 告訴 Spring：把這次 HTTP 請求 body 裡的 JSON，自動轉成我指定的 Java 物件。 |
| JSON | 一種用 `{"key": "value"}` 描述資料的純文字格式，前後端最常用來互傳資料。 |
| DTO（資料傳輸物件） | 專門用來裝資料的簡單類別，通常只有欄位加 getter/setter，本身不含商業邏輯。 |
| Request Body（請求主體） | HTTP 請求裡放實際資料內容的部分，跟放在網址上的路徑/查詢參數是不同位置。 |
