## Spring Data JPA 與 Repository 介面 · 第 3 步

### 概念：@Query 與 JPQL

方法名稱自動查詢（如 `findByEmail`）方便，但條件一複雜，方法名稱就會變得又長又難維護，甚至寫不出來（例如多表關聯、動態排序）。這時改用 `@Query` 註解，搭配 **JPQL**（Java Persistence Query Language）自己撰寫查詢邏輯。JPQL 語法類似 SQL，但操作對象是 Entity（Java 物件），不是資料表。

### 範例程式碼

```java
public interface UserRepository extends JpaRepository<User, Long> {

    // 手動寫查詢：找出信箱相符、且帳號是啟用狀態的使用者
    @Query("SELECT u FROM User u WHERE u.email = :email AND u.active = true")
    Optional<User> findActiveUserByEmail(@Param("email") String email);

}
```

- `:email` 是佔位符，對應方法參數上的 `@Param("email")`，Spring 會安全地把值填進去（避免 SQL Injection）。
- 回傳值包成 `Optional<User>`，代表「可能找得到、也可能找不到」，逼呼叫端明確處理找不到的情況。

### 術語表

| 術語 | 定義 |
|---|---|
| JPQL | 類似 SQL，但查詢對象是 Entity 物件而非資料表 |
| @Query | 貼在 Repository 方法上，自訂 JPQL 查詢內容 |
| @Param | 把方法參數綁定到 JPQL 裡的 `:` 佔位符 |
| Optional | 表示「可能有值也可能沒有」的容器，強迫處理空值情況 |

### 昨日複習重點

Spring Data JPA 可以用方法名稱（例如 findByEmail、findByNameContaining）自動產生查詢，不需要自己寫 SQL 或實作邏輯。
