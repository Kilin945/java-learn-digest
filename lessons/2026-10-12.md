## Spring Security 入門：認證與授權概念 · 第 8 步

### Stateless REST API: CSRF off + STATELESS session

**問題**：Spring Security 預設為傳統網站設計（session + cookie + CSRF 保護），純 REST API 一開 Security，POST／PUT／DELETE 常常明明帳密正確卻回 403。

**兩個重點**

1. **Session vs Stateless**：預設登入後伺服器建立 session，靠 cookie 認人。REST API 通常每次請求自己帶身分，伺服器不記人，用 `SessionCreationPolicy.STATELESS`。
2. **CSRF**：壞網站借用瀏覽器自動帶的 cookie 冒充使用者送請求。Spring 預設要求 POST／PUT／DELETE 帶 CSRF token，沒帶就 403。若 API 不靠 cookie 認人，攻擊前提不成立，可以關閉。

```java
@Bean
SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .csrf(csrf -> csrf.disable())
        .sessionManagement(s -> s
            .sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .httpBasic(Customizer.withDefaults())
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/api/public/**").permitAll()
            .requestMatchers("/api/admin/**").hasRole("ADMIN")
            .anyRequest().authenticated());
    return http.build();
}
```

**注意**：有網頁表單、靠 cookie 登入的網站不要關 CSRF，此設定只適用 stateless API。

**一句話**：REST API 要 stateless，就關 CSRF 並設 STATELESS；否則帳密正確的寫入請求也會被 CSRF 擋成 403。

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Session | 工作階段 | 伺服器替登入者記住狀態，瀏覽器靠 cookie 編號對應 |
| Stateless | 無狀態 | 伺服器不記人，每次請求自帶身分 |
| CSRF | 跨站請求偽造 | 借用瀏覽器自動帶的 cookie 冒充使用者的攻擊 |
| HTTP Basic | 基本認證 | 帳密放在 Authorization 標頭的最簡單登入方式 |

官方文件：https://docs.spring.io/spring-security/reference/features/exploits/csrf.html
