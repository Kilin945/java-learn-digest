## A1 · IoC / DI 是什麼？好處是什麼？

### 第 0 輪 · 題目與答案

**❓ IoC / DI 是什麼？好處是什麼？**

**✅** IoC（Inversion of Control，控制反轉）是說物件要怎麼建立、怎麼組裝，不由自己 `new`，交給 Spring 容器處理。DI（Dependency Injection，依賴注入）是做法：容器建好物件後，把它需要的其他物件塞進去。好處：解耦（換實作不動業務碼）、可測試（可以塞 mock）。

**你在哪裡碰過：** 專案裡 Service 上的 `@Autowired`、建構子注入，以及 anki-forge 的 configurable service bean。

### 第 1 輪 · 生活比喻

**❓ 「控制」是誰的控制？為什麼叫「反轉」？**

**✅** 自己煮飯是自己買菜、備料、開火，等於自己 new。IoC 像去餐廳，你只說要什麼，廚房負責備料和組裝。「控制」指建立並組裝依賴物件的權力，原本在你的程式手上，現在交給容器，所以叫反轉。

### 第 2 輪 · 程式碼（壞寫法 vs 好寫法）

**❓ 自己 new 有什麼不好？**

**✅** 自己 new 會讓類別和具體實作耦合，換實作要改業務碼，測試時也沒辦法替換成假的。改成從建構子傳入依賴，正式環境由 Spring 傳，測試時自己傳假的。

```java
// 壞：自己 new，實作寫死在裡面
public class OrderService {
    private final PaymentClient client = new StripeClient();
}

// 好：依賴從建構子傳進來
@Service
public class OrderService {
    private final PaymentClient client;

    public OrderService(PaymentClient client) {
        this.client = client;
    }
}

// 測試：不需要 Spring，自己 new 一個，塞假的
OrderService service = new OrderService(new FakePaymentClient());
```

類別只有一個建構子時，Spring 4.3 之後不必寫 `@Autowired`。

### 第 3 輪 · 圖解式流程

**❓ 容器怎麼知道要建哪些物件、塞什麼進去？**

**✅**
1. 掃描：找出 `@Service`、`@Component`、`@Repository`、`@Controller`，以及 `@Bean` 方法。
2. 登記：每個類別記成一份「食譜」，內容是類別與依賴。
3. 排順序：看建構子參數，A 需要 B 就先建 B。
4. 建立並注入：建好 B，傳進 A 的建構子，建出 A。
5. 收進容器：建好的物件叫 Bean，預設每種只建一個、共用。

### 第 4 輪 · 對照你自己的 code

**❓ 這些東西在我平常看到的 code 裡長什麼樣？**

**✅** 你在專案裡看得到的 Service 上的 `@Autowired` 或建構子注入就是 DI：Service 需要別的物件卻沒有 new，物件由容器啟動時建好再塞進來。anki-forge 的 configurable service bean 是同一個機制：由容器建立並放進箱子，其他類別在建構子宣告需要它，容器就傳同一個實例。要換設定或實作，改 bean 宣告，用到它的業務碼不用動。

### 第 5 輪 · 常見誤解

**❓ IoC 和 DI 是同一個東西嗎？寫了 `@Autowired` 就是 IoC 嗎？**

**✅** IoC 是設計原則（建立與組裝的控制權交出去），DI 是實現它的一種具體做法（容器把依賴傳進來）。`@Autowired` 只是標記「這裡要注入」，真正的 IoC 是整個容器替你建物件、組物件、管生命週期的機制。

### 第 6 輪 · 🪤 面試追問

**❓ 欄位注入為什麼被 IDE 警告？**

**✅** 因為依賴被藏在欄位裡：從建構子看不出類別到底需要什麼才能動，測試也沒辦法自己 new 一個出來塞假物件，一定得靠容器。建構子注入把依賴寫在簽章上，還能宣告 `final`。完整版見 A2。

```java
// 欄位注入：依賴藏起來，只能靠容器塞
@Autowired
private PaymentClient client;

// 建構子注入：寫在簽章上，可以 final
private final PaymentClient client;
public OrderService(PaymentClient client) { this.client = client; }
```

### 🥡 今日一句話帶走

不要自己 new 依賴，把建立和組裝交給容器；你只宣告需要什麼，容器建好傳進來，換實作、塞假物件都不用動業務碼。

### 📖 術語表

| 術語 | 中文 | 白話定義 |
|---|---|---|
| IoC | 控制反轉 | 設計原則：物件的建立與組裝由容器負責，不是自己 new |
| DI | 依賴注入 | 實現 IoC 的做法：容器把類別需要的依賴傳進來 |
| Container | 容器 | Spring 裡負責建立、組裝、保管物件的大箱子（ApplicationContext） |
| Bean | 容器管理的物件 | 由容器建立並管理，預設每種只有一個、共用 |
| Coupling | 耦合 | 兩個類別綁得多緊，越緊越容易連動壞 |
| Constructor injection | 建構子注入 | 依賴寫成建構子參數，由容器建物件時傳入 |
| Mock | 假物件 | 測試時頂替真實依賴，不會連外部系統 |
