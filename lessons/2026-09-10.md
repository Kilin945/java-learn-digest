## 單元測試 vs @SpringBootTest 整合測試 · 第 2 步

### 概念
- Unit test（單元測試）只測一個方法或 class 本身的邏輯，不啟動 Spring，不碰資料庫、網路等外部資源，所以很快。
- Integration test（整合測試）要測的是「多個元件組合起來能不能一起運作」，因此會真的啟動 Spring context（Spring 容器），把所有 bean（元件）建立起來、兜在一起跑跑看。
- 比喻：unit test 是檢查一顆螺絲有沒有壞；integration test 是把整台機器組起來，啟動看看能不能動。
- `@SpringBootTest` 這個 annotation（標記）加在測試 class 上，就會讓這個測試真的啟動一個 Spring Boot 應用程式。
- 最陽春的整合測試（`contextLoads()`）裡什麼斷言都沒寫，價值在於：只要應用程式能成功啟動，就代表所有元件兜得起來；如果某個 bean 缺依賴，這個測試會直接失敗。
- 代價：因為要真的啟動整個應用程式（建立所有 bean，甚至連資料庫），integration test 通常比 unit test 慢很多。

### 程式碼
```java
@SpringBootTest
class DemoApplicationTests {

    @Test
    void contextLoads() {
        // 這裡什麼都沒寫
        // 但如果 Spring context 啟動失敗（例如某個 bean 少了依賴），
        // 這個測試就會直接失敗
    }

}
```

### 術語表
| 術語 | 中文 | 定義 |
|---|---|---|
| Integration Test | 整合測試 | 測試多個元件組合起來運作是否正確，通常會真的啟動 Spring 應用程式 |
| Spring Context | Spring 容器 | Spring 啟動時建立、管理所有物件（bean）的空間 |
| Bean | 豆子／元件 | 被 Spring 建立並管理的物件實例 |
| @SpringBootTest | 標記／annotation | 加在測試 class 上，讓測試真的啟動一個 Spring Boot 應用程式來跑 |
