## Logging 與結構化日誌 · 第 6 步

### Never Log Sensitive Data

log 像公司公布欄：很多人看得到、保存很久。密碼、token、信用卡號、身分證字號等敏感資料不能寫進去。結構化 JSON 日誌會讓資料更容易被搜尋與匯出，外洩範圍反而更大。

```java
// ❌ 問題寫法
log.info("login email={}, password={}", email, password);
log.info("pay card={}", cardNo);

// ✅ 修好寫法：記內部編號、必要資料先遮罩
log.info("login userId={}", userId);
log.info("pay card={}", mask(cardNo));

private String mask(String cardNo) {
    return "*".repeat(cardNo.length() - 4)
            + cardNo.substring(cardNo.length() - 4);
}
```

### 三個習慣
1. 能不記就不記：記 userId、orderId 等內部編號即可。
2. 非記不可就遮罩，只留一小段。
3. 小心整個物件：`log.info("req={}", request)` 會呼叫 toString()，可能連密碼欄位一起印出。

### 主題總結
SLF4J Logger 取代 println → log 等級 → 例外傳整個物件 → MDC requestId → 結構化 JSON → 不記敏感資料。

### 術語表
- **Sensitive Data（敏感資料）**：外洩會傷害使用者的資訊。
- **Masking（遮罩）**：以 * 取代大部分內容，只留一小段。
- **Token（令牌）**：登入後系統發的憑證，被拿走可冒充使用者。
- **toString()**：物件被印出時呼叫的方法，可能包含敏感欄位。
