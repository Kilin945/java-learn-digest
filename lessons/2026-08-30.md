## Entity 對應：@Entity / @Id / 關聯 · 第 5 步

### 概念

昨天教的 `@ManyToOne` 是「從多看一」：很多 `Student` 各自指向一位 `Teacher`，外鍵欄位（例如 `teacher_id`）放在 `Student` 表裡。

今天教「從一看多」的反方向：在 `Teacher` 這個 Entity 裡加一個 `List<Student>` 欄位，搭配 `@OneToMany(mappedBy = "teacher")`，讓你可以從一位老師直接拿到他教的所有學生。

關鍵重點：
- `mappedBy` 的值填的是「多」那方類別裡**對應欄位的名稱**（這裡是 `Student` 類別裡的 `teacher` 欄位），不是資料庫欄位名。
- 加了 `@OneToMany(mappedBy=...)` **不會**在資料庫多建欄位，外鍵仍然只存在於「多」那方的表裡，這一邊只是唯讀地借用關聯。
- 兩邊都有對方參考（`Teacher` 有 `List<Student>`，`Student` 有 `Teacher`）就叫做**雙向關聯（bidirectional relationship）**。

### 程式碼

```java
@Entity
public class Teacher {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    @OneToMany(mappedBy = "teacher")
    private List<Student> students;
}

@Entity
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    @ManyToOne
    @JoinColumn(name = "teacher_id")
    private Teacher teacher;
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| @OneToMany | 標記在「一」的那方，對應到另一個 Entity 的多筆資料，欄位型別通常是 List |
| mappedBy | 指向「多」那方類別裡負責維護外鍵的欄位名稱，代表這邊不再多建外鍵 |
| 雙向關聯 (bidirectional) | 兩個 Entity 互相持有對方參考，可從任一邊查到對方 |
| List | 裝一群同類型物件的容器 |

### 本主題小結

到這一步，Entity 對應（@Entity / @Id / 關聯）的基礎已經涵蓋：標記資料表與主鍵、欄位自動對應與命名轉換、主鍵自動遞增、以及雙向的一對多／多對一關聯。之後遇到更進階的關聯型態（如 @ManyToMany、@OneToOne）或延伸設定（cascade、fetch 策略）時，可以再另開新主題深入。
