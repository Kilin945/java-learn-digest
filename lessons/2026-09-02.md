## 衍生查詢 vs @Query · 第 3 步

### 概念：@Query 登場時機

衍生查詢（Derived Query）靠方法名稱的命名規則自動翻譯成 SQL，適合條件少的情況。條件一多（例如 3 個以上欄位用 And/Or 串接），方法名稱會變得又長又難讀，也容易寫錯欄位順序。

這時改用 `@Query` 標註，直接在 Repository 方法上寫 JPQL（Java Persistence Query Language，語法像 SQL，但操作對象是 Entity 和它的欄位，不是資料庫表格），搭配 `@Param` 把方法參數綁定到 JPQL 裡的 `:名稱` 佔位符。

### 程式碼

```java
public interface UserRepository extends JpaRepository<User, Long> {

    // 衍生查詢：條件一多就爆炸
    // List<User> findByUsernameAndStatusAndDeptId(String username, String status, Long deptId);

    // @Query + JPQL：條件多也還算清楚
    @Query("SELECT u FROM User u " +
           "WHERE u.username = :username " +
           "AND u.status = :status " +
           "AND u.deptId = :deptId")
    List<User> searchUsers(@Param("username") String username,
                            @Param("status") String status,
                            @Param("deptId") Long deptId);
}
```

### 術語表

- **@Query**：貼在 Repository 方法上的標註，直接寫查詢語法，不靠方法名稱猜。
- **JPQL**：類似 SQL，但查詢對象是 Java Entity 和其欄位，而非資料庫表格/欄位。
- **@Param**：把方法參數對應到 JPQL 裡同名的 `:名稱` 佔位符。
- **Placeholder（佔位符）**：JPQL 裡如 `:username` 這樣先佔位、之後由參數帶值的寫法。
