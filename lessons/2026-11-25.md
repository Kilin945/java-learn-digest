## A6 第 2 篇 · 參數怎麼變成物件（@RequestBody）、回傳值怎麼變成 JSON

**題目：Spring MVC 一個請求從進到出的流程？**（第 2 篇：參數怎麼變成物件、回傳值怎麼變成 JSON）

### 題目在問什麼

- 只看 Controller 方法被呼叫前後：誰把請求 body 的文字變成物件，誰把回傳物件變成 JSON。
- 要答到：①誰負責轉換 ②@RequestBody／@ResponseBody 各管進或出 ③進出用同一種機制。
- 題目沒講：預設 JSON 套件（Jackson）、Content-Type 的影響。

```java
// 簡化示意（欄位是舉例）
// 輸入：POST /ask  Content-Type: application/json
//   {"question":"今天天氣","userId":"u1"}
// 方法想要：public AskResult ask(AskRequest req)
// 輸出：{"answer":"晴天","score":0.9}
// 進出各缺一次翻譯：文字→物件、物件→文字
```

### 解題思路

1. 先知道請求怎麼進來：DispatcherServlet 查 HandlerMapping（第 1 篇）。
2. **body 是文字、方法要物件 → 找出誰做轉換（本篇：HandlerAdapter 帶訊息轉換器）。**
3. 呼叫我的方法。
4. **回傳是物件、回應要文字 → 誰轉回 JSON，並分辨它和找 JSP 是兩條路（本篇）。**
5. 攔截器、Filter、@ControllerAdvice（第 3 篇）。

### 答案

呼叫方法前，看到參數標 @RequestBody，就找訊息轉換器把 JSON 讀成物件；方法 return 後，看到 @ResponseBody（@RestController 已內含），再找訊息轉換器把物件寫成 JSON。

```java
// 典型寫法（簡化）
@RestController
public class AskController {
    @PostMapping("/ask")
    public AskResult ask(@RequestBody AskRequest req) {
        // 進：JSON → AskRequest
        return new AskResult("晴天", 0.9);
        // 出：物件 → JSON，不找 JSP
    }
}
```

### 第 1 輪 · 釐清：訊息轉換器（HttpMessageConverter）到底是什麼？

```java
// 簡化示意
public interface HttpMessageConverter<T> {
    boolean canRead(Class<?> clazz, MediaType contentType);   // 進：看得懂嗎？
    T read(Class<? extends T> clazz, HttpInputMessage input); // 文字 → 物件
    boolean canWrite(Class<?> clazz, MediaType mediaType);    // 出：寫得出嗎？
    void write(T t, MediaType contentType, HttpOutputMessage output); // 物件 → 文字
}
// Spring 啟動時準備一串轉換器，依序問 canRead / canWrite，第一個說可以的就用
// StringHttpMessageConverter（純文字）、MappingJackson2HttpMessageConverter（JSON，靠 Jackson）
// spring-boot-starter-web 已帶 Jackson，所以不用設定也能轉 JSON
```

### 第 2 輪 · 反事實：沒寫 @RequestBody 或 Content-Type 不對，會壞在哪？

```java
// A：沒標 @RequestBody → 當 @ModelAttribute，從網址參數／表單欄位填 setter
//    JSON body 沒人讀，不報錯，欄位是 null
// B：有標，但 Content-Type 不是 application/json → 沒有轉換器 canRead → 415
// C：有標、格式對，但 JSON 壞掉 → Jackson 解析失敗 → 400（HttpMessageNotReadableException）
// 三種都不會進到 ask()
```

### 第 3 輪 · 連結經驗：qa-ask 那條跟回 JSP 畫面那條差在哪？

```java
// 典型寫法（簡化），非專案原始碼
// 出口 1：回 View 名稱 → ViewResolver → JSP
@Controller
public class PageController {
    @GetMapping("/page")
    public String page(Model model) { return "result"; }
}
// 出口 2：@ResponseBody → 訊息轉換器 → JSON（qa-ask 屬於這類）
@Controller
public class ApiController {
    @ResponseBody
    @PostMapping("/ask")
    public AskResult ask(@RequestBody AskRequest req) { return new AskResult("晴天", 0.9); }
}
// @ResponseBody 方法回 String，會被純文字轉換器直接當文字寫出
// 驗證：DevTools 看回應 Content-Type: application/json
```

### 為什麼要懂

前端說有送資料、後端欄位卻全是 null，或收到 415、400 卻不知道問題在哪。懂了轉換器這關，就知道先查：有沒有標 @RequestBody、Content-Type、JSON 格式。

### 結論

HandlerAdapter 呼叫方法前後各用一次訊息轉換器：@RequestBody 管進、@ResponseBody 管出；有 @ResponseBody 就不找 JSP。

### 術語表

| 術語 | 白話定義 |
|---|---|
| HandlerAdapter | 實際呼叫 Controller 方法的元件，呼叫前先準備參數 |
| HttpMessageConverter | 做 HTTP body 文字與 Java 物件互轉的元件，Spring 有一串，依序問誰接得了 |
| @RequestBody | 標在參數上，從請求 body 讀並轉成物件 |
| @ResponseBody | 標在方法上，回傳值直接轉成文字寫進回應，不當 View 名稱 |
| @RestController | @Controller 加上每個方法都有 @ResponseBody 的簡寫 |
| Jackson | Java 常用 JSON 套件，Spring JSON 轉換器底層用它 |
| Content-Type | HTTP 標頭，說明 body 格式 |
| @ModelAttribute | 沒標註解的物件參數預設處理：從網址參數或表單填欄位，不讀 JSON body |
| ViewResolver | 把 View 名稱對應到實際 JSP 檔的元件 |
