## B9 第 2 篇 · 死結的四個條件；固定上鎖順序、tryLock 逾時來解

**題目**：deadlock 是什麼？怎麼避免、怎麼查？（本篇只講四個條件與兩種解法，查法在第 3 篇）

### 題目在問什麼
- 要回答：死結要哪四個條件同時成立？怎麼打破其中一個？
- 題目沒明講：打破哪一個最划算 → 循環等待（固定上鎖順序）。

### 解題思路
1. 先看會卡死的 code（第 1 篇）
2. **列出四個條件（本篇）**
3. **四個缺一不可，打破一個就夠（本篇）**
4. **拆循環等待：固定順序（本篇）**
5. **順序排不出來：tryLock 逾時（本篇）**
6. 怎麼查：thread dump（第 3 篇）

### 答案
死結要互斥、持有並等待、不可搶奪、循環等待四個條件同時成立；實務上最好拆的是循環等待，做法是所有人照同一個固定順序拿鎖。

```java
// 典型寫法（簡化示意）
void transfer(Account from, Account to, long amt) {
    Account first  = from.id < to.id ? from : to;
    Account second = from.id < to.id ? to : from;
    synchronized (first) {
        synchronized (second) {
            from.balance -= amt;
            to.balance   += amt;
        }
    }
}
// 兩邊都先搶 id 小的，搶輸的手上沒握任何鎖，不會形成圈
```

### 第 1 輪（釐清）：四個條件各是哪一行？
```java
// 典型寫法（簡化示意）：會死結的版本
void transfer(Account from, Account to, long amt) {
    synchronized (from) {      // ① 互斥
        synchronized (to) {    // ② 持有並等待：握著 from 等 to
            ...
        }
    }
}
// ③ 不可搶奪：JVM 不能強拆別人的鎖
// ④ 循環等待：T1 握 A 等 B；T2 握 B 等 A
// 拆①：鎖本來就要互斥，不可行
// 拆③：強拆會留下改一半的資料，不可行
// 拆②：要一次拿齊，需多包一把大鎖，吞吐量差
// 拆④：排序即可，代價最小，最常用
```

### 第 2 輪（比較）：固定順序 vs tryLock 逾時
```java
// 典型寫法（簡化示意）
boolean transfer(Account from, Account to, long amt) throws InterruptedException {
    if (from.lock.tryLock(1, TimeUnit.SECONDS)) {
        try {
            if (to.lock.tryLock(1, TimeUnit.SECONDS)) {
                try {
                    from.balance -= amt;
                    to.balance   += amt;
                    return true;
                } finally { to.lock.unlock(); }
            }
        } finally { from.lock.unlock(); }
    }
    return false; // 逾時：鎖都已放掉，可重試或回報失敗
}
```
- 固定順序：沒有失敗路徑；前提是事先知道要拿哪幾把、能排出順序。
- tryLock：順序排不出來時用；代價是要處理失敗，且同時重試可能活鎖，重試要加隨機等待。
- 逾時放掉已握的鎖，等於打破「持有並等待」。

### 第 3 輪（連結經驗）：叢集廣播清除快取
```java
// 典型寫法（簡化示意）
void clearAndBroadcast() {
    synchronized (localCache) {
        localCache.clear();
        broadcastToPeers();   // 握著鎖呼叫別人 → 可能被回頭呼叫而循環等待
    }
}

// 修法：鎖內只改本地，廣播放鎖外
void clearAndBroadcastSafe() {
    synchronized (localCache) { localCache.clear(); }
    broadcastToPeers();
}
```

### 為什麼要懂
線上服務偶爾整個卡住、CPU 很低、請求全逾時，常是死結且重現不了。知道四個條件，code review 時就知道看：有沒有兩把鎖、拿的順序是否一致、握著鎖時有沒有呼叫外部。

### 結論
死結要四個條件同時成立，拆掉任一個就不會發生。實務最常拆循環等待（固定上鎖順序）；順序排不出來時用 tryLock 加逾時。

### 術語表
| 術語 | 定義 |
|---|---|
| 互斥 | 一把鎖同一時間只能被一條執行緒握著 |
| 持有並等待 | 手上握著一把鎖，還在等另一把 |
| 不可搶奪 | 鎖只能由持有者自己放 |
| 循環等待 | T1 等 T2、T2 等 T1，繞成一圈 |
| tryLock | ReentrantLock 的方法，可指定最多等多久，拿不到回 false |
| 活鎖 | 大家都在重試但一直互撞，永遠做不完 |
