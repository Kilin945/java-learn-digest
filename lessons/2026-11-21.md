## A4 第 2 篇 · 動態代理怎麼包住方法：手寫一個 proxy 示意；@Transactional、@Secured 就是這樣做的

### ⭐ AOP 是什麼？Spring 怎麼實作？

**題目在問什麼**

- 本篇只答後半句「Spring 怎麼實作」，關鍵字是動態代理。
- 代理（proxy）＝長得跟原物件一樣的替身，呼叫者先碰到它。
- 要答完三件事：替身是什麼、替身怎麼包住方法、@Transactional 與 @Secured 怎麼靠它生效。
- 「包住」不是改原本的 class，原 class 一個字都不動。

**解題思路**

1. 原本痛在哪：每個方法重複手寫橫切邏輯（第 1 篇）。
2. **呼叫者不用改 code 就吃到新邏輯，所以中間要有長得一樣的替身。**（本篇）
3. **替身在呼叫真方法的前後插入交易、權限檢查。**（本篇）
4. **不可能為每個 class 手寫替身，所以執行時自動產生；註解只是「請替我包」的標記。**（本篇）

**答案**

Spring 啟動時，替有 @Transactional、@Secured 等註解的 bean 產生替身放進容器；別人注入到的是替身，替身在呼叫真方法的前後做交易或權限檢查。

```java
// 簡化示意：手寫的（靜態）代理
public interface OrderService {
    void placeOrder(String id);
}

public class OrderServiceImpl implements OrderService {
    public void placeOrder(String id) {
        System.out.println("寫入訂單 " + id);   // 只有業務
    }
}

// 替身：實作同一個介面，呼叫者分不出來
public class OrderServiceProxy implements OrderService {
    private final OrderService target;
    public OrderServiceProxy(OrderService target) { this.target = target; }

    public void placeOrder(String id) {
        System.out.println("開交易");
        try {
            target.placeOrder(id);
            System.out.println("commit");
        } catch (RuntimeException e) {
            System.out.println("rollback");
            throw e;
        }
    }
}
// 輸出：開交易 → 寫入訂單 A001 → commit
```

### 第 1 輪 · 釐清：所謂「動態」代理到底動態在哪裡？

手寫版每個 service 都要多寫一個 Proxy 類別；動態＝執行時才自動產生替身類別，處理邏輯只寫一份。

```java
// 典型寫法（簡化）：JDK 動態代理
OrderService target = new OrderServiceImpl();

OrderService proxy = (OrderService) Proxy.newProxyInstance(
    OrderService.class.getClassLoader(),   // 載入執行時產生的類別
    new Class[]{ OrderService.class },     // 替身要實作哪些介面
    (proxyObj, method, args) -> {           // 呼叫替身任何方法都進這裡
        System.out.println("開交易");
        try {
            Object r = method.invoke(target, args); // 反射呼叫真物件同名方法
            System.out.println("commit");
            return r;
        } catch (InvocationTargetException e) {
            System.out.println("rollback");
            throw e.getCause();
        }
    });
// 同一個 lambda 換個 target 就能包別的 service
```

### 第 2 輪 · 連結經驗：我專案裡的 @Transactional、@Secured（Supervisor 角色授權）背後長什麼樣？

註解只是標記，真正的檢查寫在 Spring 產生的替身裡。以下為簡化典型樣貌，角色字串僅為舉例。

```java
// 典型寫法（簡化）
@Service
public class ApprovalService {
    @Secured("ROLE_SUPERVISOR")
    public void approve(Long id) { /* 只有業務 */ }

    @Transactional
    public void save(Long id) { /* 只有業務 */ }
}

// 簡化示意：approve 的替身
public void approve(Long id) {
    if (!currentUser.hasRole("ROLE_SUPERVISOR")) {
        throw new AccessDeniedException("沒有權限");  // 擋下，真方法不會執行
    }
    target.approve(id);
}
// 註解要生效需啟用：@EnableTransactionManagement（Spring Boot 自動開）、
// @EnableMethodSecurity(securedEnabled = true)
```

### 第 3 輪 · 比較：JDK 動態代理和 CGLIB 差在哪？什麼時候用哪個？

差在替身怎麼長得像真物件：一個實作介面，一個繼承類別。Spring Boot 預設走 CGLIB。

```java
// 簡化示意
// JDK 動態代理：替身 implements OrderService → 真物件一定要有介面
//   只能轉成介面型別，轉成 OrderServiceImpl 會 ClassCastException

// CGLIB：替身 extends 真物件的類別 → 沒有介面也行
class OrderServiceImpl$$SpringCGLIB$$0 extends OrderServiceImpl {
    @Override
    public void placeOrder(String id) {
        // 開交易
        super.placeOrder(id);
        // commit
    }
}
// 限制：final 類別不能繼承；final / private 方法不能覆寫 → 包不到
// Spring Boot 預設 proxyTargetClass=true（CGLIB）；
// 想改 JDK 代理：spring.aop.proxy-target-class=false
```

### 追問：proxy 的 self-invocation（同類內部呼叫）為什麼不會觸發切面？（接 A5）

切面是替身在攔，繞過替身就攔不到；同類內部呼叫走的是真物件的 this。

```java
// 典型寫法（簡化）
@Service
public class OrderServiceImpl {
    @Transactional
    public void placeOrder(String id) { }

    public void batch() {
        placeOrder("A");   // 其實是 this.placeOrder("A")，this 是真物件 → 沒開交易
    }
}
// controller → 替身.batch()（沒註解，放行）→ 真物件.batch() → this.placeOrder()（沒經過替身）
// 直接呼叫 orderService.placeOrder() 才會 替身 → 開交易 → 真物件 → commit
// 同理 @Cacheable、@Secured 在內部呼叫也失效。解法見 A5。
```

### 為什麼要懂

某方法標了 @Transactional 卻沒 rollback，或 @Secured 在內部呼叫時沒擋人。不知道註解靠替身生效，會一直盯著註解找問題，其實是呼叫路徑繞過了替身；debug 看到 $$SpringCGLIB$$ 類別名也才知道那就是替身。

### 結論

Spring 用動態代理實作 AOP：替身在呼叫真方法的前後插入交易、權限檢查，@Transactional 與 @Secured 只是「請替我包」的標記。只有經過替身的呼叫才有效，同類內部呼叫會繞過它。

深入官方文件：[Spring Framework：Proxying Mechanisms](https://docs.spring.io/spring-framework/reference/core/aop/proxying.html)

### 📖 術語表

| 術語 | 白話定義 |
|---|---|
| 代理（proxy） | 長得跟原物件一樣的替身，呼叫者先碰到它，它再決定要不要、何時呼叫真物件 |
| 動態代理 | 執行時才自動產生替身類別，不用為每個 class 手寫一個 |
| 橫切邏輯 | 交易、log、權限檢查這類散在很多業務方法裡都要做的事 |
| 反射（reflection） | 執行時用方法名稱去呼叫方法，例如 method.invoke(target, args) |
| JDK 動態代理 | JDK 內建，替身實作介面，真物件必須有介面 |
| CGLIB | 替身用繼承真物件的類別產生，沒有介面也能用，但 final 包不到 |
| self-invocation | 同一類別裡的方法直接呼叫自己的另一個方法，走 this，不經過替身 |
