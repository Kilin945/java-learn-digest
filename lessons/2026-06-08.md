## IoC 與依賴注入：為什麼不要自己 new · 第 3 步

### 概念：@Service, @Repository, @RestController — @Component 的三個分身

Spring 提供三個「語意特化」的 @Component，對應分層架構的各層職責：

| Annotation | 層次 | 餐廳比喻 | 額外功能 |
|---|---|---|---|
| `@RestController` | 控制層 | 外場服務生（接 HTTP 請求） | = @Controller + @ResponseBody |
| `@Service` | 業務邏輯層 | 廚師（處理商業規則） | 無 |
| `@Repository` | 資料存取層 | 倉庫管理員（操作 DB） | Exception translation（例外轉換）|

資料流方向：HTTP 請求 → Controller → Service → Repository

### 程式碼範例

```java
@Repository
public class OrderRepository {
    public String findNameById(Long id) {
        return "薯條"; // 暫時寫死，之後換成真實 DB 查詢
    }
}

@Service
public class OrderService {
    private final OrderRepository orderRepository;

    public OrderService(OrderRepository orderRepository) {
        this.orderRepository = orderRepository;
    }

    public String getSummary(Long id) {
        return "訂單 #" + id + "：" + orderRepository.findNameById(id);
    }
}

@RestController
public class OrderController {
    private final OrderService orderService;

    public OrderController(OrderService orderService) {
        this.orderService = orderService;
    }

    public String getOrder(Long id) {
        return orderService.getSummary(id);
    }
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| @Service | @Component 語意特化，標示業務邏輯 class |
| @Repository | @Component 語意特化，標示資料存取 class；附帶 exception translation |
| @RestController | @Controller + @ResponseBody，接收 HTTP 請求回傳 JSON／文字 |
| Layered architecture（分層架構） | 控制層 → 服務層 → 資料層，各層職責分離，只跟相鄰層溝通 |
| Exception translation（例外轉換） | @Repository 把 DB 底層例外轉成 Spring 統一格式 |

### 一句話重點
@Service、@Repository、@RestController 都是 @Component，只是多了職責標籤，讓分層架構一目瞭然。
