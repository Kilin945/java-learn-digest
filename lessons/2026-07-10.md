## @Value 與 application.properties 讀設定 · 第 4 步

### 概念：Wrap-up，把三個重點合體

這個主題總共學了三件事：

1. 用 `@Value("${key}")` 把 application.properties 裡的值注入到欄位，避免 hardcode。
2. 用 `@Value("${key:預設值}")` 準備備胎值，key 缺失也不會讓開機失敗。
3. `@Value` 只對 Spring 管理的 Bean 有效，自己 `new` 出來的物件欄位會是 `null`，必須用 `@Autowired` 拿 Spring 建立好的物件。

第 4 步把這三塊合成一個完整、可以實際運作的範例。

### 程式碼

```java
// application.properties
app.welcome-message=歡迎使用本系統

@Service   // 交給 Spring 管理，變成 Bean
public class GreetingService {

    @Value("${app.welcome-message:Hello!}")  // 有值就讀、沒值就用預設值
    private String welcomeMessage;

    public String greet() {
        return welcomeMessage;
    }
}

@RestController
public class GreetingController {

    @Autowired  // 一定要用這個拿 Spring 管理的物件
    private GreetingService greetingService;

    @GetMapping("/hello")
    public String hello() {
        return greetingService.greet();
    }
}
```

運作順序：Spring 啟動 → 建立 `GreetingService` 這個 Bean → 注入 `welcomeMessage` → Controller 用 `@Autowired` 拿到這個 Bean → 呼叫 `greet()`。

### 術語表

| 術語 | 定義 |
|---|---|
| Injection（依賴注入） | Spring 自動把值或物件塞進你寫好的欄位。 |
| Externalized Configuration（外部化設定） | 把易變的設定值搬到程式碼外部管理。 |
| Bean（元件物件） | 由 Spring 容器建立、管理生命週期的物件，只有它的 @Value 欄位才會被填值。 |

### 一句話帶走

@Value 要「讀得到值」，前提永遠是這個物件本身得先是一個 Bean。
