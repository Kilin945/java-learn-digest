## @DataJpaTest 等測試切片 · 第 3 步

### 概念：persist() vs persistAndFlush()

`entityManager.persist(user)` 只是把物件放進 **Persistence Context**（持久化上下文，JPA 管理物件狀態的暫存區，可想成「還沒送出的草稿本」），此時 SQL INSERT 還沒真正送到資料庫。

真正把暫存資料寫進資料庫的動作叫 **flush**（沖刷、強制寫入），通常發生在 transaction 結束前，或明確呼叫時。

測試中如果只用 `persist()`，多數情況下因為查詢也走同一個 Persistence Context，JPA 會自動 flush，所以測試看起來還是會過。但這種「自動」不保證每次都發生，尤其要驗證資料庫層級行為（如 unique constraint）時，沒真的 flush 可能導致測試出現 **false positive（假陽性）**——明明有問題卻顯示測試通過。

更保險的寫法：用 `persistAndFlush()`，一次做完「persist + flush」，確保後續查詢的資料是真的存在資料庫裡。

### 程式碼

```java
@Test
void findByEmail_ReturnsUser() {
    // Arrange
    User user = new User("kilin@test.com");
    entityManager.persistAndFlush(user); // 塞資料 + 強制寫入資料庫

    // Act
    User found = userRepository.findByEmail("kilin@test.com");

    // Assert
    assertEquals("kilin@test.com", found.getEmail());
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| Persistence Context 持久化上下文 | JPA 管理物件狀態的暫存區 |
| flush 沖刷、強制寫入 | 把暫存區的 SQL 真正送到資料庫執行 |
| false positive 假陽性 | 測試沒真正驗證到問題，卻顯示通過 |
