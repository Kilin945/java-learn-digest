## MockMvc 測 Controller · 第 6 步

### 概念：用 verify() 驗證 Service 有沒有被正確呼叫

之前學的 `when(...).thenReturn(...)` 只保證「假 Service 被呼叫時要回什麼」，並不保證 Controller 真的有去呼叫它。`verify()` 補上這一塊：檢查某個 mock 物件的方法「有沒有被呼叫過」以及「呼叫時傳的參數是什麼」。

比喻：`when().thenReturn()` 是交代廚房「如果有人點這道菜要端出什麼」；`verify()` 則是走進廚房確認「這道菜真的有被做過，而且用的食材（參數）沒錯」。

寫法上，`verify(...)` 要放在 `mockMvc.perform(...)` **之後**，因為必須等請求真正執行完，Controller 內部呼叫 Service 的動作才會發生，才有東西可以驗證。

```java
@Test
void shouldCallServiceWithCorrectId() throws Exception {
    when(userService.findById(1L))
        .thenReturn(new User(1L, "Kilin"));

    mockMvc.perform(get("/users/1"))
        .andExpect(status().isOk());

    // 確認 findById 真的被叫到，且參數是 1L
    verify(userService).findById(1L);
}
```

若 Controller 根本沒呼叫 `findById`，或呼叫時傳的是別的 id，這行測試就會失敗並清楚指出問題。

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| verify() | 驗證 | 確認某個 mock 物件的方法有沒有被呼叫過、呼叫幾次、傳入的參數是什麼 |
| interaction | 互動 | 「誰呼叫了誰、傳了什麼參數」這件事的統稱，verify() 檢查的就是這個 |

### 小結

到這一步，MockMvc 測 Controller 的核心工具已經齊全：`perform()` 送模擬請求、`andExpect()`/`jsonPath()` 檢查回應、`@MockitoBean` + `when().thenReturn()` 造假資料、POST 帶 JSON body、以及 `verify()` 確認互動。這個主題到此告一段落。
