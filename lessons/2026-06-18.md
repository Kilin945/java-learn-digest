## 建構子注入 vs 欄位注入 vs setter 注入 · 第 2 步

### 概念：Constructor Injection（建構子注入）

建構子注入是 Spring 官方最推薦的 DI 方式。把依賴宣告為 `final` 欄位並透過建構子傳入，確保依賴在物件一誕生就被設定且不可更換。

**生活比喻**：廚師上班第一天公司把所有廚具一次配發齊全，不能途中更換，旁人一眼就看清這位廚師需要什麼工具。

### 程式碼

```java
@Service
public class OrderService {

    // ✅ final：依賴一旦設定就不能被換掉
    private final OrderRepository orderRepository;

    // Spring 4.3+ 唯一建構子 → 不需要寫 @Autowired
    public OrderService(OrderRepository orderRepository) {
        this.orderRepository = orderRepository;
    }

    public void place(Order order) {
        orderRepository.save(order);
    }
}
```

### 優點

| 優點 | 說明 |
|------|------|
| 不可變性 | `final` 確保依賴只設定一次 |
| 測試友善 | `new OrderService(mockRepo)` 直接 new，不需啟動 Spring |
| 明確依賴 | 建構子參數一眼看出這個類別需要什麼 |

### 術語表

| 術語 | 中文 | 白話定義 |
|------|------|----------|
| Constructor Injection | 建構子注入 | 透過建構子參數傳入依賴的 DI 方式 |
| final | 不可變修飾子 | 宣告後欄位只能賦值一次，不能再改 |
| immutable | 不可變的 | 物件建立後狀態不能改變，多執行緒更安全 |
