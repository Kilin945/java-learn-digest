## Logging 與結構化日誌 · 第 3 步

### Logging Exceptions: Pass the Exception Object Last

**重點**：log 錯誤時，把整個例外物件放在最後一個參數，SLF4J 會自動附上完整 stack trace。

**比喻**：只記 `e.getMessage()` 就像警察只抄下「有人受傷」，沒有拍現場照片。stack trace 才是事故現場的足跡。

```java
try {
    orderService.pay(orderId);
} catch (Exception e) {
    // ❌ 問題寫法：只有一句話，看不到出錯的位置
    log.error("付款失敗: {}", e.getMessage());

    // ✅ 修好寫法：例外放最後，會印出完整 stack trace
    log.error("付款失敗 orderId={}", orderId, e);
}
```

- 最後一個參數如果是 Throwable，且沒有對應的 `{}`，會被當成要附上的例外。
- 記錄錯誤通常使用 ERROR 等級。

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Exception | 例外 | 程式執行時出錯所丟出的物件，記錄錯誤原因 |
| Stack trace | 堆疊追蹤 | 錯誤發生時的呼叫路徑清單，含檔案與行號 |
| catch | 捕捉 | 用 try/catch 接住例外，避免程式直接當掉 |
| Placeholder | 佔位符 | 訊息中的 `{}`，會被後面的參數依序取代 |
