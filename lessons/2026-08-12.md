## Bean Validation：@Valid 與 @NotNull · 第 1 步

### 概念

Request DTO 擋住了「不該填的欄位」（如 id、role），但沒擋住「填錯的內容」（如 name 是 null 或空字串）。資料沒驗證，錯誤通常會在後面某段程式碼才爆炸，難以追查根源。

**Bean Validation** 是 Java 的驗證標準，讓你用 annotation（標籤）在 DTO 欄位上宣告規則，Spring Boot 會自動檢查，不合格直接回 400 Bad Request——不用手寫一堆 `if` 判斷。這種「用標籤描述規則」的風格叫**宣告式（declarative）**。

最基本的兩個標籤：
- `@NotNull`：貼在欄位上，代表「這個欄位不能是 null」
- `@Valid`：貼在 controller 方法的參數上，代表「請 Spring 檢查這個物件裡的所有驗證規則」

⚠️ 只貼 `@NotNull` 沒有用，一定要在 controller 參數加 `@Valid`，Spring 才會真的觸發檢查。

### 程式碼

```java
// 1. DTO 欄位上宣告規則
public class CreateUserRequest {

    @NotNull
    private String name;

    private String email;

    // getter / setter 略
}

// 2. controller 參數上加 @Valid，Spring 才會真的去檢查
@PostMapping("/users")
public ResponseEntity<User> createUser(
        @Valid @RequestBody CreateUserRequest request) {

    // 走到這一行，代表 name 一定不是 null
    // 若 name 是 null，Spring 已經自動回 400，這行根本不會執行
    ...
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| Bean Validation | Java 官方定義的一套「用標籤宣告驗證規則」的標準，Spring Boot 內建支援 |
| Annotation（標籤/註解） | 寫在程式碼上方、以 @ 開頭的標記，告訴框架「這裡要怎麼處理」 |
| @NotNull | 貼在欄位上，代表這個欄位絕對不能是 null |
| @Valid | 貼在 controller 方法參數上，觸發對該物件所有驗證規則的檢查 |
| 宣告式（declarative） | 用標籤描述規則，讓框架執行，而非自己寫邏輯檢查 |
| 400 Bad Request | HTTP 狀態碼，代表請求本身資料不合法（區別於伺服器錯誤 500） |
