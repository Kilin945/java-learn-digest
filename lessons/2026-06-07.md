## IoC 與依賴注入：為什麼不要自己 new · 第 2 步

### 核心概念：@Component & Constructor Injection

昨天了解了「自己 new 的問題（緊耦合）」，今天學 Spring 的解法。

**比喻：** Spring IoC Container 像人力派遣公司。你不用自己找人（new），只要登記（@Component）再申請（建構子參數），公司自動幫你把人派過來（inject）。

**兩個步驟：**
1. **登記** — 在 class 上加 `@Component`，Spring 把它納入管理並建立 Bean
2. **申請** — 在需要的 class 建構子帶上對應類別的參數，Spring 自動注入

### 程式碼範例

```java
// ❌ 問題寫法（昨天）：自己 new，緊耦合
public class OrderService {
    private EmailSender emailSender = new EmailSender();
}

// ✅ 解法：@Component + Constructor Injection

@Component
public class EmailSender {
    public void send(String message) {
        System.out.println("寄信：" + message);
    }
}

@Component
public class OrderService {
    private final EmailSender emailSender;

    public OrderService(EmailSender emailSender) {
        this.emailSender = emailSender; // Spring 自動注入
    }

    public void placeOrder() {
        emailSender.send("您的訂單已成立！");
    }
}
```

### 術語表

| 術語 | 白話定義 |
|------|----------|
| `@Component` | 加在 class 上，告訴 Spring「請管理這個物件」，Spring 啟動時自動掃描並建 Bean |
| Bean | Spring IoC 容器建立並管理的物件實例 |
| Constructor Injection | 建構子注入，透過建構子參數讓 Spring 傳入依賴，官方最推薦方式 |
| IoC Container | Spring 內部管理所有 Bean 的大倉庫，需要時自動提供 |

### 一句話帶走

加 `@Component` = 登記成 Bean；建構子帶參數 = 申請依賴；Spring IoC 容器搞定剩下的，不用自己 `new`。
