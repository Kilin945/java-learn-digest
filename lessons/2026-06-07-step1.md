## IoC 與依賴注入：為什麼不要自己 new · 第 1 步

### The Problem with `new`

自己 new 物件，為什麼會讓程式變難改？

**比喻：** 想像你開了一間咖啡館。你決定「自己種咖啡豆」——買了地、種了樹、等了三年才有豆。隔天老闆說「改賣奶茶」……那三年的咖啡農場怎麼辦？

程式也一樣。當 **OrderService（訂單服務）** 自己用 `new` 製造一個 **EmailNotifier（Email 通知器）**，兩個類別就「焊死」在一起了。這叫做 **tight coupling（緊耦合）**，意思是：你想換一個零件，整台機器都要拆開重裝。

### 程式碼範例

```java
// ❌ 問題寫法：自己 new，緊耦合
public class OrderService {

    // 這行把 OrderService 和 EmailNotifier 焊死在一起
    private EmailNotifier notifier = new EmailNotifier();

    public void placeOrder(String item) {
        notifier.send("訂單成立：" + item);
    }
}

// 問題：哪天想改用 SmsNotifier 發簡訊，
// 就必須打開 OrderService 修改它的程式碼 😱
// 改的地方越多，出錯的機會就越大。
```

### 術語表

| 術語 | 白話定義 |
|------|----------|
| `new` | Java 關鍵字，用來「製造」一個物件放進記憶體。就像工廠按下開關產出一台機器。 |
| tight coupling（緊耦合） | 兩個類別直接依賴彼此的具體實作，改動一個就牽連另一個，像兩根焊死的鋼棒。 |
| dependency（依賴） | 一個類別「需要用到」另一個類別，被需要的那個就叫做它的依賴。 |
| class（類別） | Java 程式的基本單位，像一份「設計圖」；用 `new` 可以按圖製造出物件（instance）。 |

### 一句話帶走

自己 `new` = 自己種咖啡豆——換需求時，只能連根拔起重來。
