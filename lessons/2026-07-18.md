## @SpringBootApplication 與自動組態的原理 · 第 3 步

### 概念
- 昨天學到：`@ConditionalOnClass` 會檢查 classpath 上有沒有特定類別，有才套用自動組態。
- 今天學到：Spring Boot 是拿一份叫 `AutoConfiguration.imports` 的「候選清單檔」，列出所有『有可能』被套用的自動組態類別，然後才逐一用 `@ConditionalOnClass` 檢查。
- 這個檔案藏在 spring-boot-autoconfigure jar 的 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`。
- 完整流程：`@SpringBootApplication` → 觸發 `@EnableAutoConfiguration` → 讀取 AutoConfiguration.imports 候選清單 → 逐一用 @ConditionalOnClass 檢查 classpath → 通過的才真的套用組態。

### 程式碼／檔案範例
```
# META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
org.springframework.boot.autoconfigure.web.servlet.WebMvcAutoConfiguration
org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration
org.springframework.boot.autoconfigure.jackson.JacksonAutoConfiguration
```

### 術語表
| 術語 | 定義 |
|---|---|
| AutoConfiguration.imports | 自動組態候選清單檔，列出所有可能被套用的組態類別 |
| META-INF | jar 檔裡專門放中繼資料/設定的資料夾 |
| 候選（candidate） | 在名單上但未確定生效，還要通過條件檢查 |

### 本主題總結
`@SpringBootApplication` = 三合一懶人包（`@SpringBootConfiguration` + `@EnableAutoConfiguration` + `@ComponentScan`）。自動組態的運作原理是：先有一份候選清單（AutoConfiguration.imports），再逐一用條件註解（如 @ConditionalOnClass）檢查 classpath，決定每個候選是否真的生效。
