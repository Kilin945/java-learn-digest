## IoC 與依賴注入：為什麼不要自己 new · 第 4 步

### 概念：Inject the Interface, Not the Class

**核心思想**：Controller（呼叫方）只依賴 Interface（介面），不依賴具體實作 class。換實作時，呼叫方程式碼完全不需修改。

**比喻**：Interface 像插座規格，只要電器符合規格（implements），背後接核電還是太陽能（具體實作）都可以替換，電器（Controller）完全不用改。

### 程式碼

```java
// 1. 介面（插座規格）
public interface NotificationService {
    void send(String message);
}

// 2. 具體實作（Email 插頭）
@Service
public class EmailNotificationService implements NotificationService {
    @Override
    public void send(String message) {
        System.out.println("Email: " + message);
    }
}

// 3. Controller 只依賴介面
@RestController
public class OrderController {
    private final NotificationService notificationService; // 介面，非具體 class

    public OrderController(NotificationService notificationService) {
        this.notificationService = notificationService; // Spring 自動傳入 EmailNotificationService
    }
    // 改成 SmsNotificationService？Controller 一行不用改 ✅
}
```

### 術語表

| 術語 | 中文 | 白話定義 |
|------|------|----------|
| Interface | 介面 | 定義「能做什麼」的合約，只有方法簽名，沒有實作。 |
| implements | 實作 | class 承諾遵守 Interface 合約，提供具體邏輯。 |
| Depend on Abstraction | 依賴抽象 | 只依賴介面，不依賴具體 class，換實作時呼叫方不需改動。 |

### 一句話重點

讓 Controller 只認識「介面」，Spring 負責決定「哪個實作」進來——這才是 IoC 真正的控制反轉。
