## B4 第 1 篇 · heap／stack／Metaspace 各放什麼

**題目**：JVM 記憶體區與 OOM 常見成因？（本篇只講：三個記憶體區各放什麼）

### 題目在問什麼

- JVM 把記憶體切成幾區，每區放不同類東西。
- OOM = OutOfMemoryError，某一區放滿又要不到空間。
- 整題三件事：有哪幾區（本篇）、最常爆的成因（第 2 篇）、怎麼查（第 3 篇）。

```java
// 輸入
Order o = new Order(3);
// 輸出：o → stack；new Order(3) 物件 → heap；Order 這個 class 的定義 → Metaspace
```

### 答案

物件本體放 heap；區域變數與方法呼叫放各執行緒自己的 stack；class 結構資訊放 Metaspace。

```java
// 典型寫法（簡化）
public class OrderService {
    // 【Metaspace】class 本身的資訊：名稱、欄位、方法、位元碼
    static String PREFIX = "ORD-";   // 欄位定義在 Metaspace；字串物件本體在 heap

    public String create(int qty) {   // 每次呼叫，stack 疊一個新 frame
        int price = 100;              // 【stack】基本型別值放在 frame 裡
        Order o = new Order(qty);     // o（線）在 stack；Order 物件本體在 heap
        return PREFIX + (qty * price);// 字串相加在 heap 產生新字串物件
    }                                 // 方法結束：frame 彈掉，物件留在 heap 等 GC
}
```

### 第 1 輪 · 釐清：stack 到底是什麼？frame 又是什麼？

stack 是方法呼叫的紀錄本，呼叫疊一格、結束彈一格，每條執行緒各有一疊。

```java
void a() { int x = 1; b(x); }
void b(int n) { int y = n + 1; c(y); }
void c(int z) { }
// stack（上面最新）：| c: z=2 | b: n=1, y=2 | a: x=1 |
// c 結束就彈掉 c 的格子；區域變數出了方法就沒了
// 疊太深（遞迴無停止條件）→ StackOverflowError：stack 滿，不是 heap 滿
```

### 第 2 輪 · 追原因：為什麼物件要放 heap，不放 stack？

物件常要活得比建立它的方法更久，stack 的格子方法一結束就清掉。

```java
Order create(int qty) {
    Order o = new Order(qty);   // 物件在 heap
    return o;                   // 回傳位址的複本
}                               // frame 彈掉，物件還在

void caller() {
    Order x = create(3);        // x 拿到同一個 heap 物件的位址
}
// heap 全執行緒共用，由 GC 清；沒有任何線指到它時才回收（第 2 篇伏筆）
```

### 第 3 輪 · 連結經驗：凱基 OOM 調查看到的訊息對應哪一區？

```text
// 典型訊息（簡化示意，非凱基實際 log）
// java.lang.OutOfMemoryError: Java heap space → heap 滿
// java.lang.OutOfMemoryError: Metaspace       → Metaspace 滿
// java.lang.StackOverflowError                → stack 滿（不是 OutOfMemoryError）
```

### 為什麼要懂

線上 OOM 時要先分清是 heap、Metaspace 還是 stack，三者處理方向不同；分不清可能對 heap 狂加記憶體，爆的其實是無限遞迴。

### 結論

物件在 heap、區域變數與呼叫在 stack、class 資訊在 Metaspace；OOM 先看訊息判斷哪一區。

### 術語表

| 術語 | 白話定義 |
|---|---|
| heap | 放 new 出來物件本體的共用大空間 |
| stack | 每條執行緒自己的方法呼叫紀錄 |
| frame | stack 裡的一格，對應一次方法呼叫 |
| Metaspace | 放 class 結構資訊的區域 |
| GC | 垃圾回收器，清掉 heap 裡沒人指到的物件 |
| OOM | OutOfMemoryError，某區放滿又要不到空間 |
| 位元碼 | .java 編譯後的指令 |
