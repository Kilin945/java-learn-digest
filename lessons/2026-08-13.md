## Bean Validation：@Valid 與 @NotNull · 第 2 步

### 概念：@NotNull 的漏洞——空字串照樣過關

昨天學了 @NotNull（宣告規則）+ @Valid（觸發檢查）的組合，能擋下沒送值（null）的資料。但 @NotNull 只檢查「這個欄位是不是 null」，如果送的是空字串 `""` 或純空白 `"   "`，技術上「有值」，@NotNull 完全抓不到。

字串型別的欄位應該改用更嚴格的 **@NotBlank**：它會先把字串頭尾空白去掉，再檢查是否還剩下任何字元，才判定是否合法。

### 程式碼

```java
public class UserDto {

    @NotNull
    private String name;   // 送 "" 或 "   " 也會通過檢查！

    // 今天升級成這個
    @NotBlank
    private String email;  // 空字串、純空白都會被擋下
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| @NotBlank（非空白） | 比 @NotNull 更嚴格：先去掉字串頭尾空白，再檢查是否還有內容，適合用在字串欄位。 |
| 空字串（empty string） | 長度為 0 的字串 `""`，跟「完全沒有值」的 null 是兩種不同狀態。 |
| 空白字元（whitespace） | 像空格、Tab 這種看不見但佔位的字元，例如 `"   "`。 |

### 一句話帶走

@NotNull 只管「有沒有送值」，@NotBlank 才管「是不是送了空的」——字串欄位請優先用 @NotBlank。
