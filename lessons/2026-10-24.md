## B8 · abstract class 與 interface 差在哪？什麼時候用哪個？

### 今日題目與答案

interface（介面）只規定「能做什麼」，一個類別可以實作多個。abstract class（抽象類別）是「一類東西的半成品」，可以有共用欄位和寫好的方法，但只能繼承一個。實作之間有大量重複的流程和狀態，就用 abstract 把骨架寫在父類別，只留差異給子類別。只是要約定行為、各實作彼此無關，就用 interface。

**錨點**：Groovy 外掛的電文處理：共用解析骨架＝abstract class，各電文自己的欄位對應＝實作。

### 第 0 輪 · 比喻

**Q：「約定能做什麼」跟「半成品」各自像什麼？**

- interface ＝ 證照。只寫要有什麼能力，不管怎麼學的，一個人可以有很多張，持有者彼此可以毫無關係。
- abstract class ＝ 毛胚屋。水電、樓板已做好（共用欄位和方法），裝潢留白（abstract method）。不能直接住（不能 new），只能選一棟當基礎（單一繼承）。

### 第 1 輪 · 程式碼

**Q：「骨架在父類別、差異留給子類別」寫出來長怎樣？**

```java
public abstract class MessageParser {

    // 共用骨架：每支電文流程都一樣，final 表示子類別不准改順序
    public final Map<String, String> parse(String raw) {
        validate(raw);                          // 共用步驟
        Map<String, String> out = new LinkedHashMap<>();
        mapFields(raw, out);                    // 差異步驟：交給子類別
        return out;
    }

    protected void validate(String raw) {       // 寫好的方法，子類別直接用
        if (raw == null || raw.isEmpty()) {
            throw new IllegalArgumentException("empty message");
        }
    }

    // 沒有內容，子類別一定要自己實作
    protected abstract void mapFields(String raw, Map<String, String> out);
}

public class BalanceParser extends MessageParser {
    @Override
    protected void mapFields(String raw, Map<String, String> out) {
        out.put("account", raw.substring(0, 10));
        out.put("balance", raw.substring(10, 22));
    }
}
```

這種寫法叫 Template Method（樣板方法模式）：父類別定好步驟順序，子類別只填其中一步。新增電文只要多寫一個子類別。

### 第 2 輪 · 反例

**Q：全部用 interface 不行嗎？**

可以跑，但每個實作都得把共用流程抄一份：

```java
interface MessageParser { Map<String, String> parse(String raw); }

class BalanceParser implements MessageParser {
    public Map<String, String> parse(String raw) {
        if (raw == null || raw.isEmpty()) throw new IllegalArgumentException(); // 抄一份
        Map<String, String> out = new LinkedHashMap<>();
        out.put("account", raw.substring(0, 10));                               // 差異
        return out;
    }
}

class StatementParser implements MessageParser {
    public Map<String, String> parse(String raw) {
        if (raw == null || raw.isEmpty()) throw new IllegalArgumentException(); // 又抄一份
        Map<String, String> out = new LinkedHashMap<>();
        out.put("date", raw.substring(0, 8));                                   // 差異
        return out;
    }
}
```

20 支電文就要改 20 處，漏一處就是 bug。差異小、重複大，就是該用 abstract class 的訊號。

### 第 3 輪 · 對照

**Q：abstract class 為什麼只能繼承一個？interface 為什麼可以多個？**

關鍵在有沒有狀態。能繼承兩個父類別、且兩者有同名欄位或方法時，子類別不知道用誰的，這是菱形問題（diamond problem），Java 因此禁止。interface 傳統上沒有實例欄位，實作多個不會撞。

```java
class Duck extends Animal implements Flyable, Swimmable { }   // OK
class Duck extends Animal, Plant { }                          // 編譯錯誤
```

兩者常搭配用：interface 當對外約定，abstract class 當骨架，例如 `List` 與 `AbstractList`。

### 第 4 輪 · 在你自己的 code 裡

**Q：這跟我平常寫的東西有什麼關係？**

Groovy 外掛的電文處理：「共用的解析骨架」＝ abstract class 裡寫好的 `parse()`／`validate()`，「各支電文的欄位對應」＝各實作自己補的 `mapFields()`。解析流程一樣、只有欄位對應不同，正是「重複多、差異集中」的情況，所以用 abstract class。

### 🪤 面試追問

**Q：Java 8 之後 interface 有 default method 了，abstract class 還有什麼不能被取代的？**

1. 存狀態：interface 不能有實例欄位，只能放常數。
2. 建構子：abstract class 可以在建立時做完共用初始化，interface 沒有。
3. 單一繼承的語意：繼承代表「是一種什麼」，interface 代表「能做什麼」。

要共用資料和流程骨架就用 abstract class，只要約定行為就用 interface。default method 的用途是讓 interface 能演進而不破壞舊實作。

### 今日一句話帶走

interface 約定「能做什麼」，可實作多個。abstract class 提供「共用狀態和流程的半成品」，只能繼承一個。

### 術語表

| 術語 | 中文 | 白話定義 |
|---|---|---|
| interface | 介面 | 只規定「有哪些方法」的約定，可實作多個 |
| abstract class | 抽象類別 | 寫了一半的類別，可有欄位和寫好的方法，不能 new，只能繼承一個 |
| abstract method | 抽象方法 | 只有宣告沒有內容，子類別一定要補完 |
| Template Method | 樣板方法模式 | 父類別定步驟順序，子類別只填其中幾步 |
| default method | 預設方法 | Java 8 起 interface 裡可直接寫內容的方法，仍不能存狀態 |
| diamond problem | 菱形問題 | 多重繼承時同名成員衝突，Java 因此禁止 |
| constructor | 建構子 | 物件建立時自動執行的初始化程式，interface 沒有 |
