## 交易：@Transactional 的邊界與陷阱 · 第 3 步

### 概念：Checked Exception 不會自動觸發 Rollback

@Transactional 的自動 rollback 有預設規則：**只有丟出 unchecked exception（RuntimeException 或 Error 的子類）時，Spring 才會自動 rollback**。

如果方法丟出的是 **checked exception**（例如自己定義的 `extends Exception`），就算方法確實丟出例外，Spring 預設也**不會** rollback——先前的資料庫操作照樣 commit，造成資料不一致。

若要讓 checked exception 也能觸發 rollback，必須明確用 `rollbackFor` 屬性指定。

### 程式碼範例

```java
// 問題寫法：InsufficientFundsException extends Exception（checked）
@Transactional
public void transferMoney(Long from, Long to, BigDecimal amount)
        throws InsufficientFundsException {
    accountRepo.withdraw(from, amount);
    if (accountRepo.balanceOf(from) < 0) {
        // 丟出 checked exception → 預設不會 rollback！
        throw new InsufficientFundsException("餘額不足");
    }
    accountRepo.deposit(to, amount);
}

// 修好寫法：明確指定 checked exception 也要 rollback
@Transactional(rollbackFor = InsufficientFundsException.class)
public void transferMoney(Long from, Long to, BigDecimal amount)
        throws InsufficientFundsException {
    // ... 同上，這次會正確 rollback
}
```

### 今日一句話帶走

預設只有 unchecked exception 會自動 rollback，checked exception 要靠 `rollbackFor` 自己指定。

### 術語表

| 術語 | 定義 |
|---|---|
| Checked Exception（檢查例外） | 編譯器強制 try-catch 或宣告 throws 的例外，繼承自 Exception（不含 RuntimeException 家族） |
| Unchecked Exception（非檢查例外） | 繼承自 RuntimeException 或 Error，@Transactional 預設只對這種例外 rollback |
| rollbackFor | @Transactional 的屬性，用來指定額外要 rollback 的例外類型 |
