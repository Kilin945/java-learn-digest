## @Configuration 與 @Bean：手動定義 Bean · 第 1 步

### 核心概念

**為什麼需要 @Configuration + @Bean？**

元件掃描（Component Scan）要求類別上有 `@Component`，但**第三方函式庫（Third-party Library）**的類別無法修改原始碼，因此無法加 `@Component`。這時需要手動用 `@Bean` 定義。

**比喻**：@Component 是「員工自己刷門禁卡」；@Bean 是「前台幫訪客辦訪客證帶進來」。

### @Configuration vs @Bean

| Annotation | 標在哪 | 作用 |
|---|---|---|
| `@Configuration` | 類別 | 宣告這是 Spring 配置類別，Spring 掃描其中的 @Bean 方法 |
| `@Bean` | 方法 | 方法的**回傳值**由 Spring 容器接管，可供 @Autowired 注入 |

### 程式碼範例

```java
// 假設 ObjectMapper 是第三方套件，無法加 @Component

@Configuration                         // ← 這個類別是「配置檔」
public class AppConfig {

    @Bean                              // ← 方法的回傳值會進 Spring 容器
    public ObjectMapper objectMapper() {
        return new ObjectMapper();     // 直接 new，交給 Spring 管理
    }
}
```

### 術語表

| 術語 | 中文 | 白話定義 |
|---|---|---|
| `@Configuration` | 配置類別 | 標記一個 Java 類別為 Spring 配置檔，Spring 掃描其中的 @Bean 方法 |
| `@Bean` | 手動 Bean | 標在方法上，回傳物件由 Spring 容器接管，可供 @Autowired 注入 |
| Third-party Library | 第三方函式庫 | 別人寫好、透過 Maven/Gradle 引入的套件；原始碼不可修改 |
| Component Scan | 元件掃描 | Spring 自動掃描套件路徑，找出有 @Component 的類別並納入容器 |

### 一句話帶走

@Configuration 是「Bean 的登記處」，@Bean 是「替每個物件辦理入場券」。
