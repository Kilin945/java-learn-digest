## Bean 的 scope 與生命週期 · 第 5 步

### 概念：ObjectProvider<T> — 不直接依賴 ApplicationContext 也能拿到全新的 Prototype Bean

前一步教的做法是讓 Singleton Bean 注入整個 `ApplicationContext`，需要新的 Prototype Bean 時手動呼叫 `getBean()`。這樣可行，但讓 Bean 直接依賴整個容器，屬於**耦合（Coupling）**過深的寫法。

Spring 提供 `ObjectProvider<T>` 作為更乾淨的替代方案：只需注入 `ObjectProvider<PrototypeBeanType>`，需要時呼叫 `.getObject()`，Spring 會依照該 Bean 的 scope 規則回傳實例（對 prototype 而言，每次都是全新的）。

### 程式碼

```java
@Component
public class ReportPrinter { // Singleton Bean

    private final ObjectProvider<PdfBuilder> pdfBuilderProvider;

    public ReportPrinter(ObjectProvider<PdfBuilder> pdfBuilderProvider) {
        this.pdfBuilderProvider = pdfBuilderProvider;
    }

    public void printReport() {
        // 每次呼叫，都是全新的一個 PdfBuilder
        PdfBuilder builder = pdfBuilderProvider.getObject();
        builder.build();
    }
}

@Component
@Scope("prototype")
public class PdfBuilder {
    // 有自己狀態的物件
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| ObjectProvider<T> | Spring 提供的介面，可在需要的當下動態跟容器要一個 Bean 實例，取代直接注入 ApplicationContext。 |
| getObject() | 呼叫後，Spring 依 Bean 的 scope 規則產生（或回傳）一個實例。 |
| 耦合 (Coupling) | 兩段程式碼互相依賴太深，改一邊容易牽動另一邊。 |

### 主題總結（Bean 的 scope 與生命週期）

1. 預設 scope 是 singleton，容器內共用同一個實例。
2. `@Scope("prototype")` 讓每次注入都是全新實例，適合有狀態的物件。
3. `@PostConstruct`／`@PreDestroy` 分別在 Bean 建立完成後、容器關閉前執行，但 `@PreDestroy` 只對 singleton 有效。
4. Prototype Bean 注入 Singleton Bean 時只會建立一次；要每次拿新的，需手動用 `ApplicationContext.getBean()`。
5. `ObjectProvider<T>.getObject()` 是更乾淨的做法，避免直接依賴整個容器。
