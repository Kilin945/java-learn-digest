## Spring Security 入門：認證與授權概念 · 第 7 步

### Method Security with @PreAuthorize

之前在 `SecurityFilterChain` 集中用路徑寫規則；但「只能看自己的資料」這種規則看的不是路徑，適合用 **Method Security（方法層級安全）**，把規則貼在方法上。

步驟：
1. 設定類別加 `@EnableMethodSecurity`（總開關，沒開註解不生效）。
2. 方法上加 `@PreAuthorize("規則")`，在方法執行**之前**檢查，不通過回 403，方法內容不會執行。

```java
@Configuration
@EnableMethodSecurity
public class SecurityConfig { /* SecurityFilterChain 照舊 */ }

@RestController
public class OrderController {

    @PreAuthorize("hasRole('ADMIN')")
    @DeleteMapping("/orders/{id}")
    public void delete(@PathVariable Long id) { ... }

    @PreAuthorize("#username == authentication.name")
    @GetMapping("/users/{username}/orders")
    public List<Order> myOrders(@PathVariable String username) { ... }
}
```

- `hasRole('ADMIN')` 不用寫 `ROLE_` 前綴，Spring 自動補上。
- `#參數名` 引用方法參數，`authentication.name` 是目前登入者帳號。
- alice 已登入卻查 `/users/bob/orders` → 403（不是 401）。

**一句話：**開啟 @EnableMethodSecurity 後，用 @PreAuthorize 在方法執行前檢查角色或是否本人，不符就 403。

### 術語表
| 術語 | 中文 | 定義 |
|---|---|---|
| Method Security | 方法層級安全 | 把授權規則直接寫在方法上 |
| @EnableMethodSecurity | 啟用方法安全 | 總開關，沒加 @PreAuthorize 不生效 |
| @PreAuthorize | 執行前授權 | 方法執行前檢查規則，不過就 403 |
| SpEL | Spring 表達式語言 | 字串裡的小判斷式 |
