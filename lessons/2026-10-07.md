## Spring Security 入門：認證與授權概念 · 第 3 步

### PasswordEncoder: Never Store Plain Passwords

認證最常見的方式是比對帳號與密碼，但資料庫**絕不能存密碼原文**。比喻：管理員只保存「鑰匙的指紋」，開門時把你的鑰匙也算一次指紋來比對。

- **Hash（雜湊）**：單向運算，把密碼變成固定長度亂碼，無法倒推原文。
- **Salt（鹽）**：隨機字串，讓同一密碼每次雜湊結果都不同，防止對照表破解。
- **PasswordEncoder**：Spring Security 處理密碼雜湊與比對的介面；常用實作 `BCryptPasswordEncoder`。
  - `encode(raw)`：存檔前轉成雜湊。
  - `matches(raw, hash)`：登入時比對。

```java
// ❌ 問題寫法：密碼原文直接存
user.setPassword("123456");
userRepository.save(user);

// ✅ 修好寫法：先 encode 再存
@Bean
PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}

String hash = passwordEncoder.encode("123456");
user.setPassword(hash);
userRepository.save(user);

// 登入時比對
passwordEncoder.matches("123456", hash); // true
```

**一句話帶走**：資料庫只存 BCrypt 指紋；存檔用 `encode()`，登入比對用 `matches()`，不要用 `equals()`。

### 術語表
| 術語 | 中文 | 定義 |
|---|---|---|
| Hash | 雜湊 | 單向運算，無法倒推原文 |
| Salt | 鹽 | 隨機字串，讓相同密碼雜湊不同 |
| PasswordEncoder | 密碼編碼器 | 處理密碼雜湊與比對的介面 |
| BCrypt | 雜湊演算法 | 專為密碼設計、刻意較慢、自帶 salt |
| @Bean | Spring 管理的物件 | 標在方法上，回傳物件交給 Spring 管理 |
