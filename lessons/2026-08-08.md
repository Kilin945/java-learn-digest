## DTO 與 entity 為什麼要分開 · 第 1 步

### 概念：為什麼不能把 Entity 直接丟給前端

- **Entity** 是對應資料庫一張表的 Java 類別，貼 `@Entity` 標記，欄位對應表的欄位。
- 比喻：Entity 就像公司內部的「員工完整檔案」，裡面有密碼、身分證號這些不該外流的東西。
- 如果 Controller 直接把 entity 回傳出去，Spring 的**序列化**機制會把物件裡「所有」欄位都轉成 JSON 送出去——包括不該公開的欄位。
- 這是今天的核心結論：**直接回傳 Entity = 把整份內部檔案交給外人，無法控制哪些欄位該露出來。**
- 解法（下一步再教）：用 DTO（資料傳輸物件）當作對外的簡化版。

### 程式碼示範

```java
// 這是對應資料庫 users 表的 Entity
@Entity
public class User {
    @Id
    private Long id;
    private String username;
    private String password;   // 不該外流！
    private String idNumber;   // 身分證號，也不該外流！
}

// 如果 Controller 這樣寫：
@GetMapping("/users/{id}")
public User getUser(@PathVariable Long id) {
    return userRepository.findById(id).get(); // 直接回傳 Entity
}
// 結果：password、idNumber 全部一起被轉成 JSON 送出去！
```

### 術語表

| 術語 | 定義 |
|---|---|
| Entity（實體類別） | 對應資料庫一張表的 Java 類別，貼 `@Entity` 標記，欄位對應表的欄位 |
| 序列化（serialize） | 把 Java 物件自動轉成 JSON 文字的過程，會把物件裡所有欄位都轉出來 |
| DTO（資料傳輸物件） | Data Transfer Object，專門用來對外傳資料的物件，只放該公開的欄位 |
