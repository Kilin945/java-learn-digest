## Bean 是什麼：@Component / @Service / @Repository · 第 2 步

**日期**：2026-06-15

### 概念：@Service & @Repository — 角色分明的 Bean

Spring 後端程式碼通常分三層：
- **Controller**（控制器）：接 HTTP 請求、回傳結果
- **Service**（服務層）：放業務邏輯
- **Repository**（倉庫層）：跟資料庫溝通

`@Service` 和 `@Repository` 是 `@Component` 的特化版本，功能上都是讓 Spring 把 class 建成 Bean，但多了「職責標籤」，讓程式碼語意更清晰。

`@Repository` 有一個額外功能：**Exception Translation（例外轉換）** — 自動把底層資料庫原生例外（如 `SQLException`）包裝成 Spring 統一的 `DataAccessException`，讓上層程式碼不必知道底層用的是哪種資料庫。

### 程式碼範例

```java
// 倉庫層：負責跟資料庫溝通
@Repository
public class UserRepository {
    public String findNameById(int id) {
        return "Alice"; // 之後改成真正查 DB
    }
}

// 服務層：負責業務邏輯
@Service
public class UserService {
    public String greet(int id) {
        // ⚠️ 先用 new 示意，下一課改用 @Autowired 注入
        UserRepository repo = new UserRepository();
        return "Hello, " + repo.findNameById(id) + "!";
    }
}
```

### 術語表

| 術語 | 中文 | 定義 |
|------|------|------|
| `@Service` | 服務 Bean | @Component 特化版，貼在業務邏輯 class 上 |
| `@Repository` | 倉庫 Bean | @Component 特化版，貼在資料存取 class 上，附帶例外轉換 |
| 三層架構 | Three-tier | Controller → Service → Repository 分層架構 |
| Exception Translation | 例外轉換 | @Repository 自動把原生 DB 例外轉成 DataAccessException |

### 重點一句話

> @Service 和 @Repository 本質是 @Component，只是多了職責標籤——讓同事、讓自己、讓 Spring 都能一眼看出這個 Bean 的角色。
