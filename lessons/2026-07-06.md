## @Autowired、@Qualifier 與多個候選 Bean 的解析 · 第 4 步

### 概念：@Primary — 指定預設 Bean

當同一個介面有多個實作類別，且注入點沒有用 @Qualifier 明確指名時，可以在其中一個實作類別上加 `@Primary`，讓它成為 Spring 容器的預設選擇，避免拋出 `NoUniqueBeanDefinitionException`。

比喻：飲料店的「招牌品牌」——沒特別指定時，店員就給你招牌口味；但如果你明確點了某個品牌（相當於 @Qualifier），店員還是照你說的做。

### 程式碼

```java
public interface NotificationService {
    void send(String message);
}

@Service
@Primary   // 沒指名時，優先選我
public class EmailNotificationService implements NotificationService {
    public void send(String message) {
        System.out.println("寄送 Email: " + message);
    }
}

@Service
public class SmsNotificationService implements NotificationService {
    public void send(String message) {
        System.out.println("寄送簡訊: " + message);
    }
}

@Service
public class NotifyController {
    private final NotificationService notificationService;

    @Autowired   // 這裡沒有 @Qualifier，也不會報錯
    public NotifyController(NotificationService notificationService) {
        this.notificationService = notificationService;
    }
}
```

### 重點

- `@Primary` 貼在實作類別上，代表「沒人明確指名時，用我當預設」。
- 若注入點同時遇到 `@Primary` 與 `@Qualifier`，**@Qualifier 的明確指名優先於 @Primary 的預設值**。
- 至此完成「多候選 Bean 解析」主題的三個核心工具：
  1. `@Autowired`：基本依賴注入。
  2. 多實作衝突時的 `NoUniqueBeanDefinitionException`。
  3. `@Qualifier`（明確指名）與 `@Primary`（預設選擇）兩種解法。

### 術語表

| 術語 | 定義 |
|---|---|
| @Primary | 貼在某實作類別上，告訴 Spring 容器：注入點沒有明確指名時，優先使用這個 Bean。 |
| 預設 Bean（Default Bean） | 沒人明確指定時，系統自動採用的那個候選物件。 |
| 優先順序（Precedence） | @Primary 與 @Qualifier 同時存在時，注入點上明確寫的 @Qualifier 蓋過 @Primary 的預設值。 |
