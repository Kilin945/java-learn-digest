## A7 第 2 篇 · 自動配置怎麼運作：@ConditionalOnClass、@ConditionalOnMissingBean；自己的設定為什麼優先

### 題目：Spring MVC 和 Spring Boot 差在哪？

**題目在問什麼**

- 本篇只講：為什麼只加依賴，東西就自己動起來。
- 要答到四件事：① 自動設定清單 ② 憑什麼啟用 ③ 你自己定義過怎麼辦 ④ 為什麼你的優先。

```java
// 輸入：pom 只加 spring-boot-starter-web，沒寫 XML、沒寫 @Bean
// 輸出：容器裡已有 DispatcherServlet、ObjectMapper 等 Bean
// 追問：誰建的？我自己定義 ObjectMapper 時 Boot 會蓋掉嗎？（不會）
```

**解題思路**

1. 先問 Boot 怎麼知道有哪些設定可用 → 自動設定清單（本篇）
2. 每一項要有條件 → @ConditionalOnClass（本篇）
3. 你自己定義時要讓路 → @ConditionalOnMissingBean（本篇）
4. 結論：條件成立才建，你的優先（本篇）
5. starter、內嵌 Tomcat：第 1 篇

**答案**

Boot 啟動時讀自動設定清單，每個設定類別帶條件註解；條件成立才建 Bean，「你沒定義過」是條件之一，所以你的優先。

```java
// 簡化示意
@Configuration
@ConditionalOnClass(ObjectMapper.class)   // classpath 有 Jackson 才整包啟用
public class JacksonAutoConfiguration {
    @Bean
    @ConditionalOnMissingBean             // 容器沒有 ObjectMapper 才建
    public ObjectMapper objectMapper() {
        return new ObjectMapper();
    }
}
```

### 第 1 輪 · 釐清：@ConditionalOnClass 在檢查什麼？

```java
// 典型寫法（簡化）
boolean jacksonExists;
try {
    Class.forName("com.fasterxml.jackson.databind.ObjectMapper");
    jacksonExists = true;   // 依賴 jar 在 classpath 上
} catch (ClassNotFoundException e) {
    jacksonExists = false;  // 沒加依賴 → 條件不成立 → 不啟用
}
```

### 第 2 輪 · 追原因：為什麼是 Boot 讓給我，不是蓋掉我的？

```java
@Configuration
public class MyJacksonConfig {
    @Bean
    public ObjectMapper objectMapper() {
        ObjectMapper om = new ObjectMapper();
        om.findAndRegisterModules();
        return om;
    }
}
// ① 先處理你的 @Configuration → 容器已有 objectMapper
// ② 最後才處理自動設定 → @ConditionalOnMissingBean 看到已有 → 跳過
// 反事實：若自動設定先跑 → 兩個同型別 Bean → NoUniqueBeanDefinitionException
// 注意：預設比對「型別」，你定義別的型別不算你的優先
```

### 第 3 輪 · 連結經驗：在 anki-forge 與現職 XML 專案裡長什麼樣子？

```properties
# Boot 專案：application.properties
debug=true
# 啟動 log 印 CONDITIONS EVALUATION REPORT
# Positive matches：條件成立、有建
# Negative matches：條件不成立、沒建
```

```xml
<!-- 現職 XML（典型寫法，簡化）：寫了就建，沒有條件判斷 -->
<bean id="objectMapper" class="com.fasterxml.jackson.databind.ObjectMapper"/>
```

### 追問：auto-configuration 的原理是什麼（@Conditional）？

```text
# spring-boot-autoconfigure jar 內
# META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
# （Boot 2.7 以後；更早用 META-INF/spring.factories）
org.springframework.boot.autoconfigure.jackson.JacksonAutoConfiguration
org.springframework.boot.autoconfigure.web.servlet.WebMvcAutoConfiguration
...
# @SpringBootApplication 內含 @EnableAutoConfiguration → 讀清單 → 每項自帶條件 → 成立才建
# 不是魔法，是清單加條件；你自己定義的優先
```

### 為什麼要懂

想換掉 Boot 預設的 JSON 設定、連線池時，知道「自己定義同型別 Bean 就會讓它跳過」就不必改框架；功能沒自動出現時，看 debug=true 的條件報告能快速分辨是缺依賴還是被你的 Bean 擋掉。

### 結論

自動配置是一份清單加每項的條件判斷：依賴在且你沒定義才建，所以你的設定優先。

### 術語表

| 術語 | 白話定義 |
|---|---|
| 自動配置 | Boot 啟動時依條件替你建好常用 Bean |
| classpath | JVM 找 .class 的路徑清單，依賴 jar 都在裡面 |
| @ConditionalOnClass | classpath 找得到指定類別才啟用 |
| @ConditionalOnMissingBean | 容器沒有同型別 Bean 才建 |
| Bean | 交給 Spring 容器管理的物件 |
| .imports 清單檔 | Boot 放自動設定類別名稱的文字檔 |
