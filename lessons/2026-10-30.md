## B8 第 1 篇 · interface＝約定「能做什麼」，一個類別可以實作多個

**題目**：abstract class 與 interface 差在哪？什麼時候用哪個？（本篇只講 interface）

### 題目在問什麼
- interface：只寫「能做什麼」的清單，不寫怎麼做。
- abstract class：寫到一半的類別（第 2 篇）。
- 要答到：差在哪、怎麼判斷用哪個、自己專案是哪一種。

### 解題思路
1. 先搞懂 interface 規定什麼、為什麼能實作多個（本篇）
2. abstract class 的半成品特性（第 2 篇）
3. Java 8 之後 abstract class 還剩什麼（第 3 篇）
4. 回答何時用哪個，接回專案（第 2、3 篇）

### 答案
interface 是「能做什麼」的約定，只列方法名稱，一個類別可以同時實作很多個。

```java
// 典型寫法（簡化）
interface MessageParser { String parse(String raw); }
interface Loggable { void log(String msg); }

class AParser implements MessageParser, Loggable {
    public String parse(String raw) { return raw.trim(); }
    public void log(String msg) { System.out.println(msg); }
}
```

### 第 1 輪（釐清）interface 到底是什麼？
它是一種型別，代表「簽了約定就保證有這些方法」。呼叫端只認約定。

```java
MessageParser p = new AParser();
p.parse("xyz");
p = new BParser();   // 換實作，呼叫端不用改
// new MessageParser() 不行：約定沒有內容可執行
```

### 第 2 輪（追原因）為什麼 implements 能多個、extends 只能一個？
interface 只有約定沒有內容，同名也沒有「用誰的版本」的問題；父類別有寫好的內容，兩個父類別同名就無法決定。

```java
interface X { void run(); }
interface Y { void run(); }
class Both implements X, Y { public void run() { } }  // 一份就滿足兩個
// class Child extends P1, P2 { }  // 編譯錯誤：不知該用誰的 run()
```

### 第 3 輪（連結經驗）電文處理的「各電文欄位對應＝實作」
```java
// 典型寫法（簡化），非專案原始碼
interface FieldMapper { Map<String, String> map(String rawMessage); }
class MessageAMapper implements FieldMapper { /* A 自己的欄位對應 */ }
class MessageBMapper implements FieldMapper { /* B 自己的欄位對應 */ }

void handle(FieldMapper mapper, String raw) {
    Map<String, String> fields = mapper.map(raw);  // 不管哪支電文都不用改
}
```

### 為什麼要懂
Spring 裡的 Repository、Service 常是 interface；不懂「約定」就不知道為什麼可以任意換實作，看到 implements 好幾個也分不出是疊能力還是繼承內容。

### 結論
interface 是「能做什麼」的約定，只有清單沒有內容，所以一個類別可以簽很多份；實作彼此無關、只需約定行為時選它。

### 術語表
| 術語 | 白話定義 |
|---|---|
| interface | 「能做什麼」的約定，只列方法名稱 |
| implements | 類別宣告簽了這份約定，並把方法寫出來 |
| abstract class | 寫到一半的類別，第 2 篇細講 |
| 方法簽名 | 方法名稱、參數、回傳型別，不含內容 |
