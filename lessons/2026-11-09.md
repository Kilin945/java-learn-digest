## B1 第 1 篇 · HashMap 怎麼找東西：hashCode 找桶、equals 比對；只覆寫 equals 會出什麼 bug

**題目：equals/hashCode 契約？為什麼要一起覆寫？**

### 題目在問什麼
- equals：判斷兩個物件算不算同一個。hashCode：把物件變成 int 數字。
- 要答到：規則是什麼、HashMap 怎麼用這兩個方法找東西、只改 equals 會壞在哪。
- 要先問清楚：hashCode 相同，equals 一定相等嗎？（不一定）

```java
// 輸入：只覆寫 equals 的 User
Set<User> set = new HashSet<>();
set.add(new User(1, "Amy"));
// 輸出
set.contains(new User(1, "Amy"));  // false（預期 true）
set.add(new User(1, "Amy"));       // size 變 2（預期 1）
```

### 解題思路
1. 先講規則：equals 相等，hashCode 必須相同。（本篇）
2. HashMap 流程：hashCode 找桶、equals 比對。（本篇）
3. 只改 equals 的後果：內容一樣的物件進不同桶，找不到。（本篇）
4. 碰撞（hashCode 相同但 equals 不等）是允許的。（本篇一句）
5. 追問：會變動的欄位算 hashCode。（第 2 篇）

### 答案
規則是 equals 相等 → hashCode 必須相同。HashMap／HashSet 先用 hashCode 找桶、再用 equals 比對，只改 equals 則內容相同的物件被算到不同桶，查不到。

```java
// 典型寫法（簡化）：只覆寫 equals
public class User {
    private final int id;
    private final String name;
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof User)) return false;
        User u = (User) o;
        return id == u.id && Objects.equals(name, u.name);
    }
    // 沒寫 hashCode → 用 Object 預設，兩個內容相同的 User hashCode 幾乎一定不同
}

// 修法
@Override
public int hashCode() { return Objects.hash(id, name); }
// equals 相等 → hashCode 必須相同（單向）
// hashCode 相同 → equals 不一定相等（碰撞，允許）
```

### 第 1 輪 · 釐清：HashMap 的「桶子」是什麼？hashCode 怎麼找到它、equals 在哪一步登場？

```java
// 簡化示意（真實 HashMap 還會打散 hash、桶太長轉成樹）
Entry[] table = new Entry[16];   // 16 個桶

V get(K key) {
    int idx = Math.abs(key.hashCode()) % 16;   // 步驟1：hashCode → 桶編號
    for (Entry e : table[idx]) {               // 步驟2：只翻這一桶
        if (e.key.equals(key)) return e.value; // 步驟3：桶內用 equals 比
    }
    return null;
}
// hashCode 決定去哪一格，equals 決定格子裡哪一筆是你要的
```

### 第 2 輪 · 追原因：為什麼要「hashCode 找桶 + equals 比對」兩段式？

```
// 100 萬筆資料
// A（沒有桶）：逐一 equals，最壞 100 萬次
// B（HashMap）：hashCode 算一次 → 桶編號 → 只比那一桶（通常 1～2 筆）
// hashCode：快但粗，負責縮小範圍；equals：慢但準，負責最後確認
// 推論：該算同一個的物件必須進同一個桶，equals 才有機會被呼叫
//       → equals 相等的兩個物件 hashCode 必須相同
```

### 第 3 輪 · 連結經驗：entity 當 HashMap 的 key，這個 bug 會看到什麼症狀？

```java
// 典型寫法（簡化）：entity 只覆寫 equals
Map<User, String> roles = new HashMap<>();
roles.put(new User(1, "Amy"), "ADMIN");
User fromDb = new User(1, "Amy");
roles.get(fromDb);   // null！沒有例外、沒有 log
// 症狀：照常執行，只是查不到，容易誤判成資料沒進來
// 檢查：當 key 的 class 是否有 equals 沒有 hashCode
```

### 為什麼要懂
排查「資料明明在 Map／Set 裡卻查不到」時，不知道 hashCode 先決定桶子，就會一直去查資料來源。看到 entity 當 key 或放進 HashSet 去重，先檢查 equals 與 hashCode 是否成對。

### 結論
HashMap 先用 hashCode 找桶、再用 equals 確認，所以 equals 相等的物件 hashCode 必須相同；只改 equals 會查不到、Set 去不了重。

### 術語表
| 術語 | 白話定義 |
|---|---|
| 契約 | Java 規定 equals 與 hashCode 必須遵守的規則 |
| 桶（bucket） | HashMap 內部陣列的一格，同一格放一小串 Entry |
| 碰撞 | 兩個不相等的物件算出同一個桶；允許，只是桶裡多比幾筆 |
| Entry | HashMap 裡一筆資料：key 加 value |
