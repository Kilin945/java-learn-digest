## 統一例外處理：@RestControllerAdvice · 第 3 步

### 概念：用 ResponseEntity 回傳結構化錯誤

昨天的最簡單版本只回傳一句純文字（String），這造成兩個問題：
1. HTTP 狀態碼永遠是預設的 200 OK，即使實際上是「找不到資料」的錯誤，前端無法單靠狀態碼判斷是否出錯。
2. 回傳格式是純文字而非 JSON，前端難以解析。

解法：用 `ResponseEntity<T>` 包裝回傳值，同時指定內容（body）與正確的 HTTP 狀態碼；並用一個 DTO（Data Transfer Object，資料傳輸物件）class 如 `ErrorResponse` 來裝結構化的錯誤資訊（狀態碼、訊息、時間戳記）。

比喻：退貨時，店員一句「不行喔」跟遞給你一張寫明原因、代碼、時間的「退貨拒絕單」，資訊量差很多——後者才是「結構化資訊」。

### 程式碼：問題寫法 → 修好寫法

昨天（問題寫法，狀態碼永遠 200）：
```java
@ExceptionHandler(ResourceNotFoundException.class)
public String handleNotFound(ResourceNotFoundException ex) {
    return ex.getMessage();
}
```

今天（修好寫法，結構化內容 + 正確狀態碼）：
```java
public class ErrorResponse {
    private int status;
    private String message;
    private LocalDateTime timestamp;
    // constructor、getter 省略
}

@ExceptionHandler(ResourceNotFoundException.class)
public ResponseEntity<ErrorResponse> handleNotFound(ResourceNotFoundException ex) {
    ErrorResponse error = new ErrorResponse(
        HttpStatus.NOT_FOUND.value(),
        ex.getMessage(),
        LocalDateTime.now()
    );
    return new ResponseEntity<>(error, HttpStatus.NOT_FOUND);
}
```

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| ResponseEntity<T> | 回應實體 | 一個「包裝盒」，同時裝著 HTTP 狀態碼與回應內容（body），完整控制回傳給前端的東西。 |
| HttpStatus | HTTP 狀態碼列舉 | Spring 把常見狀態碼（如 404、500）包成好記的常數。 |
| DTO | 資料傳輸物件 | 單純用來裝資料、在不同層之間搬運的 class，通常只有欄位和取值方法。 |
| LocalDateTime | 日期時間物件 | Java 8 之後表示「日期＋時間」的標準寫法。 |
