## Spring Security 入門:認證與授權概念 · 第 2 步

### The Security Filter Chain: every request passes the guards first

**比喻**:進大樓要先過一排警衛——第一位驗證件(認證),第二位看你能不能進該樓層(授權),全過了才到辦公室(Controller)。任何一關擋下,Controller 完全不會被執行。

**重點**
1. 加入 `spring-boot-starter-security` 後,Filter Chain 自動啟用,所有 API 預設被鎖住(回 401)。
2. 認證與授權由鏈上不同的 Filter 負責,不寫在 Controller 裡,Controller 專心做業務邏輯。
3. 開發者透過 `SecurityFilterChain` 設定哪些路徑放行、哪些要登入。

```
Client request
   │
   ▼
[ Filter 1 ]  認證:你是誰
   │
   ▼
[ Filter 2 ]  授權:你能不能進
   │
   ▼
[ Controller ]
```

```java
@Configuration
public class SecurityConfig {

    @Bean
    SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http.authorizeHttpRequests(auth -> auth
            .requestMatchers("/public/**").permitAll()
            .anyRequest().authenticated()
        );
        return http.build();
    }
}
```

### 術語表
| 術語 | 中文 | 定義 |
|---|---|---|
| Filter | 過濾器 | 在請求抵達 Controller 前先執行的程式,可放行或擋下請求 |
| Filter Chain | 過濾器鏈 | 多個 Filter 依序排成一列執行 |
| SecurityFilterChain | 安全過濾器鏈設定 | 描述「哪些路徑要怎麼保護」的設定物件 |
| @Bean | Bean 標記 | 請 Spring 建立並管理該方法回傳的物件 |
| permitAll() | 全部放行 | 該路徑不需登入 |
| authenticated() | 需已認證 | 該路徑必須先通過認證 |
