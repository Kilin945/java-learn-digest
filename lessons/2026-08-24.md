## Spring Data JPA 與 Repository 介面 · 第 4 步

### 概念：Paging & Sorting with Pageable

查詢結果筆數很多時，不會一次全部撈出來，而是「分頁」拿資料，並可以指定排序方式。

- `Pageable`：分頁請求介面，代表「第幾頁、一頁幾筆、怎麼排序」。
- `PageRequest`：`Pageable` 的實作類別，用 `PageRequest.of(頁碼, 每頁筆數, 排序)` 建立。
- `Page<T>`：查詢結果容器，含這一頁的資料清單 + 總筆數/總頁數等資訊。
- `Sort`：排序條件物件，例如 `Sort.by("createdAt").descending()`。

只要在 Repository 方法最後多加一個 `Pageable` 型別的參數，Spring Data JPA 就會自動組出對應的 `LIMIT`/`OFFSET`/`ORDER BY`，不需要手寫分頁邏輯。

### 程式碼

```java
public interface MemberRepository extends JpaRepository<Member, Long> {

    Page<Member> findByNameContaining(String keyword, Pageable pageable);
}

// 使用端
Pageable pageable = PageRequest.of(0, 10, Sort.by("createdAt").descending());
Page<Member> result = memberRepository.findByNameContaining("王", pageable);

result.getContent();        // 這一頁的資料 (List<Member>)
result.getTotalElements();  // 符合條件的總筆數
result.getTotalPages();     // 總頁數
```

### 術語表

| 術語 | 定義 |
|---|---|
| Pageable | 分頁請求介面，描述頁碼、每頁筆數、排序方式 |
| PageRequest | Pageable 的具體實作，用 `.of()` 建立實例 |
| Page<T> | 分頁查詢結果容器，含資料 + 分頁統計資訊 |
| Sort | 排序條件物件，指定欄位與升冪/降冪 |
