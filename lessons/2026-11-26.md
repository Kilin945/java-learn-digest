## A6 第 3 篇 · 攔截器 vs Filter；@ControllerAdvice 統一處理例外

**題目：Spring MVC 一個請求從進到出的流程？**

### 題目在問什麼
- Filter：Servlet 規格的關卡，在 Spring 之前。
- 攔截器（Interceptor）：Spring MVC 的關卡，進出 Controller 方法前後。
- 統一處理例外：集中接例外，不用每個 Controller 寫 try/catch。
- 要答到：① 兩者各站哪一層 ② 差在哪 ③ 例外怎麼統一處理與它接不到什麼。

### 解題思路
1. 找 handler（第 1 篇）
2. 參數與回傳轉換（第 2 篇）
3. **排出 Filter 與攔截器在路徑上的位置（本篇）**
4. **比較兩者拿得到的資訊與適用情境（本篇）**
5. **@ControllerAdvice 站的位置與管不到的範圍（本篇）**

### 答案
Filter 站最外層、屬 Servlet 規格，不知道交給哪個 Controller 方法；攔截器在 Spring MVC 內，拿得到 handler。例外統一放 @ControllerAdvice 搭 @ExceptionHandler，但只接得到 DispatcherServlet 範圍內的。

```text
瀏覽器 → Filter → DispatcherServlet(查 HandlerMapping)
  → 攔截器 preHandle → Controller 方法
  → 攔截器 postHandle / afterCompletion → Filter 回程
例外：DispatcherServlet 內拋出 → @ControllerAdvice 接；Filter 內拋出 → 接不到
```

### 第 1 輪 · 釐清：HandlerInterceptor 三個方法各在什麼時間點跑？
```java
// 典型寫法（簡化）
public class LogInterceptor implements HandlerInterceptor {
    // 進 Controller 前；true 放行、false 擋下
    public boolean preHandle(HttpServletRequest req, HttpServletResponse res, Object handler) { return true; }
    // Controller 正常跑完、View 渲染前；Controller 拋例外不會進來
    public void postHandle(HttpServletRequest req, HttpServletResponse res, Object handler, ModelAndView mv) { }
    // 整個結束後（preHandle 回 true 就會來），適合收尾
    public void afterCompletion(HttpServletRequest req, HttpServletResponse res, Object handler, Exception ex) { }
}

@Configuration
public class WebConfig implements WebMvcConfigurer {
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new LogInterceptor()).addPathPatterns("/**");
    }
}
```

### 第 2 輪 · 追原因：為什麼 Filter 拿不到 Controller 方法的資訊，攔截器卻拿得到？
```java
// 典型寫法（簡化）
public class MyFilter implements Filter {
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {
        // 只有 Servlet 層資訊；DispatcherServlet 還沒跑、HandlerMapping 還沒查
        chain.doFilter(req, res);
    }
}
// 攔截器的 handler 是 DispatcherServlet 查完才給的：
// if (handler instanceof HandlerMethod hm) { hm.getMethod().getName(); }
// Filter：編碼、CORS、全域 log；攔截器：依 Controller 方法做權限、記錄
```

### 第 3 輪 · 挑戰假設：@ControllerAdvice 會接住所有例外嗎？
```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<Map<String, String>> handleBadRequest(IllegalArgumentException e) {
        return ResponseEntity.badRequest().body(Map.of("error", e.getMessage()));
    }
    @ExceptionHandler(Exception.class)
    public ResponseEntity<Map<String, String>> handleAll(Exception e) {
        return ResponseEntity.status(500).body(Map.of("error", "server error"));
    }
}
// 接得到：Controller、攔截器、參數轉換失敗
// 接不到：Filter 內拋的（變成 Tomcat 錯誤頁）
```

### 追問：攔截器和 Filter 差在哪？例外要統一處理放哪？
| | Filter | 攔截器 |
|---|---|---|
| 屬於 | Servlet 規格 | Spring MVC |
| 位置 | DispatcherServlet 之前 | DispatcherServlet 之後 |
| 知道 handler | 否 | 是 |
| 適合 | 編碼、CORS、全域 log | 權限判斷、記錄 |

例外統一處理放 @ControllerAdvice + @ExceptionHandler，只接得到 Spring 內部拋出的；Filter 炸掉它接不到。

### 為什麼要懂
上線後某種錯誤回 Tomcat 的 HTML 錯誤頁而不是統一 JSON，不知道 @ControllerAdvice 管不到 Filter 就會找錯地方。想依 Controller 方法做權限卻寫在 Filter，也會拿不到方法資訊。

### 結論
Filter 管 Servlet 層、攔截器管 Spring MVC 層，差別在能不能拿到 handler；@ControllerAdvice 只收 DispatcherServlet 裡面的例外。

### 術語表
| 術語 | 白話定義 |
|---|---|
| Filter | Servlet 規格的關卡，進 Spring 前先經過 |
| FilterChain | 多個 Filter 串成的鏈，呼叫 chain.doFilter 才放行 |
| HandlerInterceptor | Spring MVC 攔截器介面，三個方法 |
| handler | 要處理這個請求的 Controller 方法 |
| DispatcherServlet | Spring MVC 唯一入口 |
| @ControllerAdvice | 讓設定對所有 Controller 生效；@RestControllerAdvice 另加直接輸出 JSON |
| @ExceptionHandler | 指定某方法處理某種例外 |
