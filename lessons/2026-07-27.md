## application.yml 結構與設定優先序 · 第 5 步

### 概念：Profile-specific config（情境專屬設定）

不同使用場合（開發、測試、正式上線）常需要不同設定值。Spring Boot 讓你另外建立 `application-{profile}.yml`，只寫「跟預設值不同」的部分，其餘欄位沿用 `application.yml` 的預設值。

啟動時透過 `spring.profiles.active` 告訴 Spring Boot 要啟用哪個 profile，例如 `--spring.profiles.active=dev` 會讀取 `application-dev.yml` 並疊加（覆寫）在預設設定之上。

### 程式碼範例

```yaml
# application.yml（預設）
server:
  port: 8080
app:
  name: my-service

# application-dev.yml（開發環境覆寫）
server:
  port: 8081
```

```bash
java -jar app.jar --spring.profiles.active=dev
# 結果：app.name 仍是 my-service，server.port 變成 8081
```

### 本主題完整優先序（priority order）總結

命令列參數（command-line argument） > 環境變數（environment variable） > application-{profile}.yml > application.yml（預設）

越具體、越針對當下啟動情境的設定，優先權越高，可以覆寫（override）更通用、寫死在檔案裡的設定。

### 術語表

| 術語 | 定義 |
|---|---|
| Profile | 代表一種使用場合（開發、測試、上線等），可各自擁有專屬設定值 |
| application-{profile}.yml | 檔名帶場合名稱的設定檔，只需寫與預設不同的值 |
| spring.profiles.active | 指定目前要啟用的 Profile |
| Override（覆寫） | 用新值蓋掉舊值，未提及的欄位維持原值 |
| Relaxed binding（寬鬆綁定） | Spring Boot 自動把環境變數名稱（如 SERVER_PORT）對應到設定 key（如 server.port） |

### 主題總結（application.yml 結構與設定優先序，已完整涵蓋）

1. application.yml 用 YAML 縮排表示巢狀結構，最終對應到點記法 key（如 server.port）。
2. 設定優先序由高到低：命令列參數 > 環境變數 > application-{profile}.yml > application.yml。
3. 命令列參數與環境變數都能覆寫 yml 裡的值，環境變數靠寬鬆綁定自動對應。
4. Profile 讓不同環境（開發／上線）能各自套用專屬設定，而不需要複製整份設定檔。
