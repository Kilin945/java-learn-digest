## Spring Security 入門：認證與授權概念 · 第 4 步

### UserDetailsService: How Spring Finds Your User

Spring Security 不知道使用者資料存在哪裡（MySQL、Oracle…），所以要由你實作 `UserDetailsService` 這個介面，當作「查人窗口」。

比喻：飯店櫃檯（Spring Security）不認識客人，打電話給住客資料室（你的 UserDetailsService）查帳號與密碼雜湊。

- 合約只有一個方法：`loadUserByUsername(String username)`
- 回傳 `UserDetails`（帳號、密碼雜湊、角色）
- 找不到人 → 丟 `UsernameNotFoundException`

**登入流程**：送出帳號密碼 → Spring 呼叫 `loadUserByUsername` 取得 UserDetails → 用 `PasswordEncoder.matches()` 比對輸入密碼與雜湊 → 成功才算認證通過。比對密碼是 Spring 做的，你只負責查人。

```java
@Service
public class MyUserDetailsService implements UserDetailsService {

    private final UserRepository userRepository;

    public MyUserDetailsService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    @Override
    public UserDetails loadUserByUsername(String username) {
        AppUser u = userRepository.findByUsername(username)
            .orElseThrow(() -> new UsernameNotFoundException("找不到: " + username));

        return User.withUsername(u.getUsername())
            .password(u.getPasswordHash())  // DB 裡本來就是 BCrypt 雜湊
            .roles("USER")                  // 先寫死，之後再教角色
            .build();
    }
}
```

**一句話**：UserDetailsService 是交給 Spring Security 的「查人窗口」：給帳號、回 UserDetails（含密碼雜湊）；比密碼是 Spring 的事。

### 術語表

| 術語 | 中文 | 說明 |
|---|---|---|
| interface | 介面 | 規定必須有哪些方法的合約，由類別實作內容 |
| UserDetailsService | 使用者查詢服務 | Spring Security 介面，用帳號找出使用者 |
| UserDetails | 使用者詳細資料 | Spring Security 認得的使用者格式 |
| UsernameNotFoundException | 找不到使用者例外 | 查不到人時丟的錯誤，登入判定失敗 |
| builder | 建造者 | 逐步設定欄位、最後 build() 產出物件的寫法 |
