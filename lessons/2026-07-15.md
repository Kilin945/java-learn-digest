## Profiles：dev / prod 用不同設定 · 第 4 步

### 概念：用環境變數啟用 Profile（正式上線的做法）

前面幾步學的 `spring.profiles.active` 是寫死在 `application.properties`，或用命令列參數 `--spring.profiles.active=xxx` 覆蓋。但實際公司部署到不同機器時，最常見的做法是完全不改 jar 檔，改用**環境變數** `SPRING_PROFILES_ACTIVE` 在啟動當下告訴程式現在是哪個環境。

比喻：`spring.profiles.active` 就像貼在披薩盒上的標籤貼紙。寫死在設定檔裡，等於把標籤印死在配方紙上，換口味要重印。用環境變數，等於「出貨當下才貼標籤」——同一份程式碼、同一個 jar 檔，丟到不同機器就能變成不同環境。

也可以用逗號同時啟用多個 profile，例如 `dev,mail`，兩組專屬設定會一起疊加套用。

```bash
# 方法一：先設環境變數，再啟動
export SPRING_PROFILES_ACTIVE=prod
java -jar myapp.jar

# 方法二：Docker 容器啟動時直接帶入（最常見）
docker run -e SPRING_PROFILES_ACTIVE=prod myapp-image

# 同時啟用多個 profile
java -jar myapp.jar --spring.profiles.active=prod,mail
```

**本主題到此告一段落**：我們學了（1）application-{profile}.properties 疊加設定檔、（2）spring.profiles.active 啟用 profile 的幾種方式、（3）@Profile 註解讓同一介面依環境切換實作、（4）正式上線時用環境變數啟用 profile、以及可同時啟用多個 profile。核心觀念是：**環境的切換交給設定/環境變數決定，程式碼永遠不用因為換環境而改動。**

### 術語表

| 英文 | 中文 | 定義 |
|---|---|---|
| Environment Variable | 環境變數 | 作業系統或容器層級記住的設定值，程式啟動時可讀取，不用寫在程式碼或設定檔裡 |
| SPRING_PROFILES_ACTIVE | Profile 啟用變數 | 環境變數版的 spring.profiles.active，適合部署到不同機器時使用 |
| Comma-separated profiles | 逗號分隔多重 profile | 一次啟用多個 profile，對應的專屬設定全部疊加套用 |
