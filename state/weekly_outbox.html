這週從 Entity 關聯一路走到 @Transactional，資訊量不小。花幾分鐘試著先自己回想再看解答，記憶會扎實很多。

🧠 本週回想題

  1. @ManyToOne 通常標在關聯的哪一方（「一」還是「多」）？搭配的 @JoinColumn 又是用來做什麼的？
  2. 如果 Order 有很多 OrderItem，你想在 Order 這邊也能直接拿到它的 OrderItem 清單，該怎麼寫？這個關聯會不會在資料庫多一個外鍵？
  3. 什麼是 Derived Query Method（衍生查詢方法）？寫一個範例：用 username 查使用者的方法名稱該怎麼命名？
  4. 如果要用衍生查詢同時依 username 和 status 查詢，方法名稱怎麼寫？方法參數的順序需要注意什麼？
  5. 承上題，如果條件變成 5 個欄位、還要 JOIN 另一張表，你會怎麼選擇（繼續用衍生查詢，還是換方式）？換的話該怎麼寫？
  6. @Query 搭配 @Param 是怎麼運作的？請寫一個簡單的 JPQL 範例，包含一個 : 佔位符。
  7. 綜合題：判斷「用衍生查詢還是 @Query」的原則是什麼？請用一兩句話說明你的判斷依據。
  8. @Transactional 標在方法上代表什麼？如果方法中途丟出例外，資料庫會發生什麼事？

—— 解答 ——

  1. 標在「多」的那一方。@JoinColumn 用來指定這個關聯在資料庫裡對應的外鍵欄位名稱。
  2. 在 Order（「一」的那方）用 @OneToMany(mappedBy = "order")（假設 OrderItem 裡的欄位叫 order）。這只是唯讀清單，不會多建外鍵，外鍵已經由 OrderItem 那邊的 @ManyToOne 維護。
  3. 靠方法名稱的命名規則讓 Spring Data JPA 自動翻譯成 SQL，不用手寫查詢。範例：findByUsername(String username)。
  4. findByUsernameAndStatus(String username, String status)。參數順序要跟方法名稱裡欄位出現的順序一致。
  5. 條件太多、需要 JOIN 時改用 @Query 寫 JPQL，例如：@Query("SELECT o FROM Order o JOIN o.items i WHERE ...") 搭配 @Param。
  6. @Query 直接寫 JPQL 查詢語法，@Param 把方法參數對應到 JPQL 裡的 : 佔位符。範例：
    @Query("SELECT u FROM User u WHERE u.username = :username")
    User findByUsername(@Param("username") String username);
  7. 條件簡單（1~2 個）用衍生查詢方法名稱最清楚易讀；條件變多（3 個以上）、需要 JOIN 或聚合、或方法名稱長到難理解，就改用 @Query + JPQL + @Param 較好維護。
  8. 代表該方法變成一個交易邊界：方法正常結束會自動 commit；若丟出例外，會自動 rollback，確保一組資料庫操作要嘛全部成功、要嘛全部復原。
