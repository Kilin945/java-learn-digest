📘 每週回顧 · Java / Spring Boot · 2026-07-31

這週你把兩大主題都摸過一輪了：application.yml 設定優先序，還有內嵌 Tomcat 與 main() 啟動流程。 下面這幾題刻意把兩邊混在一起問，幫你把知識串成一條線，而不是分開的小碎片。先自己想過一遍再往下看解答會更有效果 💪

  1. Spring Boot 啟動一個 Java 應用程式，預設情況下不用另外裝任何東西，內建的 web 伺服器是什麼？它被放在哪裡？
  2. 主 class 上要貼哪個 annotation，main() 裡又要呼叫哪一行程式碼，才算是真正啟動了整個 Spring Boot 應用程式（含內嵌伺服器）？
  3. 啟動 console 印出「Tomcat started on port(s): 8080」和「Started XxxApplication in X seconds」代表什麼？如果看到「Port 8080 was already in use」呢？
  4. 假設 8080 port 被佔用導致啟動失敗，你會在 application.properties 裡加哪一行設定來解決？這行設定跟 main() → SpringApplication.run() → 讀設定 → 啟動內嵌 Tomcat 這條流程有什麼關係？
  5. 同樣是改 port，如果你想「不改任何設定檔」、只在啟動指令上臨時多打一個參數把 port 換成 9090，你會怎麼下這個 command-line argument？它跟 application.yml 裡寫的 server.port 相比，誰會贏？
  6. 如果你改用設定環境變數 SERVER_PORT=9090 的方式呢？Spring Boot 是靠什麼機制自動把它對應到 server.port 這個設定名稱的？
  7. 現在把命令列參數、環境變數、application-{profile}.yml、application.yml（預設）四種來源全部混在一起考慮，完整的優先序（誰蓋過誰）是什麼？要啟用某個 profile（例如 dev），要靠哪個設定值指定？

—— 解答 ——

  1. 內嵌 Tomcat（embedded Tomcat）。它被打包進應用程式的 jar 檔裡，不用另外安裝或設定外部 Tomcat，預設用 8080 port。
  2. 主 class 貼 @SpringBootApplication，main() 裡呼叫 SpringApplication.run(該class, args)，這一行就是啟動整個應用程式（含內嵌 Tomcat）的關鍵程式碼。
  3. 這兩行代表應用程式已經成功啟動；「Port 8080 was already in use」則代表該 port 被佔用，啟動失敗（failed to start）。
  4. 加上 server.port=8081（或其他未被佔用的 port）。這正是完整啟動流程的最後一環：main() 呼叫 SpringApplication.run() → 讀取設定（讀到 server.port）→ 用這個 port 啟動內嵌 Tomcat。
  5. 啟動指令加上 --server.port=9090。這是設定優先序裡最高的一層：命令列參數（command-line argument）會覆寫（override）application.yml 裡寫的值。
  6. Spring Boot 靠「寬鬆綁定（relaxed binding）」自動把環境變數 SERVER_PORT 對應到設定名稱 server.port，不用另外寫轉換規則。
  7. 完整優先序：命令列參數 > 環境變數 > application-{profile}.yml > application.yml（預設）。要啟用某個 profile，是靠 spring.profiles.active（例如設成 dev）來指定。
