這週你從測試切片（test slice）一路走到 Actuator 監控，今天又踏進設定外部化的第一步。 在往下一週前，先靠「主動回想」（active recall）把這些串起來——不用翻筆記，先自己想，想不出來再看解答。

🧠 本週回想題

  1. 在 @DataJpaTest 裡，如果你只呼叫 entityManager.persist()，接著馬上呼叫 Repository 的查詢方法，可能會發生什麼問題？為什麼？
  2. AAA（Arrange-Act-Assert）是哪三個階段？各自對應測試方法裡的哪個動作？
  3. @DataJpaTest、@WebMvcTest、@JsonTest 都是 test slice 家族的成員，它們共同的設計邏輯是什麼？
  4. 預設打 /actuator/health 有回應，但打 /actuator/metrics 卻沒有東西，要加哪一行設定才能打開更多端點？
  5. 承上題，就算打開了 /actuator/metrics，看到的也只是一串名稱清單，要怎麼做才能看到某個指標的實際數值？availableTags 的作用又是什麼？
  6. 今天學的 @Value("${'$'}{key}") 讀取 application.properties，跟本週稍早的 management.endpoints.web.exposure.include 設定，本質上在解決同一類什麼問題？
  7. 如果要寫一個 @DataJpaTest，測試「先塞一筆假資料、再驗證 Repository 查得到」，你會怎麼組合這週學到的 TestEntityManager 方法與 AAA 結構寫出這個測試？

—— 解答 ——

  1. persist() 只把資料放進 Persistence Context 暫存區，還沒真的寫進資料庫；緊接著查詢可能讀到暫存區裡的物件而「測試通過」，卻掩蓋了資料其實沒落地的問題（假陽性）。要用 persistAndFlush() 才能確保真的寫進去。
  2. Arrange（準備）＝建立測試資料與情境；Act（執行）＝呼叫被測方法；Assert（驗證）＝檢查結果是否符合預期。
  3. 「只蓋你要測的那層樓，其他換假貨」——每個 test slice 只載入該層需要的元件（例如 @DataJpaTest 只載入 JPA 相關 bean），其餘（Controller、Service 等）不啟動或用假的，讓測試更快、更聚焦。
  4. 在 application.properties 加上 management.endpoints.web.exposure.include=health,info,metrics。
  5. 要打 /actuator/metrics/{名稱}（例如 /actuator/metrics/jvm.memory.used）才能看到實際數值與 baseUnit；availableTags 則列出可以用來篩選這個指標的維度（例如依 area、id 篩選）。
  6. 兩者都是「把會變動的東西抽離程式碼，改成外部設定」——一個是應用參數（@Value），一個是監控端點的開關；共同精神是換設定不用改程式碼、不用重新編譯。
  7. 在 Arrange 階段用 entityManager.persistAndFlush(entity) 塞入假資料並確保真的落地；Act 階段呼叫 Repository 的查詢方法；Assert 階段驗證回傳結果是否包含剛剛塞入的那筆資料。
