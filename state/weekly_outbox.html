本週你學了 OOP 設計（abstract class vs interface）、並行（deadlock）、Spring 核心（IoC / DI），還有一組手寫排序的 null 處理題。先別翻到最後，每題在心裡（或寫下來）答一遍，再對解答。
🧠 回想題

Q1（淺）　interface 是「約定什麼」？為什麼一個類別可以 implements 很多個 interface，卻只能 extends 一個 class？

Q2（淺）　IoC 與 DI 各是什麼？兩者的關係是什麼？

Q3（中）　電文解析有好幾種格式，解析流程骨架相同、只有欄位切法不同。你會選 abstract class 還是 interface？為什麼 default method 取代不了 abstract class？

Q4（中）　Spring 裡建構子注入為什麼比欄位注入好？請至少說出三點。

Q5（中）　deadlock 發生的四個必要條件是什麼？實務上最常打破哪一個、怎麼打破？

Q6（中）　線上服務卡住，你懷疑是 deadlock，要怎麼確認？thread dump 裡要找什麼關鍵字？

Q7（中深）　寫 int key = arr[i] 時，如果 arr 是 Integer[] 而元素是 null，會發生什麼事？為什麼上週的插入排序題不用在迴圈裡判斷 null？

Q8（深）　題目要求「null 放前面」，相較於「null 放後面」，三個步驟（搬移、排序範圍、補 null）各要怎麼改？正式專案為什麼不手寫，而改用什麼？

—— 解答 ——

A1　interface 只約定「能做什麼」（方法簽章），沒有內容、沒有狀態，所以多實作不會衝突、可以 implements 很多個。class 帶有狀態與實作，繼承多個會有衝突（菱形問題），所以只能 extends 一個。呼叫端只認約定，不在乎誰實作。

A2　IoC（Inversion of Control，控制反轉）：物件的建立與組裝交給 Spring 容器，不是自己 new。DI（Dependency Injection，依賴注入）：容器把依賴注入進來。DI 是實現 IoC 的具體手法。

A3　選 abstract class：各實作之間重複多（解析流程骨架），把共用的流程與狀態放在父類別，子類別只填差異（template method）。default method 沒有狀態、沒有建構子，也不具備單一繼承的語意，所以取代不了。若只是約定行為、實作彼此無關，才用 interface。

A4　①依賴寫在建構子簽章上，一眼看得出需要什麼；②欄位可宣告 final，不可變；③測試時可以自己 new 並傳入 mock，不需要 Spring 容器或反射。

A5　互斥、持有並等待、不可搶奪、循環等待，四個同時成立才會死結。實務上打破「循環等待」：所有執行緒用固定的上鎖順序；輔以 tryLock 加逾時，拿不到就放掉已持有的鎖。

A6　抓 thread dump（例如 jstack <pid> 或 jcmd <pid> Thread.print），搜尋 Found one Java-level deadlock，下面會列出互相等待的執行緒與鎖。

A7　null 自動拆箱（呼叫 intValue()）會丟 NPE。上週的做法是排序前先用 arr[n++] = v 把非 null 原地往前搬，讓前 n 格保證非 null；插入排序只跑 [0, n)，所以不需要 null 判斷。

A8　①改成從尾端往前搬非 null；②排序範圍改成 [k, length)（k 為 null 的個數）；③補前 k 格為 null。排序邏輯本身不變。正式專案用 Arrays.sort 配 Comparator.nullsFirst / nullsLast，不手寫只是題目限制。
