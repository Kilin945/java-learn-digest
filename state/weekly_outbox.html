本週走過的路

這週你把「設定外部化與機密管理」學完（環境變數、Profiles、@ConfigurationProperties），接著開始「Logging 與結構化日誌」（SLF4J、log 等級、例外記錄、MDC）。下面 7 題先自己想一遍，再往下看解答。

🧠 回想題

Q1. 為什麼不要把資料庫密碼直接寫進 application.properties？改用環境變數 DB_PASSWORD 之後，程式裡的 @Value("${db.password}") 需要改嗎？為什麼？

Q2. 你有 application-dev.properties 和 application-prod.properties，要怎麼指定現在用哪一份？密碼該放在 profile 檔案裡嗎？

Q3. 相較於一堆零散的 @Value，@ConfigurationProperties(prefix="db") 的設定類別有什麼好處？還需要搭配什麼註解才會啟用？

Q4. 為什麼要用 SLF4J 的 Logger 取代 System.out.println？下面這行有什麼可以改進的地方？
log.info("user " + id + " login at " + time);

Q5. 正式環境的 log 太多，你只想讓某個套件（例如 com.example.service）只輸出 WARN 以上，要怎麼做？需要改程式碼或重新部署嗎？

Q6. 下面兩種寫法，哪一種能保留完整 stack trace？為什麼？
(a) log.error("付款失敗: " + e.getMessage());
(b) log.error("付款失敗 orderId={}", orderId, e);

Q7.（跨主題）你想讓同一個請求的每一行 log 都帶同一個 requestId。請說明：在哪裡放進去、pattern 怎麼寫、結束時要做什麼？如果忘了這一步，在 thread pool 環境下會發生什麼事？

—— 解答 ——

A1. 寫進 properties 會被 git 記錄，密碼就外洩到版本歷史。改用環境變數後，Spring Boot 的寬鬆綁定（relaxed binding）會把 DB_PASSWORD 自動對應到 db.password，所以 @Value 完全不用改。

A2. 用 spring.profiles.active=dev（或 prod）切換。密碼不放 profile 檔，仍交給環境變數處理，因為 profile 檔也會進 git。

A3. 把相關設定打包成一個型別安全（type-safe）的類別，例如 DbProperties，集中管理、好維護、有型別檢查。要搭配 @EnableConfigurationProperties 啟用。密碼欄位一樣由環境變數提供。

A4. SLF4J Logger 有等級、可設定輸出位置與格式，println 都做不到。字串拼接應改用 {} 佔位符：log.info("user {} login at {}", id, time);，更乾淨，也避免不必要的字串拼接。

A5. 在 application.properties 加 logging.level.com.example.service=WARN。不用改程式碼，也不用重新部署（改設定即可）。等級由輕到重：TRACE → DEBUG → INFO → WARN → ERROR。

A6. 是 (b)。把 Exception 物件放在參數的最後一個，SLF4J 就會自動印出完整 stack trace；(a) 只留 e.getMessage()，會丟掉出錯位置等關鍵資訊。

A7. 在 Filter 裡請求進來時 MDC.put("requestId", ...)；log pattern 用 %X{requestId}；結束時必須在 finally 裡 MDC.clear()。MDC 是綁在 thread 上的，thread pool 會重複使用 thread，忘了清除，下一個請求可能沿用到上一個請求的 requestId，log 會被錯誤歸類。
