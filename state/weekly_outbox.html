這週你從「Spring 怎麼包住方法」一路走到「請求怎麼進來」，最後碰了 Java 序列化。先別翻解答，每題在腦中（或紙上）講出答案，再對照信末。

📝 回想題

Q1（淺）　Spring 的 @Transactional、@Secured 是怎麼「生效」的？用「替身（proxy）」這個詞說一遍：替身在真方法的前後做了什麼？

Q2　同一個 class 裡，方法 a() 呼叫自己的 b()，而 b() 標了 @Transactional，為什麼交易沒開？你可以用哪個方法在執行時驗證？

Q3　下面這段，資料庫最後是 commit 還是 rollback？為什麼？如果要讓它 rollback，有哪兩種改法？
@Transactional public void save() { try { repo.save(x); throw new RuntimeException(); } catch (Exception e) { log.error("fail", e); } }

Q4　方法丟出 IOException（checked exception），@Transactional 預設會 commit 還是 rollback？要怎麼改？另外，private 方法標 @Transactional 為什麼沒用？

Q5　一個 POST /orders 請求進來，依序經過哪幾個角色才到你的 Controller 方法？如果網址查不到、或網址對但 HTTP 方法不對，各回什麼狀態碼？

Q6　@RequestBody 與 @RestController 背後都用了什麼元件？請求的 Content-Type 不對、JSON 格式壞掉，各回幾號錯誤？如果忘了寫 @RequestBody，會發生什麼事？

Q7　Filter 與 Interceptor 差在哪一層？哪一個拿得到 handler？如果例外是在 Filter 裡丟出來的，@ControllerAdvice 接得到嗎？

Q8（深）　class Order implements Serializable { private Customer customer; }，其中 Customer 沒有 implements Serializable。呼叫 writeObject(order) 會怎樣？用哪兩個 API 完成「寫出去、讀回來」？再串起來想：Q2 的 proxy 概念跟這題有沒有關聯？（開放題，沒有標準答案，想想看就好。）

—— 解答 ——

A1　Spring 產生一個長得跟原物件一樣的 proxy，呼叫時先經過 proxy：在真方法之前開交易／檢查權限，之後依結果 commit／rollback。註解只是「請替我包」的標記，真正的工作由 proxy 做。

A2　同類內部呼叫是 this.b()，this 是真物件而不是 proxy，所以 proxy 沒機會開交易，b() 上的註解被略過（self-invocation）。驗證：在 b() 裡印 TransactionSynchronizationManager.isActualTransactionActive()，對照從外部呼叫與內部呼叫的結果。

A3　commit。例外被自己 try-catch 吃掉了，沒穿出方法，proxy 看到的是「正常結束」。改法：(1) 在 catch 裡重新拋出（throw e 或包成 RuntimeException）；(2) 呼叫 TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()。

A4　預設 commit，只有 RuntimeException 與 Error 才 rollback。解法：@Transactional(rollbackFor = Exception.class)。private（以及 final）方法 proxy 攔不到，所以註解無效；改成 public（非 final）。

A5　請求 → DispatcherServlet（Spring MVC 唯一入口）→ 問 HandlerMapping（啟動時由 @RequestMapping 系列註解建好的「HTTP 方法＋網址 → Controller 方法」對照表）→ 查到才呼叫你的 Controller 方法。網址查不到 404；網址對但方法不對 405。

A6　都靠 HttpMessageConverter（預設 JSON 用 Jackson）：@RequestBody 把 JSON 讀成物件（進），@ResponseBody／@RestController 把回傳物件寫成 JSON（出）。Content-Type 不對 415；JSON 壞掉 400。忘了 @RequestBody 會被當成 @ModelAttribute，物件欄位全是 null。

A7　Filter 在 Servlet 層、DispatcherServlet 之前，不知道 handler；Interceptor 在 Spring MVC 層，拿得到 handler，適合權限與記錄。Filter 裡丟出的例外在 DispatcherServlet 範圍之外，@ControllerAdvice 接不到。

A8　執行時丟 NotSerializableException（編譯不會報錯）；類別以及欄位裡的每個物件都要 implements Serializable。寫出用 ObjectOutputStream.writeObject，讀回用 ObjectInputStream.readObject。開放題的關聯：兩者都是「物件在記憶體中的樣子」與「外界看到的形式」之間的轉換，也都靠一個標記或約定（Serializable／註解）讓框架知道怎麼處理。

答對幾題不重要，能用自己的話講出「為什麼」才算真的學會 🌱
