這週把 @RestController 家族 跟 接收資料的三種方式 兩個主題都學完了。趁記憶還熱，用下面幾題把這週的東西串起來，別急著看解答，先自己想一遍再對照 👇
🧠 回想題
1. 一個類別貼了 @RestController，它的方法回傳一個 Java 物件，這個物件最後會變成什麼？跟一般 MVC 的 @Controller 差在哪裡？
2. @RequestMapping(value = "/hello", method = RequestMethod.GET) 這句話裡，value 跟 method 分別在告訴 Spring 什麼？
3. 如果要「新增一筆訂單」，你會用 @GetMapping、@PostMapping 還是 @PutMapping？為什麼不能用另外兩個？
4. class 上寫 @RequestMapping("/api/users")，方法上寫 @GetMapping("/{id}")，最後 client 要打的完整網址是什麼？
5. GET /users/3 這個請求，如果方法簽名是 getUser(@PathVariable Long id)，Spring 是怎麼知道 id 要填 3 的？
6. @PathVariable 跟 @RequestParam 都能從網址拿值，那它們兩個的網址寫法跟使用情境有什麼不同？@RequestParam 的 defaultValue 是用來解決什麼問題？
7. 前端送一包 JSON（例如 {"name":"Amy","age":20}）當作 request body，方法參數要怎麼寫才能自動接成一個 User 物件？
8.（綜合題）設計一個 API：更新某使用者第幾頁的某筆訂單，網址長這樣 PUT /users/{userId}/orders?page=1，body 帶更新後的訂單內容。請說出這裡的 userId、page、body 分別該用哪個標籤接？
—— 解答 ——
1. 回傳值會直接變成 HTTP response body（通常轉成 JSON）送回去，不會經過 View 樣板排版。@Controller 預設回傳值是要去找對應的畫面（View）。
2. value 是網址路徑（這個方法對應哪個路徑），method 是請求方式（GET/POST/PUT/DELETE，這個方法要處理哪種動作）。
3. 用 @PostMapping，因為「新增」對應 POST 動作；GET 是查詢、PUT 是更新既有資料，語意上都不是「新增」。
4. GET /api/users/{id}，class 上的路徑是共同前綴，方法上的路徑接在後面，兩者合併才是完整網址。
5. 網址範本裡的 {id} 是一個會變動的占位，Spring 看到方法參數上有 @PathVariable 且名字對上 id，就把網址裡實際的值（3）塞進去。
6. @PathVariable 抓的是網址路徑本身的一部分（如 /users/3 裡的 3），通常代表「這是誰/哪一個」；@RequestParam 抓的是 ? 後面 key=value 的查詢參數（如 ?page=2），通常是可有可無的篩選/分頁條件。defaultValue 是用來處理「client 沒帶這個查詢參數」的情況，給一個預設值，避免沒傳就出錯或變成 null。
7. createUser(@RequestBody User user)。Spring 會自動把 request body 的 JSON 轉成對應的 Java 物件（DTO）。
8. userId 是路徑的一部分 → @PathVariable；page 是 ? 後面的查詢參數 → @RequestParam；訂單內容是整包結構化資料放在 body → @RequestBody。三者合起來就是這週學的「REST API 接收資料的完整方式」。
