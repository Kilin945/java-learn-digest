這週你把 MockMvc 測 Controller 的完整流程走了一遍，從基本設定到驗證呼叫參數。先自己回想，答案在信末。
🧠 本週回想題
1. @WebMvcTest 和 @SpringBootTest 有什麼不同？為什麼測 Controller 通常選 @WebMvcTest？
2. mockMvc.perform(get("/api/users")) 之後，要怎麼斷言回應狀態碼是 200？
3. 如果只想檢查 JSON 回應裡「某一個欄位」的值，該用 content().string() 還是 jsonPath()？為什麼？
4. @WebMvcTest 環境下沒有真正的 Service bean，這會造成什麼問題？要怎麼解決？
5. 測試一個 POST /api/users 的 Controller，Java 物件要怎麼轉成 JSON 塞進 request body？需要哪個 annotation 和哪個方法？
6. 除了確認回應內容對不對，要怎麼確認 Controller 真的呼叫到 Service、而且參數正確？這行程式碼要寫在 perform 前面還是後面？
7.（綜合題）假設你要測 POST /api/orders，Controller 呼叫 OrderService.create(order) 並回傳建立好的訂單 JSON。請說出完整測試會用到的工具／annotation（至少 5 個），並排出大致使用順序。
—— 解答 ——
1. @WebMvcTest 只載入 Web 層相關元件（Controller、Filter 等），不啟動整個 Spring context，是一種 slice test（只測一部分）；@SpringBootTest 會載入整個應用程式的 context，較重、較慢。測 Controller 只需驗證 HTTP 層邏輯，不需要真正跑起 Service/Repository，所以用 @WebMvcTest 比較快。
2. .andExpect(status().isOk())。
3. 用 jsonPath("$.欄位").value(...)。content().string() 是整包字串死板比對，多一個空白或欄位順序不同就會失敗；jsonPath 可以只鎖定要驗證的欄位，更彈性也更好除錯。
4. Controller 注入的 Service 會是 null，一呼叫就丟 NullPointerException。解法是用 @MockitoBean 塞一個假的 Service 進測試環境，再用 when(...).thenReturn(...) 指定它被呼叫時要回傳什麼。
5. 先用 ObjectMapper.writeValueAsString(物件) 把 Java 物件轉成 JSON 字串，再用 .contentType(MediaType.APPLICATION_JSON).content(json字串) 帶進 perform(post("/路徑")...)。
6. 用 verify(mockService).方法名(參數)。這行要寫在 mockMvc.perform(...) 之後——要先讓請求真正跑過，才有呼叫紀錄可以驗證。
7. 大致順序：
① @WebMvcTest(OrderController.class) 標註測試類別，只載入 Web 層
② @MockitoBean 塞一個假的 OrderService
③ when(orderService.create(any())).thenReturn(建立好的訂單) 設定假資料
④ ObjectMapper.writeValueAsString(order) 把要送出的訂單轉成 JSON
⑤ mockMvc.perform(post("/api/orders").contentType(MediaType.APPLICATION_JSON).content(json)) 送出請求
⑥ .andExpect(status().isOk())、.andExpect(jsonPath("$.欄位").value(...)) 驗證回應
⑦ verify(orderService).create(...) 確認 Service 真的被呼叫、參數正確
