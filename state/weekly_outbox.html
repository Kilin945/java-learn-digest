這週你走過三個主題：Spring Boot 的外圍與自動配置、HashMap／hashCode／equals、JVM 記憶體與 OOM。先不要往下看解答，每題試著用自己的話回答，答不出來的就是今天最值得複習的地方。

🧠 回想題（由淺入深）

Q1. Spring MVC 和 Spring Boot 的關係是什麼？Controller 的寫法在傳統 WAR＋外部 Tomcat 與 Boot 之間有差嗎？

Q2. @SpringBootApplication、starter、內嵌 Tomcat 各自取代了傳統做法裡的哪一塊？

Q3. 自動配置裡的 @ConditionalOnClass 與 @ConditionalOnMissingBean 各自判斷什麼？為什麼你自己定義的 Bean 永遠優先？

Q4. HashMap 的 get(key) 是怎麼找到東西的？如果只覆寫 equals 沒覆寫 hashCode，會出現什麼 bug？

Q5. 把物件放進 HashSet 之後，修改了參與 hashCode 的欄位，再呼叫 contains 會怎樣？為什麼？該怎麼設計或處理才安全？

Q6. 說出 heap、stack、Metaspace 各放什麼。Object o = new Object(); 這行裡，o 和那個物件各在哪？

Q7. 舉出三種常見造成 heap OOM 的寫法，並說明為什麼 GC 救不了它們。

Q8. 線上發生 OOM，你要怎麼事先準備、事後調查？Metaspace OOM 與 heap OOM 的成因與判讀有什麼差別？（串聯題：想想第 5 題的「孤兒物件」與這題的 GC Root 有沒有關係。）

—— 解答 ——

A1. Spring MVC 是 web 框架本體，Boot 是外面的腳手架（設定、相依、啟動方式）。Controller 的寫法（@RestController、@GetMapping 等）兩邊完全相同。

A2. @SpringBootApplication 取代 web.xml／XML 設定；starter 把一組相依與版本打包管好；內嵌 Tomcat 讓 jar 直接 java -jar 跑，不用再打 WAR 丟外部 Tomcat。

A3. @ConditionalOnClass：classpath 有該依賴才啟用；@ConditionalOnMissingBean：你沒定義同類 Bean 才幫你建。自動設定排在你的設定之後才判斷，所以你定義了它就退讓。

A4. 先用 hashCode 算出桶（bucket），再在桶內用 equals 比對。只覆寫 equals 會讓「內容相同」的物件算出不同 hashCode、進不同桶，結果 get 查不到、Set 去不了重。規則：equals 相等 ⇒ hashCode 必須相同。

A5. 找不到（false）。hashCode 只在放入時算一次決定桶子，改欄位後物件不會搬家，但之後查詢會用新 hashCode 走去別的桶，contains／get／remove 都失敗，物件變孤兒。解法：hashCode 只用不會變的欄位（如 id）；真的要改就先 remove 再 add。

A6. heap：物件本體，全執行緒共用、由 GC 回收；stack：每個執行緒各自的區域變數與方法呼叫，方法結束就消失；Metaspace：class 的結構資訊。o（參考變數）在 stack，new Object() 的物件在 heap。

A7. ① static Map 一直塞不清；② 沒上限的快取；③ 沒關的串流／連線。共同點：GC 從 GC Root 仍然走得到它們，被視為「還在用」，所以不會回收。

A8. 事先加 -XX:+HeapDumpOnOutOfMemoryError 與 -XX:HeapDumpPath=... 留現場；事後用 MAT 看 Dominator Tree（誰佔最多）與 Path to GC Roots（誰抓著不放）。先看 log 錯誤訊息判斷哪一區爆：heap OOM 是物件累積；Metaspace OOM 是類別（ClassLoader）累積。串聯：第 5 題的孤兒物件還被 Set 抓著，就是「GC Root 走得到、卻沒人在用」的一種，長期累積就會走向 heap OOM。
