📘 每週回顧 · Java / Spring Boot · 2026-07-24

這週從「Spring Boot 為什麼自動組態」一路教到「starter-web 帶了哪三份禮物」，再到「application.yml 怎麼設定」。以下用回想題把整週串起來，建議先自己想過一輪再看解答 👇

🧠 本週回想題

1. application.yml 裡如果你這樣寫：

server:
  port: 8081

這段設定最終會被 Spring Boot 拼成什麼樣的 dot notation（點記法）？程式讀取時實際用的名字是什麼？

2. application.yml 這個檔案應該放在專案的哪個路徑底下？它用什麼方式（縮排 or 括號）來表示巢狀結構？

3. 你加了一行 spring-boot-starter-web 依賴，完全沒寫任何伺服器設定，程式執行後卻能直接處理 HTTP 請求——這是因為這包 starter 內建了什麼？

4. 當瀏覽器打到 /hello 這個網址時，是誰（哪個元件）負責接住這個請求，再依照 @RestController 和 @GetMapping 的標籤，轉接到你寫的方法上？

5. 你的 Controller 方法回傳了一個 Java 物件（例如 User），前端收到的卻是 JSON 字串。這中間是哪個函式庫、在背後幫你做了轉換？

6. 綜合第 3~5 題：請用一句話說明 spring-boot-starter-web 這一行依賴，總共幫你打包好了哪三大禮物？

7. 進階挑戰：假設 classpath 上根本沒有 Tomcat 相關的類別，Spring Boot 的自動組態機制（AutoConfiguration.imports + @ConditionalOnClass）會怎麼處理「內建 Tomcat 這個自動組態類別」？為什麼即使候選清單裡列了它，最後也不會真的套用？

—— 解答 ——

1. 會拼成 server.port。縮排的巢狀結構最終都會攤平成一串用 . 連接的完整名字，這就是程式實際讀取設定時用的 key。

2. 放在 src/main/resources 底下。用縮排（indentation）表示 key 之間的巢狀（nested）關係，同一層級的縮排要對齊。

3. 因為 spring-boot-starter-web 內建了一個小型 Tomcat（網頁伺服器），程式一執行就自動啟動，不用自己另外安裝或設定伺服器。

4. 是 DispatcherServlet（可以想成「總機」）。它先接住所有請求，再依照 @RestController／@GetMapping 的標籤，把請求轉接到對應的方法，這整套機制就是 Spring MVC。

5. 是 Jackson。它會自動把回傳的 Java 物件轉換成 JSON 格式，完全不用自己寫轉換程式碼。

6. 三大禮物：① Tomcat 伺服器（不用自己裝）② Spring MVC + DispatcherServlet（自動轉接請求到你的方法）③ Jackson（自動把物件轉成 JSON）。

7. 不會套用。Spring Boot 會用 @ConditionalOnClass 去檢查 classpath 上有沒有對應的類別，AutoConfiguration.imports 裡列出的只是「候選」清單；如果 classpath 上根本沒有 Tomcat 的類別，這個條件檢查就會失敗，這個自動組態類別就會被跳過，不會真的生效。這就是自動組態「先列候選、再逐一檢查條件」的完整運作方式。
