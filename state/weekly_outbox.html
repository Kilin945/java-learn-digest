這週你走過三個主題：abstract class vs interface、死結（deadlock）、Spring IoC / DI。先不要往下看解答，每題自己在腦中（或紙上）回答一次，再對答案。

✏️ 回想題

Q1. abstract class 被稱為「半成品骨架」。在電文解析的例子裡，哪些東西該寫在父類別、哪些該留成 abstract 方法？為什麼流程方法常加 final？

Q2. Java 8 有了 default method，interface 已經能寫行為。那 abstract class 還有哪三件事是 interface 做不到的？

Q3. 用一句話描述「死結」是怎麼形成的。為什麼死結的測試常常測不出來？

Q4. 死結需要哪四個條件同時成立？只要拆掉其中一個就不會發生——實務上最常拆哪一個，怎麼拆？

Q5. 順序排不出來（沒辦法固定上鎖順序）時，還有什麼招可以避開死結？

Q6. 線上程式卡死，你懷疑是死結。請說出用 jps、jstack 查它的步驟，以及怎麼從輸出對出「哪兩條執行緒互等」。

Q7. 自己 new 物件有哪三個問題？Spring 容器（IoC）是怎麼解決的？

Q8.（綜合）同一個 interface 有兩個實作 Bean，建構子注入時 Spring 不知道選哪個，你有哪兩種指定方式？另外，為什麼建構子注入比欄位注入更好測試？

—— 解答 ——

A1. 共用流程（例如：收電文 → 驗證 → 解析 → 回傳）寫在父類別；各電文格式不同的那一步（例如欄位怎麼切）留成 abstract 方法給子類別實作。流程方法加 final，是為了鎖住執行順序，子類別只能填空、不能改流程。這就是 Template Method 的做法。

A2. ① 實例欄位（狀態）　② 建構子　③ 單一繼承（表達「是一種什麼」）。interface 沒有實例欄位與建構子，而且一個類別可以實作多個 interface。要「共用資料＋流程骨架」就用 abstract class。

A3. 兩條執行緒各握一把鎖，又都在等對方手上那把，繞成一圈永遠停住。它只在時間點剛好交錯時才發生，所以測試時常剛好沒撞上，正式環境才爆。

A4. 互斥、持有並等待、不可搶奪、循環等待。最常拆「循環等待」：讓所有執行緒都用固定的上鎖順序（例如永遠先鎖 A 再鎖 B）。

A5. 用 tryLock 加逾時：等不到鎖就放手（釋放已持有的鎖），之後重試或回報失敗。這是拆掉「持有並等待」。

A6. jps 找 Java 程序的 PID → jstack <PID> 拍 thread dump → 拉到最底找「Found one Java-level deadlock」。再看每條執行緒的 waiting to lock（想要的鎖位址）與 locked（已握的鎖位址），把位址對起來，就知道 T1 握 A 等 B、T2 握 B 等 A。若沒有這行，要再排除資料庫鎖、java.util.concurrent 的鎖、或單純變慢。

A7. 問題：① 寫死實作（換實作要改程式）　② 組裝鏈越來越長（A 要 new B、B 要 new C…）　③ 沒人管份數（到底該一份還一堆）。IoC 把「建立與組裝」交給容器：啟動時掃描、建立並存放 Bean，要用時由容器給你。

A8. 指定方式：@Primary（標預設那個）或 @Qualifier("名稱")（在注入點指名）。建構子注入的依賴是從外面傳進來，測試時可以直接 new 並傳入假物件（mock / fake），不用啟動 Spring；欄位注入通常得靠反射或啟動容器才塞得進去。
