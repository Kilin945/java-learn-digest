這週你學了兩個主題：多候選 Bean 的解析（@Autowired / @Qualifier / @Primary）、以及用 @Value 讀 application.properties 設定。以下用主動回想（active recall）的方式幫你把整週串起來，先自己想一遍答案，再往下滑看解答。
🧠 回想題
1. 如果同一個 interface 有兩個以上的實作類別，都標了 @Component／@Service，然後你用 @Autowired 直接注入這個 interface 型別，Spring 會丟出什麼例外？為什麼？
2. 承上題，怎麼用 @Qualifier 解決這個問題？需要在哪兩個地方各加上什麼？
3. @Primary 的作用是什麼？如果某個注入點同時受到 @Primary 和 @Qualifier 影響，Spring 會聽誰的？
4. 要把 application.properties 裡的一個 key 注入到欄位中，@Value 的語法怎麼寫？
5. 如果 application.properties 裡缺少某個 key，而 @Value 又沒設定備用值，會發生什麼事？怎麼用語法避免這個情況？
6. 你自己寫了 new MyService() 來建立物件，結果裡面標了 @Value 的欄位是 null，這是為什麼？該怎麼修正才能拿到設定值？
7.（整合題） 假設你有一個 NotificationService 介面，兩個實作類別 EmailNotificationService 和 SmsNotificationService，你希望預設用 Email 版本，但某個地方要明確指名用簡訊版本；同時 Email 版本裡有一個 API 金鑰要從 application.properties 讀取，且要有預設值以防設定檔漏寫。請用這週學到的四個概念（@Qualifier、@Primary、@Value 讀值、@Value 預設值）描述你會怎麼寫。
—— 解答 ——
1. 會丟出 NoUniqueBeanDefinitionException。因為 Spring 在容器裡找到多個符合該 interface 型別的 Bean，卻不知道要注入哪一個候選者，所以無法自動決定。
2. 在每個候選實作類別上用 @Qualifier("名字") 貼上名字標籤，再到注入點（欄位或建構子參數）上也標 @Qualifier("名字")，指名要哪一個實作，Spring 就會依名字精準選取。
3. @Primary 是幫多個候選 Bean 指定一個「預設 Bean」，讓沒有寫 @Qualifier 的注入點也能自動選到它。若兩者同時出現，注入點上明確寫的 @Qualifier 優先權較高，會覆蓋 @Primary 的預設選擇。
4. 用 @Value("${key}") 標在欄位上，Spring 就會去 application.properties 找對應的 key=value，把 value 注入進來。
5. 若沒有預設值，Spring Boot 會因為找不到該 key 而開機失敗（啟動時噴錯）。要避免的話用冒號語法：@Value("${key:預設值}")，缺少該 key 時就會退回用預設值，不影響啟動。
6. 因為 @Value 這類注入只對 Spring 建立並管理的物件（Bean）有效。自己用 new 建立的物件不是 Spring 管理的，所以欄位不會被處理，只會維持 null。要拿到設定值，必須讓這個類別由 Spring 管理（例如標 @Service/@Component），再透過 @Autowired 取得這個由 Spring 建立、已經填好值的 Bean。
7. EmailNotificationService 和 SmsNotificationService 都標 @Service；在 EmailNotificationService 上加 @Primary 作為預設值。EmailNotificationService 內部用 @Value("${notification.apiKey:default-key}") 讀取 API 金鑰並提供預設值。需要明確用簡訊版本的地方，在注入點寫 @Qualifier("smsNotificationService")（此時會贏過 @Primary）；其他沒指名的地方就自動拿到 @Primary 的 Email 版本。而 EmailNotificationService 本身必須交給 Spring 管理（靠 @Service + @Autowired 取得），@Value 的金鑰欄位才會被正確填值。
