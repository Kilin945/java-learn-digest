📘 每週回顧 · Java / Spring Boot · 2026-08-28

這週你走完了 Spring Data JPA 與 Repository 介面 整個系列，並開始踏入 Entity 對應。在看解答之前，先自己想想看，這樣記憶才會黏得住 💪

  1. Entity 基礎： @Entity 和 @Id 這兩個 annotation 各自的作用是什麼？沒有 @Id 會發生什麼問題？
  2. 命名轉換： 如果 Entity 裡有一個欄位叫 userName，資料表裡對應的欄位名稱長怎樣？這個轉換是你要自己設定，還是 Spring 自動處理？
  3. Derived Query： 想查詢「email 包含某個關鍵字」的使用者，方法名稱該怎麼寫？完全不用寫 SQL 是怎麼辦到的？
  4. @Query： 什麼情況下方法名稱查詢（Derived Query）不夠用，得改用 @Query？回傳型別為什麼常常包成 Optional？
  5. 分頁排序： 想要「查全部使用者、依註冊時間新到舊排序、每頁 20 筆」，Repository 方法要怎麼設計？回傳的 Page<T> 除了資料本身還多帶了什麼？
  6. 綜合整理： Repository 介面裡「CRUD（繼承 JpaRepository）」「Derived Query」「@Query」「Pageable」這四樣工具，各自解決什麼問題？為什麼說它們是「你描述要什麼，Spring Data JPA 生出怎麼拿」？
  7. 主鍵產生： @GeneratedValue(strategy = GenerationType.IDENTITY) 是做什麼用的？它跟 @Id 是什麼關係？不加這個 annotation 的話，新增資料時 id 要怎麼給？
  8. 跨主題整合： 假設你要做一個對應 user_profiles 表的 Entity，主鍵自動遞增，並提供「依姓名關鍵字查詢 + 分頁 + 依註冊時間排序」的功能——這牽涉到本週哪幾個概念？大致的實作流程會是什麼樣子？

—— 解答 ——

  1. @Entity 把一個 class 標記成「對應到資料表」的物件；@Id 標記其中一個欄位作為主鍵（primary key），是每一列資料的唯一識別依據。沒有 @Id，JPA 不知道哪個欄位能唯一辨識一筆資料，整個 Entity 會設定失敗。
  2. 會自動轉成 user_name（snake_case）。這是 Spring Data JPA 的預設命名策略（naming strategy）自動處理的，camelCase → snake_case，不需要手動設定。
  3. 寫 findByEmailContaining(String keyword) 就可以。Spring Data JPA 會解析方法名稱裡的 findBy、欄位名 Email、關鍵字 Containing，自動生成對應的查詢實作，不需要你寫 SQL 或實作邏輯。
  4. 當查詢條件變複雜（多表 join、動態條件、聚合等）到方法名稱寫不出來或會變得又臭又長時，就改用 @Query 搭配 JPQL 自己寫查詢語法，並用 @Param 安全地綁定參數（避免 SQL injection）。回傳包成 Optional 是因為查詢結果可能查無資料（no data found），用 Optional 明確表達「可能是空的」，逼呼叫端處理這個情況。
  5. 在 Repository 方法多加一個 Pageable 參數即可，呼叫時用 PageRequest.of(pageNumber, pageSize, Sort.by("createdAt").descending()) 建立。回傳的 Page<T> 除了這一頁的資料，還附帶總筆數（total elements）、總頁數（total pages）等分頁資訊。
  6. CRUD（繼承 JpaRepository）處理最基本的新增/查詢/修改/刪除；Derived Query 處理「條件明確、可以用方法名稱描述」的查詢；@Query 處理「條件太複雜，方法名稱寫不出來」的查詢；Pageable 處理「資料量大，需要分頁與排序」的情境。四者合起來，你只要「描述想要什麼資料」，Spring Data JPA 就把「怎麼拿」的實作生出來，這就是它的核心設計哲學。
  7. 它讓資料庫在新增資料時自動遞增產生主鍵值（auto-increment），你不用自己指定 id。它是搭配 @Id 使用的：@Id 宣告「這是主鍵」，@GeneratedValue 進一步宣告「這個主鍵值怎麼產生」。如果不加，新增資料時就得自己手動設定一個唯一的 id 值。
  8. 會用到：@Entity + @Id + @GeneratedValue(strategy = GenerationType.IDENTITY) 定義 Entity 與主鍵產生方式；欄位命名交給 Spring 自動轉 snake_case；Repository 用 Derived Query（如 findByNameContaining）或 @Query 處理姓名關鍵字查詢；最後在方法簽名加上 Pageable 參數，呼叫時傳入 PageRequest.of(page, size, Sort.by("registeredAt"))，回傳 Page<UserProfile>。整個流程就是這週學的四塊拼在一起。
